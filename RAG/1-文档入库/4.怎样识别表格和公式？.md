**表格和公式的识别，都要分成两步：先找到它们，再恢复内部结构。普通 OCR 主要识别文字，不能仅凭“文字识别出来了”就认为表格和公式处理正确。**

## 1. 表格怎样识别？

**第一步：定位表格区域。**

有边框的表格，可以结合横线、竖线和文字位置判断；无边框表格，则需要结合文字对齐、间距、行列排列或版面模型判断。

所以，**没有网格线，不代表不是表格；出现很多数字，也不一定就是表格。**

**第二步：提取单元格内容。**

- 文字型 PDF：优先利用可靠的文字层及坐标。
- 扫描件或表格截图：对表格区域进行 OCR，保留文字的位置。
- 文字层缺失或乱码：不能继续信任直接提取的结果，需要重新识别。

**第三步：恢复行列关系，这是最重要的一步。**

需要确定每段文字属于哪一行、哪一列，以及：

- 哪些是表头，是否存在多级表头。
- 哪些单元格跨行、跨列。
- 空白单元格、零值和“无数据”标记分别是什么。
- 数值对应哪个项目、年份和单位。

例如，“产品 A 的价格是 100 元”，不仅要识别出“产品 A”和“100”，还要确定它们属于同一行，且“100”对应价格列。**文字都识别正确，但数值放错列，结果仍然是错误的。**

**第四步：保留表格及说明之间的关系。**

表格标题、单位、脚注和适用条件需要关联到表格。例如，“单位：万元”被遗漏，会让数值含义完全改变。

简单表格可以转成 Markdown；复杂表格应保留能表达合并单元格的 HTML 或结构化单元格数据，不能为了统一格式而丢掉结构。

## 2. 公式怎样识别？

**第一步：定位公式，包括行内公式和独立公式。**

公式可能由可复制字符组成，也可能是图片或矢量绘制结果。不能只查找图片，也不能只根据等号判断。

**第二步：识别符号和二维关系。**

除了字母、数字、运算符，还要恢复上下标、分子分母、根号范围、积分上下限、矩阵排列等。

例如，“a+b 整体除以 c”与“a 加上 b/c”含义不同。**普通 OCR 即使识别出相同字符，也可能丢失这些关系。**

**第三步：转写成 LaTeX，并关联原文。**

LaTeX 是识别结果的表达形式，不是公式在 PDF 中必然存在的源码。需要同时保留公式原图或区域、页码、公式编号，以及附近的变量解释和适用条件。

**第四步：检查结果。**

可以检查 LaTeX 是否能解析和渲染，再与原图核对关键符号、上下标及分式结构。**能够渲染，只能说明表达形式有效，不能证明转写内容正确。**

表格单元格中也可能包含公式，这两条处理链不能完全割裂。

## 3. 两个项目实际上怎么做？

**MimirQ：不同解析路径的能力差别很大。**

- **基础 PDF 路径**：通过提取文本中的 Markdown 表格特征判断表格，不是完整的页面表格检测，不能依靠它处理一般 PDF 表格。
- **DeepDoc 路径**：包含页面 OCR、版面识别、表格结构识别和表格构建；补充处理还会把 OCR 文字匹配到单元格。不过，其中一个补充适配器按行列交集生成单元格，并假定第一行为表头，复杂表头和合并单元格仍需要验证。
- **Docling 路径**：明确请求表格结构识别，但不能据此推断公式也完成了准确转写。Docling 的公式理解本身是独立增强步骤。[官方说明](https://docling-project.github.io/docling/usage/enrichments/)
- **公式补充路径**：根据图片说明或文件名中的公式提示筛选候选图片，调用外部公式 OCR，保留图片并追加 LaTeX。它需要开启并配置服务，**不是对所有页面中的公式自动检测**，也可能漏掉没有标识的公式图片。

**WeKnora：内置路径和专业解析引擎也要分开看。**

- **内置 PDF 路径**：没有看到专门的表格、公式结构识别环节。对于进入多模态处理的图片，主要通过提示词让视觉模型输出 Markdown 表格和 LaTeX；这不等于已经验证行列、合并单元格和数学结构正确。
- **MinerU 路径**：请求中明确包含表格和公式识别开关，构造器默认开启。MinerU 官方提供表格 HTML、公式 LaTeX 输出，但实际效果仍取决于部署版本和模型。[官方说明](https://github.com/opendatalab/MinerU)
- **后续表格整理**：简单 HTML 表格转换为 Markdown；带合并单元格的表格保留 HTML 结构。但如果上游已经丢失合并关系，这一步无法恢复。

**最终使用原则：复杂表格和公式，应选择有专门结构识别能力的解析路径，保留原始区域和结构化结果，再进行质量检查。不能只依靠全文文字提取，也不能把“提示模型输出表格或 LaTeX”当成正确性保证。**
