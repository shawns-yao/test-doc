# Agent 面经 · 清单与参考答案


## 一、基础认知类
### 1.1 Agent 和普通 Chatbot、和传统 RPA 的本质区别是什么?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>Chatbot 是被动应答、RPA 是固定规则脚本、Agent 是<b>目标驱动的自主感知-决策-行动闭环</b>。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Chatbot:</b>基于对话/检索的单轮问答,无目标拆解、无工具调用、无长期规划,本质是"你问我答"。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">RPA:</b>按预定义规则与流程执行重复操作(模拟鼠标键盘/调接口),确定性强但无法应对未预编程的变化,无理解与泛化。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Agent:</b>围绕用户目标,自行规划步骤 → 记忆上下文 → 选择并调用工具 → 观察结果反馈 → 迭代修正直到完成,能在开放、动态环境里自主决策。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:能拆目标、会调工具、看得懂结果、错了会重来 = Agent;只会答 = Chatbot;只会照脚本 = RPA。</div>
</div>
</div>

### 1.2 一个完整的 Agent 一般包含哪几个核心模块?(记忆、规划、工具调用、执行反馈这套说不清楚基本就凉半截)

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>四大件 = <b>规划 Planning + 记忆 Memory + 工具调用 Tool Use + 执行与反馈 Observation</b>,实际落地还会加"安全/权限"与"可观测"。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">① 规划:</b>把大目标拆成子任务与执行顺序(Plan-and-Execute / ReAct 逐轮思考),决定"先做什么、下一步做什么"。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">② 记忆:</b>短期记忆(当前上下文窗口)+ 长期记忆(向量库存储历史/知识/用户画像),让 Agent 跨轮保持一致性。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">③ 工具调用:</b>通过 Function Calling / MCP 使用检索、数据库、API、代码执行等外部能力,解决模型自身知识与能力边界。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">④ 执行与反馈:</b>拿到工具结果后反思(是否满足当前子目标),决定继续、修正或终止,形成闭环。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:规划决定"想清楚",工具决定"够得着",记忆决定"记得住",反馈决定"不跑偏"。</div>
</div>
</div>

### 1.3 ReAct 是什么,跟单纯的 Function Calling 有啥区别?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>ReAct 是<b>"思考→行动→观察"的多轮推理范式</b>,把 Thought 显式说出来再决定行动;Function Calling 是<b>模型一次输出"调哪个工具+参数"的接口能力</b>,本身不含多轮推理循环。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">ReAct:</b>每一轮先输出 Thought(推理),再选 Action(调工具),拿到 Observation(结果)进入下一轮,可回溯纠错,适合多步推理、易出错需修正的复杂任务。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Function Calling:</b>模型在生成时按注入的工具 Schema 输出结构化调用(名称+参数),一次决策直接执行,不强制暴露中间推理,省 token、延迟低,适合单步目标明确场景。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:两者常搭配使用——用 Function Calling 做工具解析与执行,用 ReAct 思路做多步规划,不是二选一(展开见下方"题目 1")。</div>
</div>
</div>

### 1.4 Agent 的"记忆"分哪几种?短期记忆和长期记忆分别怎么落地?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>按时间分<b>短期(工作)记忆与长期记忆</b>;按内容分<b>情景记忆、语义记忆、程序记忆</b>。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">短期记忆落地:</b>即当前上下文窗口。靠 token 预算管理:超限做摘要压缩(Summarization)、滑动窗口只留最近轮次、必要时剔除无关检索片段。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">长期记忆落地:</b>向量数据库(Embedding 存储历史对话/知识库片段,按相关性检索召回)+ 结构化记忆(用户画像/事实存 KV 或图谱)+ 记忆写入策略(重要信息抽取后入库,避免全量存)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">追问点:</b>何时写入记忆?如何更新与遗忘?检索结果与当前上下文怎么融合排序?多用户记忆如何隔离?</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:短期=上下文窗口(靠摘要/裁剪),长期=向量库+结构化(靠写入/检索策略),再补一句"记忆与检索是两件事,写不进去就检不出来"。</div>
</div>
</div>

## 二、框架与工程实现类

### 2.1 LangChain / LangGraph / AutoGen / CrewAI 用过哪个?为什么选它,踩过什么坑?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>选型看<b>可控性 vs 上手速度</b>:LangGraph 适合生产级有状态编排,其余更适合快速原型与特定场景,没有银弹。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">LangGraph:</b>把 Agent 建成<b>状态图</b>(节点=工具/模型,边=转移条件),支持循环、分支、checkpoint 持久化与人工介入,可控性和工程化最好,生产首选。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">LangChain:</b>生态最全(集成多),上手快,但抽象层多、隐式逻辑重,版本升级破坏性大,调试困难,适合快速验证。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">AutoGen:</b>微软出品,强在多 Agent 对话式协作与代码执行,适合研究与多体研究,生产治理弱一些。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">CrewAI:</b>角色化 Crew 分工,声明式简单,适合轻量多角色任务,复杂状态机/可控性不如 LangGraph。</div>
<div style="margin:6px 0 0;"><b style="color:#B26E00;">踩坑点(结合自己的项目讲):</b>版本升级不兼容、隐式 Chain 内部逻辑难追踪、长任务 token 超限、工具调用失败缺少兜底、checkpoint 恢复不完整导致重复执行。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:要可控上 LangGraph、要快速上 LangChain、要对话式多体用 AutoGen、要轻量分工用 CrewAI;回答一定带上自己踩过的具体坑。</div>
</div>
</div>

### 2.2 MCP 协议是干嘛的,最近为什么突然这么火,解决了什么之前的痛点?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>MCP(Model Context Protocol)是<b>AI 应用连接外部工具/数据的统一开放协议</b>,相当于"AI 界的 USB-C",由 Anthropic 提出并快速成为事实标准。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">解决的历史痛点:</b>此前每个 Agent 对接工具都要自研适配器,工具格式、鉴权、发现机制各自为政,接入成本高、生态碎片化,换个框架全部重接。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">它定义了什么:</b>统一了 <b>Server(提供工具/资源/提示词)— Client(Host 应用)</b> 的通信规范,工具以标准化 Schema 暴露、动态发现与调用,支持本地与远程。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">为什么火了:</b>Anthropic 开源推行,OpenAI/Google 等跟进兼容,"一次接入、处处复用",工具生态、鉴权安全、可观测得以标准化。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:USB-C 类比 + 三个关键词(统一协议、解耦工具与框架、生态互通);再补一句它和 Function Calling 不冲突,FC 是模型能力、MCP 是接入标准。</div>
</div>
</div>

### 2.3 Function Calling 底层模型是怎么"决定"该调哪个工具、传什么参数的?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>本质仍是<b>语言模型的自回归预测</b>:工具以 JSON Schema 注入上下文,模型推理"当前是否需要外部信息/动作",需要则生成工具名与符合 Schema 的参数。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">决定依据:</b>模型综合<b>用户意图 + 对话历史 + 各工具的描述与参数说明</b>做语义匹配;工具 description 写得越清楚,选对率越高(典型失败是工具描述含糊导致选错)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">参数生成:</b>模型按 Schema 的 required 字段、类型与枚举约束输出结构化 JSON;部分模型还会输出 reasoning 再给调用,提升参数准确性。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">工程侧兜底:</b>不能完全信任模型输出——调用前做 Schema 强校验、参数白名单/枚举校验、低温度、必要时加 few-shot 示例,校验失败让模型重生成而不是直接执行。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:"选工具靠语义匹配,传参数靠 Schema 约束,可靠性靠工程校验"——模型负责决策,代码负责兜底。</div>
</div>
</div>

### 2.4 工具调用失败了怎么办?重试机制、超时机制怎么设计?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>核心原则是<b>区分可重试与不可重试错误,失败信息回灌给 Agent 决策,而不是无脑重试</b>。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">可重试(指数退避):</b>网络超时、429 限流、5xx 服务端错误 → 指数退避 + 抖动(Exponential Backoff + Jitter),设置最大重试次数(如 3 次)与总超时上限。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">不可重试(立即失败):</b>参数校验失败、鉴权失败、404 不存在 → 重试无意义,直接把错误转成结构化反馈让 Agent 修正参数/换工具。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">幂等设计:</b>写操作必须带请求 ID/幂等键,保证重试不产生重复副作用(避免重复下单/重复写库)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">超时机制:</b>分连接超时、读取超时、总执行超时三层;超时后中断并返回可重试错误。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:退避重试防抖 + 幂等防重复 + 错误分类防空转 + 反馈模型让它自己改;能说出"429 要退避、参数错要改参不是重试"就及格。</div>
</div>
</div>

## 三、RAG / 知识增强类

### 3.1 Agent 里用的 RAG 和普通问答 RAG 有什么不一样(比如要不要多轮检索、什么时机触发检索)?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>普通 RAG 是<b>单次被动检索后直接生成</b>;Agent 内 RAG 是<b>由 Agent 按需触发、可多轮、结果参与决策与反思</b>的检索。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">触发时机:</b>普通 RAG 固定"每问必检"或"不问不检";Agent 由模型自己判断"执行当前子任务是否需要外部知识",需要才检索,减少无效检索与噪声。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">多轮与改写:</b>Agent 任务跨多步,检索常伴随 <b>Query 改写/分解</b>(把复杂问题拆成多个子检索),甚至边推理边补检(ReAct 循环中的检索),而不是一次检索定终身。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">结果用途:</b>普通 RAG 检索结果只喂给最终生成;Agent 的检索结果还会<b>影响后续规划决策</b>(如证据不足触发再检索或换策略)。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:普通 RAG = 查一次答一次;Agent RAG = 需要才查、边想边查、查完还能改主意。</div>
</div>
</div>

### 3.2 检索结果不准导致 Agent 决策跑偏,你怎么解决?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>先定位是<b>召回不全会导致没检索到,还是排序噪声导致检索到错的</b>,再分层治理,最后用评测闭环验证。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">召回侧(查不到):</b>混合检索(BM25 关键词 + 向量语义 + 重排)、Query 改写与扩展、HyDE(先让模型生成假设答案再检索)、多路召回、索引切分策略调整。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">排序侧(查不准):</b>引入 Reranker(cross-encoder)精排,把最相关片段顶到前面;设置相似度阈值与 top-k 控制,过滤低分噪声。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Agent 侧兜底:</b>把检索结果做成"证据"给模型并提示<b>"证据不足就明说/继续检索/换问法",不要硬答</b>;关键决策前加一步证据充分性校验。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">评测闭环:</b>建评测集(标准问法 + 期望证据),指标看检索命中率与端到端正确率,badcase 回流迭代切分/embedding/重排。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:四板斧 = 混合检索保召回、Reranker 保精度、提示词"没证据不许答"、评测集驱动迭代。</div>
</div>
</div>

### 3.3 Chunk 怎么切效果比较好?有没有真的因为切分策略翻过车?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>优先<b>按语义边界切(标题/段落/句子),而不是按固定字符数硬切</b>;好切分的标准是"单个 chunk 语义完整、且足以支撑一次回答"。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">常规做法:</b>Markdown 结构切分(按标题层级保留上下文)→ 段落/语义块 → 超长再按句界切,配合 overlap(10%~20%)避免上下文断裂。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">进阶策略:</b>Parent-Child 双粒度——检索用小子块提高命中,送模型用父块补足上下文;按表格/代码等结构做专用解析器;按文档类型自适应切分策略。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">切分翻车真实案例(可讲):</b>曾经按固定 512 字符硬切,把一条完整 FAQ/一个表格从中间切断,检索命中的是残缺片段导致回答截断;后来改成"按问题条目切分 + overlap",命中率明显提升。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:别数着字数切,要顺着语义切;检索粒度可以小,喂给模型的粒度要大(parent-child 一句话讲清)。</div>

## 四、多智能体协作类

### 4.1 什么场景下必须上 Multi-Agent,单 Agent 搞不定?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>当任务需要<b>多种专业角色、不同上下文边界或角色间校验/协作</b>,单 Agent 因为"一个上下文塞不下/一个角色做不完/缺少制衡"才需要多体。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">典型场景:</b>① 需要多个专业视角(产品/研发/测试讨论一个方案);② 上下文隔离(各 Agent 只管自己领域,避免互相污染);③ 对抗与校验(一个生成一个审查);④ 并行任务(多个独立子任务同时推进)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">反例(要会说不):</b>大多数单目标任务单 Agent + 工具就够了;Multi-Agent 会带来通信开销、状态不一致、错误传播、成本上升——"能用单体解决就不上多体"。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:上多体的理由 = 角色分工 / 上下文隔离 / 互相校验 / 并行,不是"听起来高级"。</div>
</div>
</div>

### 4.2 Agent 之间怎么通信、怎么分工?听说过 Orchestrator 模式吗?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>通信方式 = <b>共享状态(黑板) / 消息传递(队列、事件) / 直接函数调用</b>;编排模式中最主流的是 <b>Orchestrator-Worker(主管-工人)</b>。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">通信:</b>① 共享黑板/数据库(各 Agent 读写同一任务状态,简单但需锁与一致);② 消息总线(事件驱动、解耦、可回溯,生产常用);③ 直接调用(同进程函数或 HTTP,简单直接但耦合)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">分工模式:</b>集中编排(主管拆任务派发给工人并汇总) vs 对等协作(Agent 自由对话/辩论,灵活但难收敛)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Orchestrator 模式:</b>一个中央 Agent 负责<b>任务分解、路由分配、结果汇总与冲突仲裁</b>,Worker 只专注执行被分配的切片任务——可控、可观测、易加人工介入,是工程上最稳的多体模式。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:先答通信三选一,再答"主管-工人"集中编排最可控,对比级联/对等模式容易失控。</div>
</div>
</div>

### 4.3 多个 Agent 互相"甩锅"进入死循环,怎么兜底?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>兜底三板斧 = <b>轮次/步数硬上限 + 仲裁者(或升级人工)+ 状态机约束消息流向</b>。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">硬性上限:</b>全局最大通信轮数、单个 Worker 最大尝试次数,超限强制终止并转人工或回退默认方案。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">引入仲裁者:</b>Orchestrator 或专门的 Judge Agent 在 Agent 间分歧时做裁决;裁决不了升级人工,不让争论无限持续。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">状态机约束:</b>定义"谁在什么状态能向谁发什么消息",限制互相推诿的发言空间,必要时只允许把问题抛回给主管而非互踢皮球。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">可观测:</b>所有消息带 trace_id 全链路记录,循环/重复模式可检测(如相邻消息相似度),方便定位是哪个 Agent 在甩锅。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:上限防死循环、仲裁防甩锅、状态机防互踢、日志防黑盒。</div>
</div>
</div>

## 五、工程落地 / 稳定性类

### 5.1 Agent 的成本怎么控制(Token 消耗、调用次数、模型选型分级)?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>成本 = <b>Token 单价 × 用量 × 调用次数</b>,分别从模型分级、上下文瘦身、调用收敛三路控制。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">模型分级:</b>任务分级路由——简单分类/抽取用小模型或快模型,复杂推理才用大模型;内部工具调用与面向用户回复可分层用不同模型。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Token 瘦身:</b>控制上下文长度(摘要压缩、只保留必要检索结果、裁剪历史)、精简 System Prompt、结构化输出用低 token 格式、Prompt Caching 复用前缀。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">调用次数收敛:</b>限制最大步数/工具调用次数、合并可并行调用、失败重试设上限、命中缓存(语义缓存)直接复用历史结果。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">成本观测:</b>按 Agent/任务/用户维度打点 token 与成本,建立告警,用数据驱动优化(先量化再砍)。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:分级(贵的少用)、瘦身(上下文别塞满)、收敛(别瞎调工具)、打点(先量化再优化)。</div>
</div>
</div>

### 5.2 怎么评估一个 Agent 做得好不好,有哪些具体指标?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>不要只看"效果好不好",要分层看 <b>任务成功率、过程合理性、输出质量、成本效率</b>,并配离线评测集与线上回评。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">任务层:</b>任务完成率/成功率、端到端目标达成率(有没有把活干完、干对)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">过程层:</b>路径合理性(步数是否绕远、工具调用次数)、重复调用率、无效调用率、死循环率(有没有瞎折腾)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">质量层:</b>工具调用准确率、幻觉/瞎调用比例、回答正确率(人工评估 + LLM-as-Judge 自动打分结合)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">效率层:</b>单任务 Token 成本、响应延迟(P50/P95)、资源占用。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">评测体系:</b>离线评测集(golden set)回归 + 线上灰度对比 + 用户反馈回流,形成持续优化闭环。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:结果对不对(任务层)+ 过程蠢不蠢(路径层)+ 质量稳不稳(幻觉/准确率)+ 贵不贵(成本效率);能说出"离线评测集 + 线上灰度"闭环是加分项(展开见"题目 2")。</div>
</div>
</div>

### 5.3 Agent 出现幻觉、瞎调工具,线上怎么兜底?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>幻觉靠<b>"证据约束 + 不确定性表达"</b>,瞎调工具靠<b>"权限白名单 + 调用前校验 + 高危操作人工确认"</b>,线上靠<b>监控告警与熔断降级</b>。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">治幻觉:</b>要求回答必须引用检索来源或工具结果;提示"没有证据就承认不知道,不要编造";关键数值/事实与来源做一致性校验;RAG 检索不到时不硬答。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">治瞎调工具:</b>工具白名单 + 参数 Schema 强校验 + 危险操作(删除/下单/发消息)二次人工确认;按用户权限过滤可用工具。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">线上兜底:</b>全量审计日志(调了什么工具、什么参数、谁触发的可回查);异常率监控(工具调用失败率/拒绝率突增告警);高风险场景先灰度、可一键熔断降级到人工或只读模式。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:管住嘴(证据+拒答)、管住手(白名单+校验+审批)、看得见(审计+监控+熔断)。</div>
</div>
</div>

### 5.4 生产环境怎么做 Agent 的可观测性(日志、Trace、埋点)?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>Agent 可观测的核心是<b>一条完整推理链可回放</b>:从用户请求到每一步 Thought、工具调用、结果的全程 Trace + 结构化日志 + 指标埋点。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Trace 链路:</b>一次会话一个 trace_id,串联每个 Agent 步骤的输入/输出/工具调用/耗时;每步关键事件打 span(模型调用、工具调用、检索、人工介入点)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">结构化日志:</b>记录模型名称、温度、token 用量、工具名与参数、返回状态、错误类型,便于事后检索与统计(可接入 OpenTelemetry/LangSmith 类平台)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">指标埋点:</b>成功率、平均步数、工具调用分布、token 成本、延迟、幻觉投诉率、重试率,做趋势告警。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">回放与评测:</b>线上可一键回放某条会话的完整推理过程用于定位问题;抽样把线上 badcase 回流到离线评测集,驱动持续优化。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:三个词——Trace 串全链、日志留证据、指标出告警;再加一句"能回放才能复盘,能回流才能进化"。</div>
</div>

## 六、系统设计类(压轴大题,基本必考)

### 6.1 设计一个智能客服/代码助手/数据分析 Agent,讲讲你的整体架构

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>按<b>接入层 → Agent 编排层 → 能力层 → 模型层 → 数据与可观测底座</b>分层设计,并明确每一层的职责与关键决策。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">接入层:</b>多渠道/协议接入,做会话管理与用户身份(客服:IM/工单;代码助手:IDE 插件)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">Agent 编排层:</b>意图识别与任务规划,按场景选模式(客服=意图路由 + 多轮澄清;代码助手=代码理解 + 修改计划;数据分析=SQL/图表工具编排),并接人工升级通道。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">能力层(工具/RAG):</b>通过 Function Calling/MCP 暴露工具集(客服:订单/物流/知识库检索;代码:文件/执行/测试;数据:库表查询/代码执行沙箱)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">模型层:</b>模型分级路由、Prompt 管理、结构化输出约束、缓存。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">底座:</b>向量库(知识检索)、任务状态存储、鉴权与安全(沙箱/权限/审计)、Trace 日志与评测监控、灰度与降级。</div>
<div style="margin:6px 0 0;"><b style="color:#B26E00;">加分讲法:</b>用具体例子串一遍(用户问"我的订单为什么没发货"→ 意图识别 → 查订单工具 → 检索物流知识 → 生成回答 → 解决不了转人工),并主动讲两个关键取舍:什么时候 RAG 什么时候直连业务 API、安全边界怎么做。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:分层讲结构 + 场景串流程 + 主动谈取舍;系统设计题不怕简单,怕没有分层和闭环。</div>
</div>
</div>

### 6.2 如果任务要跑几十步才能完成,怎么保证 Agent 不跑偏、不断链?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答:</b></div>
<div style="margin:6px 0 0;"><b style="color:#3F8C12;">一句话结论:</b>用<b>目标锚定 + 步数上限 + 检查点 + 状态持久化</b>四条腿走路,让长任务"想得清、走不偏、断得了链也接得上"。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">① 目标锚定:</b>把总目标拆成结构化任务清单(Plan),每步开始前让模型对照目标判断"这一步是否服务于主线",偏离就拉回。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">② 硬上限:</b>最大步数/最大工具调用次数,超限熔断转人工,从根上杜绝无限循环。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">③ 检查点与自检:</b>每 N 步生成阶段性小结,校验中间结果(输出格式/数值合理性/与目标一致性);关键决策点人工确认或规则校验(风险操作审批)。</div>
<div style="margin:6px 0 0;"><b style="color:#3A5FBF;">④ 状态持久化与断点续跑:</b>任务状态、已执行步骤、中间产物写入存储(对应 LangGraph checkpoint 思想),进程崩溃/超时后能从最近检查点恢复,而不是从头重跑;失败步骤有重试与降级策略。</div>
<div style="margin:6px 0 0;"><b style="color:#B26E00;">加分讲法:</b>补一个"上下文瘦身"——长任务中定期对历史做摘要压缩,防止上下文塞满后模型丢失早期约束;再举个自己处理过的长任务例子(展开见"题目 3")。</div>
<div style="margin:6px 0 0;color:var(--muted);font-size:13px;">记忆要点:清单防跑偏、上限防死循环、检查点防断链、持久化防白干。</div>
</div>
</div>

## 七、挑 3 道我印象最深的,展开讲讲回答思路

### 题目 1:ReAct 和纯 Function Calling 到底有什么区别?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答思路:</b></div>
<div style="margin:6px 0 0;">先说结论——ReAct 是一种"思考-行动-观察"循环的范式,强调模型每一步都要显式输出推理过程(Thought),再决定要不要调用工具(Action),拿到结果后再反思(Observation)继续下一轮;</div>
<div style="margin:6px 0 0;">而纯 Function Calling 更多是模型直接判断"该不该调、调哪个",不强制暴露中间推理链路。</div>
<div style="margin:6px 0 0;">可以补一句:ReAct 更适合需要多步推理、容易出错要回头修正的复杂任务,Function Calling 更适合单步、目标明确的调用场景,两者其实经常是搭配着用的,不是二选一。</div>
</div>
</div>

### 题目 2:怎么评估一个 Agent 系统做得好不好?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答思路:</b></div>
<div style="margin:6px 0 0;">不要只说"看效果好不好"这种空话,可以从几个维度拆开讲:任务完成率(有没有把活干完)、路径合理性(有没有绕远路、重复调用)、工具调用准确率、幻觉/瞎调用的比例、响应延迟和成本、以及人工评估+自动化评测(比如用另一个模型当裁判打分)结合的方式。</div>
<div style="margin:6px 0 0;">能提一句"离线评测集+线上灰度反馈"闭环会明显加分。</div>
</div>
</div>

### 题目 3:任务链很长(几十步)的 Agent,怎么防止它跑偏或者死循环?

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);background:transparent;color:var(--text);font-family:'Roboto','PingFang SC','Segoe UI',Arial,sans-serif;font-size:14px;line-height:1.7;box-sizing:border-box;max-width:780px;margin:12px 0;">
<div style="background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
<div><b>回答思路:</b></div>
<div style="margin:6px 0 0;">可以从几个手段讲:一是设置最大步数/最大工具调用次数硬性上限;</div>
<div style="margin:6px 0 0;">二是引入阶段性检查点,定期让模型回顾目标、判断是否偏离;</div>
<div style="margin:6px 0 0;">三是关键决策点加人工确认或者规则兜底;</div>
<div style="margin:6px 0 0;">四是记忆管理上做摘要压缩,避免上下文塞太满导致模型"忘了自己在干嘛"。</div>
<div style="margin:6px 0 0;">举个自己实际处理过的小例子会比干讲理论更有说服力。</div>
</div>
</div>
