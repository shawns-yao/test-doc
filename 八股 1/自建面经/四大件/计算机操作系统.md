# 1.1 用户态和内核态有什么区别？用户态切入内核态有哪些方式？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>用户态运行普通应用代码，权限受 CPU 特权级限制，不能直接访问内核地址、设备寄存器或执行特权指令；内核态运行操作系统内核，可以管理进程、内存、文件和设备。这样能够隔离应用故障和恶意访问，应用需要通过受控接口请求操作系统服务。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（切入方式）：</b>① <b>系统调用</b>：应用主动触发，如 <code>read</code>、<code>write</code>、<code>mmap</code>；② <b>硬件中断</b>：由网卡、磁盘和定时器等设备触发；③ <b>异常/陷阱</b>：缺页、除零和非法指令等由当前指令执行引发。CPU 保存必要上下文、切换到内核栈并跳转到内核处理函数，处理完成后返回用户态。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>用户态到内核态的切换不一定伴随进程切换，但会产生寄存器保存、权限检查、内核栈切换和缓存影响等开销；x86 通过特权级（Ring 0/Ring 3）实现权限隔离。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>隔离换来了安全和稳定，代价是每次陷入都有切换开销。优化 I/O 时可以使用批量系统调用、异步 I/O、零拷贝以及减少无意义的用户态/内核态往返。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>Netty/Java NIO 通过 <code>epoll</code> 系统调用驱动事件循环；高并发服务控制单请求系统调用次数（批量读写、缓冲）；大文件传输用 <code>sendfile</code> 零拷贝减少用户态/内核态拷贝；日志和网络写入合并批量提交。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>系统调用和普通函数调用有什么区别（特权级切换 + 上下文保存）；用户态能直接操作硬件吗（不能，必须经过内核）；陷入内核后栈在哪（切换到内核栈）；中断和系统调用的区别（被动 vs 主动）。</div>
  </div>
</div>

# 1.2 进程和线程有什么区别？进程间通信方式有哪些？线程间同步方式有哪些？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>进程是资源分配和隔离的基本单位，拥有独立的虚拟地址空间、文件描述符表和资源限制；线程是调度和执行的基本单位，同一进程内线程共享代码段、堆、全局变量和打开的文件，但各自拥有栈、寄存器和线程局部存储。进程隔离性强但创建、切换和通信成本较高；线程共享数据方便，但需要处理数据竞争和同步。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（IPC 方式）：</b>匿名管道、命名管道、消息队列、共享内存、信号量、信号、Unix Domain Socket 和网络 Socket。共享内存速度快，但必须配合锁、信号量或原子变量；管道和消息队列提供缓冲与阻塞语义；Socket 可以支持跨主机通信。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（线程同步）：</b>互斥锁、读写锁、自旋锁、条件变量、信号量、屏障和原子操作。选择时要看临界区长度、读写比例、是否需要超时或中断。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>共享内存最快但并发控制全靠自己；管道是单向字节流、消息队列有长度限制；自旋锁适合短临界区（忙等不切换）；条件变量必须配互斥锁使用；<code>volatile</code> 只保证可见性不保证原子性。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>多进程崩溃隔离好但通信成本高；多线程共享地址空间，一个线程的野指针可能拖垮整个进程；锁使用不当会死锁、活锁或性能退化——需要保证加锁顺序一致、异常路径释放资源。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>服务内部用线程池 + 线程安全集合处理并发；跨服务用 RPC/消息队列（网络 IPC）；本地多进程协作（日志采集、Agent）用 Unix Domain Socket 或共享内存；锁只保护真正共享的可变状态，减少全局锁粒度。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>线程切换为什么比进程切换轻（共享地址空间，无需切换页表）；共享内存为什么还要同步（多写者竞争）；协程和线程的区别（用户态调度、无内核切换）；I/O 密集任务选什么（线程/协程，等待期不占 CPU）。</div>
  </div>
</div>

# 1.3 僵尸进程和孤儿进程有什么区别？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>子进程退出后，内核仍保留退出码、资源统计和进程标识，等待父进程调用 <code>wait</code> 或 <code>waitpid</code> 回收，这段状态称为<b>僵尸进程</b>；<b>孤儿进程</b>是父进程先退出、子进程仍在运行，内核会把它重新托管给 init 或 subreaper，由新的父进程负责最终回收。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>僵尸进程不再执行代码，也不占用原来的用户态内存，但会占用进程表项；父进程长期不回收大量子进程可能耗尽 PID 或进程表资源。孤儿本身不一定是问题，只要有新父进程接管回收。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>不能通过简单杀死僵尸进程解决问题，因为它已经退出；应修复或终止其父进程，让 init/subreaper 接管并回收。排查僵尸要确认父进程是否正确处理 <code>SIGCHLD</code> 并循环调用 <code>waitpid</code>。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>进程管理器（supervisor 类）必须注册 <code>SIGCHLD</code> 处理并循环 <code>waitpid(-1, ...)</code> 回收所有子进程；Java 中避免频繁 fork 外部进程，用线程池复用；容器内 PID 1 要承担 init 职责（tini 等）防止僵尸堆积。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>僵尸进程占用什么资源（进程表项/PID）；如何批量回收（循环 waitpid 或 SIGCHLD 处理器）；孤儿进程会变僵尸吗（由新父进程负责回收，若新父进程不回收仍可能僵住）。</div>
  </div>
</div>

# 1.4 一个进程中的一个线程挂掉，会影响同进程下的其他线程吗？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>线程共享进程地址空间、堆、全局变量和大部分进程资源，因此一个线程发生未处理的致命错误时，可能使整个进程终止。例如 Linux 下线程发生段错误、非法指令或某些致命信号时，默认动作通常是终止整个进程，其他线程也会被清理。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>如果只是线程函数正常返回、显式退出，或者语言运行时捕获了线程级异常，其他线程可以继续运行。但即使进程没有立刻退出，一个线程破坏共享堆、持有锁后异常退出或写入错误数据，也可能让其他线程后续崩溃或永久阻塞——危害不限于"直接退出"一种形式。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>线程共享内存是性能优势也是崩溃放大器。工程上可以把不可信任务隔离到独立进程（如浏览器每个标签页一个进程）；锁、文件、事务要在异常路径释放或回滚，否则一次异常可能让整个进程资源泄漏。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>每个线程入口设置异常捕获和清理逻辑（finally 释放锁/连接）；业务隔离：不可信第三方任务用独立进程或容器承载；故障定位用 core dump、线程栈和日志；线程池任务失败不影响池本身，但要监控任务失败率和卡死线程。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>为什么线程崩溃会影响整个进程（共享地址空间、致命信号默认终止进程）；如何隔离崩溃影响（独立进程/容器）；线程卡死怎么发现（堆栈 dump、超时监控）。</div>
  </div>
</div>

# 1.5 什么是死锁？解决死锁有哪些办法？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>死锁是多个线程/进程互相等待对方持有的资源，导致全部无法推进。四个必要条件：① <b>互斥</b>（资源一次只能被一个线程占用）；② <b>持有并等待</b>（持有资源的同时等待其他资源）；③ <b>不可剥夺</b>（资源只能主动释放）；④ <b>循环等待</b>（形成等待环）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">解决办法（预防）：</b>破坏四个条件之一——破坏互斥较难（资源天然互斥）；破坏持有并等待（一次性申请全部资源）；破坏不可剥夺（超时强制释放）；最常用的是破坏循环等待：<b>全局锁顺序</b>，所有线程按固定顺序加锁。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">解决办法（检测与恢复）：</b>锁获取加超时（<code>tryLock(timeout)</code>），超时后回滚重试；死锁检测（资源分配图找环）后强制剥夺或终止部分进程；Java 的 <code>jstack</code> 可检测 <code>synchronized</code> 死锁。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>数据库死锁通常由事务加锁顺序不一致引起，InnoDB 会检测并回滚代价较小的事务；分布式场景的锁超时、重试和幂等本质上也是防死锁；活锁（不断重试但无进展）不是死锁但同样危险。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>死锁发生时相关线程永久阻塞，资源无法释放；预防措施（如全局锁顺序）会降低并发度；超时方案可能误伤长任务，超时值需要按业务合理设置。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>多资源操作前定义锁获取顺序（如先用户后订单）；用 <code>ReentrantLock.tryLock</code> 代替无限阻塞；数据库事务保持短小、加锁顺序一致、合理索引减少锁范围；监控锁等待时长和死锁告警。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>死锁四个必要条件是什么；如何破坏循环等待（锁排序）；<code>tryLock</code> 能完全避免死锁吗（能避免无限等待但不保证业务成功，需重试）；死锁和活锁、饥饿的区别。</div>
  </div>
</div>

# 1.6 多进程和多线程有什么区别？I/O 密集型任务更适合使用进程、线程还是协程？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>多进程：独立地址空间、强隔离、创建/切换/通信成本高，适合 CPU 密集并行和需要故障隔离的场景；多线程：共享地址空间、切换轻、通信方便，但需要同步且崩溃互相影响。协程：用户态调度、单线程内并发，切换不经过内核，成本最低。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">I/O 密集型选型：</b>I/O 密集任务的特点是大部分时间在等待（网络、磁盘），CPU 占用低。选<b>协程/异步 I/O</b>最优——等待期不占线程，单线程可承载数万并发（Go goroutine、Java 虚拟线程、Python asyncio、Node.js）；其次是<b>多线程</b>（线程池 + 阻塞 I/O，线程数 ≈ I/O 等待占比 × CPU 核数）；纯多进程浪费内存且切换开销大，一般不作为首选。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>线程数不是越多越好——线程切换和栈内存（默认 1MB 级）有成本；I/O 密集场景线程池大小 ≈ CPU 核数 ×（1 + 等待时间/计算时间）；协程适合大量轻量任务，但单个协程内不能有阻塞调用（否则卡住整个调度器）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>多进程内存占用高、IPC 复杂；多线程受线程数上限约束、共享状态需同步；协程需要异步框架配合（阻塞调用会破坏并发），且复杂 CPU 任务不会因协程加速。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>Web 服务：Netty/虚拟线程（I/O 密集）；计算任务：线程池/进程池并行分片；数据同步任务：生产者消费者 + 异步批量；Java 21+ 虚拟线程可直接用同步代码风格获得协程级并发密度。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>为什么 I/O 密集用协程（等待期不占线程资源）；协程和线程的切换成本差在哪（用户态 vs 内核态）；线程池大小怎么算（I/O 密集公式）；协程里能放阻塞调用吗（不能，会阻塞整个调度循环）。</div>
  </div>
</div>

# 1.7 操作系统中的进程如何交互？管道等进程间通信方式有什么特点？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>进程地址空间互相隔离，交互必须通过内核提供的 IPC 机制：管道、消息队列、共享内存、信号量、信号、Socket。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（各方式特点）：</b>① <b>匿名管道</b>：父子进程间单向字节流，随进程消亡，容量有限（默认 64KB），写满阻塞；② <b>命名管道（FIFO）</b>：通过文件系统路径，无亲缘关系进程也可用；③ <b>消息队列</b>：内核维护的消息链表，有类型和长度限制，可随机读取；④ <b>共享内存</b>：映射同一物理内存，零拷贝最快，但需自行同步；⑤ <b>信号量</b>：计数器，用于互斥和同步，不传数据；⑥ <b>信号</b>：异步通知事件；⑦ <b>Socket</b>：跨主机/本地通用，Unix Domain Socket 比 TCP 少协议栈开销。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>管道是字节流无消息边界，需要应用层定协议（长度前缀/分隔符）；共享内存不经过内核拷贝，但同步开销要自己承担；消息队列和信号量都有内核资源上限（<code>ipcs -l</code> 可查）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>管道/消息队列有内核拷贝开销但天然同步；共享内存最快但生命周期和并发全靠应用管理，崩溃后可能留下脏数据；信号不适合传数据只适合通知。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>Shell 管道串联命令（<code>ps | grep</code>）；日志采集进程用 Unix Domain Socket 传输；跨服务通信走 TCP/HTTP 或消息队列（本质网络 IPC）；高频小数据传递考虑共享内存 + 原子标志。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>管道为什么是半双工（单向内核缓冲）；共享内存为什么最快（无内核拷贝）但要同步；消息队列和管道的区别（有界/类型/随机读）；Unix Domain Socket 比 TCP 快在哪（无协议栈和路由开销）。</div>

# 1.8 信号量机制是什么？适合解决什么问题？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>信号量是带计数器的同步原语，两个原子操作：<code>P（wait）</code>——计数器减一，小于 0 则阻塞；<code>V（signal）</code>——计数器加一，唤醒等待者。二值信号量（0/1）等价互斥锁；计数信号量控制"最多 N 个线程同时访问"。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程：</b>① 初始化信号量并设置初始计数 N；② 访问共享资源前执行 <code>P</code>，计数不足则挂起；③ 释放资源后执行 <code>V</code> 唤醒一个等待线程；④ 内核保证 P/V 原子性（关中断或原子指令）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>信号量适合控制"资源数量"而非单纯互斥——连接池限流（N=池大小）、生产者消费者（空/满两个信号量）、读者写者（读写信号量）；互斥锁是信号量计数为 1 的特例，但互斥锁有"持有者"概念，信号量没有。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>信号量不记得持有者，容易误释放（任意线程可 V）；P/V 顺序错误会导致死锁或计数漂移；跨进程信号量（<code>semget</code>）有内核资源和权限管理成本；Java 中 <code>Semaphore</code> 可响应中断和超时更安全。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>连接池/线程池限流（信号量控制并发获取）；限流器（Semaphore 令牌）；生产者-消费者队列；数据库连接池的实现本质就是信号量 + 队列；分布式场景可对应 Redis 计数或令牌桶。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>信号量和互斥锁的区别（计数 vs 持有者）；信号量能实现互斥吗（二值信号量可以但不推荐）；信号量如何实现限流（初始计数 = 最大并发）；P/V 为什么要原子（防止竞态条件）。</div>
  </div>
</div>

# 2.2 `malloc` 返回的是虚拟地址吗？物理地址什么时候会被使用？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b><code>malloc</code> 返回的是<b>虚拟地址</b>，不是物理地址。程序永远只操作虚拟地址；物理内存由内核通过页表映射按需分配。这是"虚拟内存"设计的核心：进程地址空间只是映射关系，不是真实占用。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程：</b>① <code>malloc</code> 在堆区分配虚拟地址范围（大块走 <code>mmap</code>，小块从内存池 <code>brk</code> 扩展）；② 首次访问该地址时触发<b>缺页异常</b>；③ 内核分配物理页、建立页表映射（写时分配）；④ 后续访问直接命中页表。因此 <code>malloc</code> 后不写不读就不会真正占用物理内存。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>物理地址只在 CPU 访问内存时由 MMU 通过页表转换产生，用户程序全程不可见；<code>top</code> 的 VIRT（虚拟）vs RES（常驻物理）差别就在这里；<code>memset</code>/写入才触发物理页分配（零页 COW）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>大块 <code>malloc</code> 后不写看似"占了很多内存"其实没占用物理内存（VIRT 高 RES 低）；反之频繁写会触发大量缺页和物理页分配；内存不足时触发 OOM killer 或 swap 抖动。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>排查内存问题看 RES 而不是 VIRT；JVM 堆大小设置影响虚拟内存映射；大缓存预分配 + 预热写入避免运行期抖动；<code>mmap</code> 映射大文件利用虚拟内存按需加载。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>malloc 不写会占用物理内存吗（不会，缺页时才分配）；VIRT 和 RES 的区别；物理地址什么时候被用到（MMU 转换后访存）；为什么进程虚拟地址空间能大于物理内存（按需映射 + swap）。</div>

# 2.3 什么情况下会发生栈溢出？如何排查和避免？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>每次函数调用在栈上分配栈帧（局部变量、参数、返回地址），栈空间有限（Linux 默认 8MB，Java 线程栈默认 1MB）；当栈帧总量超过栈上限时发生栈溢出。常见诱因：无限递归、递归深度过大（如深树遍历）、栈上超大局部变量/数组、线程栈设置过小。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">排查流程：</b>① 看错误信息——C/C++ 段错误（栈溢出信号）或 Java <code>StackOverflowError</code>；② 抓线程栈（<code>jstack</code>/<code>pstack</code>/gdb）看调用链是否循环递归；③ 检查递归终止条件和深度（树/图遍历、正则、序列化递归）；④ 用 <code>ulimit -s</code> 确认栈上限，评估每帧大小（大数组、深拷贝）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">避免手段：</b>① 递归改迭代（显式栈/队列，BFS）；② 限制递归深度（尾递归优化、深度参数）；③ 大数组放堆（<code>malloc</code>/<code>new</code>）而不是栈上；④ 按需调大线程栈（<code>ulimit -s</code>、JVM <code>-Xss</code>），但注意内存总量 = 线程数 × 栈大小；⑤ 压缩对象图深度（嵌套对象转平铺）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>栈溢出是"写越界"还是"深度超限"要区分——深度超限是 <code>StackOverflowError</code>/SIGSEGV 于栈底附近；栈上声明大数组（如 <code>int a[1000000]</code>）也会直接爆栈；Java 递归序列化循环引用也会栈溢出（JSON 循环引用）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>线程栈越大能承载更深递归但内存翻倍（千线程 × 栈 8MB = 8GB）；调大栈是缓解不是根治——深递归应改算法；递归代码要防恶意输入构造深树（如 XML 深度攻击）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>树形结构（组织架构、菜单）遍历用迭代栈；JSON/XML 解析限制最大深度；JVM 服务根据线程数设置合理 <code>-Xss</code>（默认 1MB 通常够用，深递归才调）；压测覆盖深数据场景防生产栈溢出。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>栈溢出和堆溢出的区别（深度 vs 容量）；递归为什么慢（函数调用开销 + 栈压力）可以怎么优化（迭代/尾递归）；线程栈大小怎么定（深度需求 × 单帧大小，权衡线程数）。</div>
  </div>
</div>

  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>TCP 连接四元组 = <b>源 IP + 源端口 + 目的 IP + 目的端口</b>，唯一标识一条连接。连接关闭后，内核要释放与该四元组相关的所有资源，但 TIME_WAIT 状态会保留四元组一段时间（2MSL）防止旧报文串扰新连接。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（释放的资源）：</b>① <b>文件描述符</b>：socket fd 从进程 fd 表移除；② <b>发送/接收缓冲区</b>：sk_buff 队列内存释放；③ <b>TCP 控制块（TCB）</b>：序列号、窗口、拥塞状态等连接状态释放；④ <b>端口</b>：本地端口回到可用池；⑤ <b>定时器</b>：重传、保活等定时器取消；⑥ TIME_WAIT 期间保留四元组和部分状态，2MSL 后才彻底释放。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>TIME_WAIT 由主动关闭方进入（等待 2MSL 约 1-4 分钟）；大量短连接会导致 TIME_WAIT 堆积占用端口；四元组冲突时新连接无法建立——<code>net.ipv4.tcp_tw_reuse</code> 可复用 TIME_WAIT 连接（仅出向）；服务端大量 CLOSE_WAIT 说明对端关闭了但应用没关 fd，是典型的 fd 泄漏。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>连接释放不彻底（CLOSE_WAIT 堆积）会耗尽 fd 和内存；TIME_WAIT 过多会占端口；调小 2MSL 有旧报文串扰风险，一般不主动改；长连接可减少建连/断连开销但要处理保活和失效检测。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>高并发服务用连接池复用 TCP（避免频繁 TIME_WAIT）；排查 <code>ss -tan</code> 看 TIME_WAIT/CLOSE_WAIT 分布；关闭资源要 finally 释放（try-with-resources）；HTTP 服务启用 keep-alive 减少建连；网关层面关注 <code>tcp_tw_reuse</code> 与端口范围。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>为什么主动关闭方要等 2MSL（确保最后一个 ACK 可达 + 旧报文消亡）；CLOSE_WAIT 大量出现说明什么（应用没调用 close，fd 泄漏）；四元组里能有两个相同连接吗（不能，唯一标识）；TIME_WAIT 多怎么办（复用/长连接/调参权衡）。</div>
