# 2.2 SSR 的底层原理是什么？除了 SSR 还有哪些渲染模式？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理（SSR）：</b>服务端把组件渲染成 HTML 字符串返回，浏览器直接展示首屏；随后加载 JS 完成<b>水合（hydration）</b>——绑定事件、接管交互。核心 = 同一套组件代码在 Node 端跑一遍（renderToString），而不是浏览器端渲染。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">渲染模式对比：</b>① <b>CSR（客户端渲染）</b>：空 HTML + JS 渲染——首屏慢、SEO 差，SPA 默认；② <b>SSR</b>：服务端出 HTML——首屏快、SEO 好，代价是服务端压力和 TTI 延迟（水合前不可交互）；③ <b>SSG（静态生成）</b>：构建时生成 HTML——最快、最省，适合内容不变页面（文档/博客）；④ <b>ISR（增量静态再生）</b>：SSG + 定时/按需重建；⑤ <b>混合渲染</b>：按路由选模式（Nuxt/Next 支持）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>SSR 环境没有 window/document（服务端执行要注意副作用）；水合不一致（服务端 HTML 与客户端渲染结果不同）会告警；数据获取要在服务端完成（预取注入）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>SSR 为什么首屏快但交互慢（HTML 先到，JS 后加载水合）；什么场景用 SSG（内容不变）；Next.js 的 SSR 和 SSG 怎么选（数据变化频率）。</div>
  </div>
</div>

# 3.4 `Reflect` 和 `Proxy` 如何理解？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念：</b><b>Proxy</b> 给对象加一层拦截（get/set/has/delete 等 13 种 trap），可以代理任何操作；<b>Reflect</b> 提供与 Proxy trap 一一对应的<b>默认行为方法</b>（<code>Reflect.get</code> 等），保证拦截后能调用原始逻辑且返回值一致。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（典型用法）：</b><code>new Proxy(target, { get(obj, key, receiver) { ...; return Reflect.get(obj, key, receiver); } })</code>——trap 里先做自定义逻辑，再用 Reflect 走默认行为；Reflect 还统一了返回值（如 <code>Reflect.set</code> 返回布尔）和 receiver 绑定。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">应用场景：</b>① Vue 3 响应式（Proxy 代理 data）；② 数据校验/脱敏（set trap 拦截非法值）；③ 埋点统计（get trap 记录访问）；④ 私有属性模拟（has/get trap 隐藏）；⑤ 撤销代理（Proxy.revocable）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>Proxy 和 Object.defineProperty 的区别（全量代理 vs 属性级、Vue2 vs Vue3）；Reflect 为什么存在（统一默认行为 + 函数式调用）；代理能代理函数吗（能，apply trap）。</div>
  </div>
</div>

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">

    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念：</b>AST 是源代码的结构化树形表示——每个节点是一个语法单元（变量声明、函数调用、字面量），是编译器/转译器的中间产物。</div>

    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>词法和语法的区别（切 token vs 组结构）；AST 和 CST 的区别（是否保留无关语法细节）；怎么调试 AST（AST Explorer 可视化）。</div>

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">

      </div>
      <div style="flex:1 1 300px;min-width:0;background:var(--card);border:1px solid var(--border);border-left:3px solid #3A5FBF;border-radius:12px;padding:10px 12px;font-size:13.5px;line-height:1.7;">
        <b style="color:#3A5FBF;">Zustand（自上而下，store 中心）</b>
        <div style="margin:4px 0 0;">一个/几个<b>集中 store</b>（hooks 风格 <code>create</code>），组件选择订阅自己需要的切片（selector），默认浅比较避免多余重渲染。</div>

        <div style="margin:4px 0 0;"><b style="color:#B26E00;">缺点：</b>selector 不当会订阅过宽导致重渲染；大 store 组织不当会变"全局变量袋"。</div>
      </div>
    </div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">怎么选：</b>状态关联松散、粒度细 → Jotai；状态聚合明确、要全局访问 → Zustand；两者都比 Redux 轻量，面试能讲清差异即可。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>为什么 Zustand 比 Context 性能好（selector 订阅 vs 全量重渲染）；原子派生是什么（derived atom 自动计算）；持久化怎么做（persist 中间件）。</div>

# 4.1 HTTP 是什么？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念：</b>HTTP（超文本传输协议）是应用层<b>请求-响应</b>协议，客户端发请求、服务端回响应；无状态、可扩展（头部/方法/状态码可演进），基于 TCP（HTTP/3 基于 QUIC/UDP）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">核心要素：</b>① 方法：GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS；② 状态码：2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误；③ 头部：请求头/响应头携带元数据（Content-Type、Cache-Control、Cookie 等）；④ 版本演进：1.0/1.1/2.0/3.0（见 [[Learn/秋招-面试/八股/自建面经/四大件/计算机网络|计算机网络]] 4.2）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">工作原理：</b>URL 解析 → 建立连接 → 发送请求（请求行 + 头 + 体）→ 服务端处理 → 返回响应（状态行 + 头 + 体）→ 关闭或复用连接。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>GET 和 POST 的区别（语义 + 缓存 + 幂等）；HTTP 和 HTTPS 区别（见 4.1 网络协议）；无状态怎么维持会话（Cookie/Session/Token）。</div>
  </div>
</div>

# 4.2 HTTP 的无状态是什么意思？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念：</b>无状态 = 服务器<b>不保存客户端上下文</b>——每个请求独立，服务端不记得"你是谁、上次做了什么"。好处：易于水平扩展（任何节点可处理任意请求）、协议简单。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">会话维持方案（弥补无状态）：</b>① <b>Cookie + Session</b>：服务端存 Session（内存/Redis），Cookie 带 sessionId；② <b>Token（JWT）</b>：服务端不存状态，签名令牌自包含用户信息，放 Header/Cookie；③ <b>本地存储</b>：localStorage/IndexedDB 存客户端状态。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">前后端配合：</b>前端把登录态（Cookie/Token）随每次请求携带；服务端鉴权后放行——"无状态协议 + 有状态业务"靠会话机制桥接。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>Session 和 JWT 的区别（服务端存储 vs 自包含签名）；无状态为什么利于扩容（无粘性，任意节点处理）；Token 放哪安全（HttpOnly Cookie 防 XSS 读取）。</div>
  </div>
</div>

# 4.5 HTTP 缓存怎么实现？强缓存和协商缓存有什么区别？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="display:flex;flex-wrap:wrap;gap:8px;margin:8px 0 0;">
      <div style="flex:1 1 300px;min-width:0;background:var(--card);border:1px solid var(--border);border-left:3px solid #3A5FBF;border-radius:12px;padding:10px 12px;font-size:13.5px;line-height:1.7;">
        <b style="color:#3A5FBF;">强缓存</b>
        <div style="margin:4px 0 0;"><b>不发请求</b>，直接读本地缓存。</div>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">字段：</b><code>Cache-Control: max-age=3600</code>（相对时间，优先）或 <code>Expires</code>（绝对时间，HTTP/1.0）。</div>
        <div style="margin:4px 0 0;"><b style="color:#B26E00;">命中条件：</b>缓存未过期 → 200 (from disk/memory cache)。</div>
      </div>
      <div style="flex:1 1 300px;min-width:0;background:var(--card);border:1px solid var(--border);border-left:3px solid #3A5FBF;border-radius:12px;padding:10px 12px;font-size:13.5px;line-height:1.7;">
        <b style="color:#3A5FBF;">协商缓存</b>
        <div style="margin:4px 0 0;"><b>发请求</b>，服务端判断是否用缓存。</div>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">字段：</b>请求带 <code>If-None-Match</code>（对比 <code>ETag</code>，内容哈希）或 <code>If-Modified-Since</code>（对比 <code>Last-Modified</code>）。</div>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">结果：</b>未变 → <code>304</code> 用缓存；变了 → 200 新响应。</div>
      </div>
    </div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">配合策略：</b>强缓存 + 版本号（文件名 hash）是静态资源标配——hash 变了 URL 变，天然绕过旧缓存；协商缓存用于 HTML 等需及时更新的资源；<code>no-cache</code> = 走协商，<code>no-store</code> = 完全不用缓存。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>max-age 和 Expires 谁优先（Cache-Control）；ETag 和 Last-Modified 谁可靠（ETag 内容级）；怎么强制刷新（Ctrl+F5 带 no-cache）。</div>

# 4.6 什么是跨域？有哪些解决方式？JSONP 如何实现？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">

  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念：</b>跨域 = 浏览器<b>同源策略</b>限制（协议 + 域名 + 端口任一不同即跨域），阻止页面读取跨源响应（防 CSRF/数据窃取）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">解决方式：</b>① <b>CORS（标准方案）</b>：服务端加 <code>Access-Control-Allow-Origin</code> 响应头；简单请求直接放行，复杂请求（自定义头/非简单方法）先 <b>OPTIONS 预检</b>；② <b>JSONP</b>：利用 <code>&lt;script&gt;</code> 标签不受同源限制，只支持 GET；③ <b>代理转发</b>：开发用 Vite/Webpack proxy，生产用 Nginx 反向代理同源化；④ <b>postMessage</b>：跨域窗口通信（iframe）；⑤ 同源部署（前后端同域）最省事。</div>

# 5.4 HardMan 这类任务如何分析和实现？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">

  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>思路（任务队列 + Promise 链）：</b>
    <div style="margin:6px 0 0;"><b style="color:#3F8C12;">题目本质：</b>「HardMan('jack').rest(3).learn('computer').rest(2).learn('english')」——链式调用 + 按序执行 + 延时任务。核心 = <b>任务队列 + 链式 push + 启动执行</b>。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现要点：</b>① 每个方法把任务（函数/延时）push 进队列并 <code>return this</code>（链式）；② 队列用 <b>Promise 链</b>串联（<code>queue = queue.then(task)</code>），保证顺序；③ 延时用 <code>setTimeout</code> 包 Promise；④ 首次调用启动执行（或构造后自动跑）；⑤ 注意 setTimeout 的调用顺序（先入队后统一执行，避免立即计时）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">追问：</b>为什么用 Promise 链不用 setTimeout 直接排队（保证顺序 + 可等待异步）；如果支持异步任务怎么处理（任务返回 Promise）；怎么支持插入（在链中间插任务）。</div>
  </div>
</div>
