# 1.1 `git reset` 和 `git revert` 有什么区别？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="display:flex;flex-wrap:wrap;gap:8px;margin:8px 0 0;">
      <div style="flex:1 1 300px;min-width:0;background:var(--card);border:1px solid var(--border);border-left:3px solid #3A5FBF;border-radius:12px;padding:10px 12px;font-size:13.5px;line-height:1.7;">
        <b style="color:#3A5FBF;">git reset</b>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">行为：</b>移动当前分支的 HEAD 指针，<b>重写历史</b>——提交记录被移除/修改。</div>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">模式：</b><code>--soft</code>（保留暂存区）、<code>--mixed</code>（默认，保留工作区）、<code>--hard</code>（丢弃工作区改动）。</div>
        <div style="margin:4px 0 0;"><b style="color:#B26E00;">适用：</b>本地未推送的提交回退、整理提交（rebase 前）；<b>已推送的共享分支不要用</b>——会与其他人的历史分叉。</div>
      </div>
      <div style="flex:1 1 300px;min-width:0;background:var(--card);border:1px solid var(--border);border-left:3px solid #3A5FBF;border-radius:12px;padding:10px 12px;font-size:13.5px;line-height:1.7;">
        <b style="color:#3A5FBF;">git revert</b>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">行为：</b>生成一个<b>反向提交</b>来抵消目标提交的改动，<b>不重写历史</b>，原提交保留。</div>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">模式：</b><code>git revert &lt;commit&gt;</code> 自动创建新提交；可 <code>-n</code> 不自动提交。</div>
        <div style="margin:4px 0 0;"><b style="color:#3F8C12;">适用：</b>已推送到共享分支的提交回退——历史完整、协作安全。</div>
      </div>
    </div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>判断标准就一条：<b>提交是否已推送/共享</b>——未推送用 reset 干净回退；已推送用 revert 安全回退。revert 可能出现冲突（后续提交改了同一处），需要手动解决。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>reset --hard 后还能找回提交吗（可以，reflog）；revert 和 cherry-pick 的关系（反向后应用 vs 正向应用）；rebase 和 merge 的区别。</div>
  </div>
</div>

# 2.1 Linux 中 `grep` 和 `awk` 怎么使用？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b><code>grep</code> 负责<b>按行过滤</b>（找匹配的行），<code>awk</code> 负责<b>按列处理</b>（对每行切分字段做计算/格式化）——grep 是筛子，awk 是加工机，常组合使用。常用命令：</div>
  </div>
</div>

```bash
# ===== grep 常用 =====
grep "error" app.log          # 基本匹配
grep -i error app.log         # 忽略大小写
grep -v error app.log         # 反选（不含 error 的行）
grep -n error app.log         # 显示行号
grep -r error ./src           # 递归目录
grep -E "err|warn" app.log    # 扩展正则（多条件）
grep -c error app.log         # 计数
grep -A 3 -B 2 error app.log  # 匹配后 3 行 / 前 2 行

# ===== awk 常用 =====
awk '{print $1, $3}' file            # 取第 1、3 列（默认空格分隔）
awk -F: '{print $1}' /etc/passwd     # 指定分隔符
awk '{sum += $1} END {print sum}'    # 列求和
awk '$3 > 100' file                  # 条件过滤
awk 'NR>1 && $2=="ERROR"' file       # 跳过表头 + 过滤
awk '{print $NF}' file               # $NF = 最后一列

# ===== 组合实战：统计日志中错误码出现次数 =====
grep "ERROR" app.log | awk '{print $NF}' | sort | uniq -c | sort -rn
# grep 过滤 → awk 取列 → 排序计数 → 降序
```

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <div style="margin:0;"><b style="color:#3A5FBF;">关键细节：</b>awk 的 <code>$0</code> 是整行；管道是核心思维（一条命令只做一件事）；处理大文件先 <code>head</code> 看格式再写完整命令；<code>sort | uniq -c</code> 是统计标配。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>grep 和 egrep 的关系（egrep 即 <code>grep -E</code>）；awk 和 cut 的区别（awk 能做计算和条件，cut 只能切）；怎么统计每个 IP 的请求数（awk 取 IP 列 + <code>sort | uniq -c</code>）。</div>
  </div>
</div>

    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>不要凭 top 一屏就下结论——要持续采样（<code>top -d 1</code>、sar）确认持续性；优化前先量化（占比、时长），优化后复测；紧急时先扩容/重启止血，再定位根因。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>监控 CPU 使用率 + load + GC 次数告警；压测基线明确正常水位；大促前容量评估；Java 服务排查标配：top → jstack → 火焰图 → 代码优化。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>load average 高但 CPU 不高可能是什么（I/O 等待/不可中断进程）；Full GC 为什么耗 CPU（标记整理算法 + STW 处理）；上下文切换高怎么降（减少线程数/协程/无锁）。</div>
  </div>
</div>

# 3.1 Docker 了解吗？在项目中怎么使用？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>Docker 是容器化技术：用<b>命名空间（Namespace）</b>隔离进程视图（PID/网络/文件系统），用<b>Cgroups</b>限制资源（CPU/内存），镜像分层复用文件系统，实现"一次构建、到处运行"。与虚拟机区别：共享宿主机内核、无完整 OS 开销、秒级启动。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（项目中使用）：</b>① 写 <code>Dockerfile</code>（基础镜像 → 复制产物 → 启动命令），多阶段构建减小镜像；② <code>docker build</code> 构建镜像，推送到私有仓库（Harbor）；③ <code>docker run</code> 启动；④ 多容器用 <code>docker compose</code> 编排（应用 + Redis + MySQL 本地一键起）；⑤ 生产由 K8s 调度，Docker 只是运行时。常用命令：</div>
  </div>
</div>

```bash
# 构建与推送
docker build -t registry/app:v1.0.0 .
docker push registry/app:v1.0.0

# 运行容器（端口映射 / 数据卷 / 环境变量 / 资源限制）
docker run -d --name app \
  -p 8080:8080 \
  -v /data/app:/app/data \
  -e SPRING_PROFILES_ACTIVE=prod \
  --memory 2g --cpus 2 \
  registry/app:v1.0.0

# 查看与调试
docker ps                 # 运行中的容器
docker logs -f app        # 跟随日志
docker exec -it app bash  # 进入容器
docker compose up -d      # 多容器编排启动
```

  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <div style="margin:0;"><b style="color:#3A5FBF;">关键细节：</b>容器<b>无状态化</b>（数据卷外置，重启不丢）；镜像标签不可变（版本可追溯）；资源限制必须设（<code>--memory --cpus</code>）防容器吃光宿主机；健康检查（<code>HEALTHCHECK</code>）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>容器内日志要输出到 stdout 由采集器收集（别写容器内文件）；镜像体积影响拉取和启动速度（多阶段构建 + 精简基础镜像）；共享内核意味着内核漏洞影响所有容器（隔离弱于虚拟机）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>CI 流水线：代码 → 测试 → 构建镜像 → 推仓库 → K8s 滚动发布；本地开发用 compose 起依赖；环境一致性（开发/测试/生产同一镜像）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>容器和虚拟机的区别（共享内核 vs 独立内核）；镜像分层原理（只读层 + 写时复制）；Namespace 和 Cgroups 各管什么（隔离 vs 限制）；容器里 PID 1 为什么特殊（init 职责）。</div>
  </div>
</div>

# 3.2 Nginx 怎么使用？项目中配置了什么？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>Nginx 是高性能反向代理/Web 服务器，事件驱动 + 多 worker 进程，单机可扛十万级并发连接。项目中的角色：反向代理（转发到后端服务）、静态资源服务、负载均衡、SSL 终结、限流。核心配置如下：</div>
  </div>
</div>

```nginx
# ① 反向代理
location /api/ {
    proxy_pass http://backend_upstream;
}

# ② 负载均衡（轮询 / 加权 / IP hash）
upstream backend {
    server 10.0.0.1:8080 weight=3;
    server 10.0.0.2:8080;
    # ip_hash;  按客户端 IP 哈希，会话保持
}

# ③ 静态资源 + gzip 压缩
location /static/ {
    root /data/web;
    expires 7d;          # 强缓存一周
    gzip on;
}

# ④ SSL 终结
server {
    listen 443 ssl;
    ssl_certificate     /etc/nginx/cert.pem;
    ssl_certificate_key /etc/nginx/cert.key;
}

# ⑤ 限流（每 IP 10 r/s，burst 20 个突发，nodelay 快速拒绝）
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
location /api/ {
    limit_req zone=api burst=20 nodelay;
}

# ⑥ 超时与健康检查
proxy_connect_timeout 5s;
proxy_read_timeout 60s;
```

    <div style="margin:0;"><b style="color:#3A5FBF;">关键细节：</b>反向代理要透传真实 IP（<code>proxy_set_header X-Real-IP $remote_addr;</code>）；WebSocket 需要 <code>Upgrade</code> 头；静态资源命中缓存减少后端压力；gzip 压缩传输体积。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>Nginx 是单点（前面加 LVS/云 LB 或 Nginx 集群）；配置错误会导致服务不可用（先 <code>nginx -t</code> 验证再 reload）；连接数和 worker 数按机器调整（<code>worker_processes</code>、<code>worker_connections</code>）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>前端静态资源 + 后端 API 同域部署（避免跨域）；按路径分流（<code>/api</code> 到后端、其他走静态）；灰度：upstream 里新旧版本按权重切换；限流保护后端。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>Nginx 为什么快（事件驱动 + 非阻塞 + 零拷贝）；反向代理和正向代理的区别（服务端 vs 客户端代理）；reload 为什么不断连接（平滑重载）；Nginx 和 LVS 的区别（七层 vs 四层）。</div>

# 3.3 Kubernetes 了解吗？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>Kubernetes（K8s）是容器编排平台：声明式管理（写 YAML 描述期望状态，控制器持续调和实际状态）。核心对象：<b>Pod</b>（最小调度单元）、<b>Deployment</b>（无状态应用副本 + 滚动更新）、<b>Service</b>（稳定访问入口 + 负载均衡）、<b>ConfigMap/Secret</b>（配置）、<b>Ingress</b>（七层入口）、<b>HPA</b>（自动伸缩）。架构：Master（API Server/Controller/Scheduler）+ Worker（Kubelet/容器运行时）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（部署一个应用）：</b>① 写 Deployment YAML（镜像、副本数、资源限制、探针）；② <code>kubectl apply</code> 提交，Scheduler 把 Pod 调度到节点；③ Kubelet 拉镜像启动容器，探针（就绪/存活）通过后加入 Service 端点；④ 更新时滚动发布（逐个替换，新旧并存），失败自动回滚；⑤ 流量经 Ingress → Service → Pod。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>Pod 是<b>临时</b>的（重建后 IP 变，靠 Service 抽象）；资源 requests/limits 必须设（调度依据 + 限制）；探针决定流量摘除和重启；滚动发布要配 <code>maxUnavailable/maxSurge</code>；配置变更触发滚动重启（ConfigMap 挂载）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>K8s 运维复杂度高（学习成本、etcd 高可用）；有状态应用（数据库）用 Operator 或托管服务更省心；网络插件（CNI）和存储（PV/PVC）选型影响性能；排查问题链路长（Pod 状态 → 事件 → 日志 → 网络）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>CI/CD：镜像推仓库 → GitOps（Argo CD）同步到 K8s；HPA 按 CPU/QPS 自动扩缩容；资源配额和命名空间隔离环境；监控用 Prometheus + Grafana 采集 Pod 指标。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>Deployment 和 StatefulSet 的区别（无状态 vs 有状态，稳定网络标识）；Service 怎么发现 Pod（标签选择器 + Endpoints）；滚动更新和蓝绿发布的区别；Pod 重启会丢什么（本地文件/内存状态，数据卷除外）。</div>
  </div>
</div>

# 3.4 项目是怎么部署的？


<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>部署 = 从代码到线上服务的自动化链路（CI/CD）：提交触发构建、测试、打包、发布，目标是"可重复、可回滚、可追溯"。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实现流程（完整链路）：</b>① 开发提交 → GitLab/GitHub 触发 CI；② 流水线：单元测试 + 静态检查 → 构建（Maven/Gradle）→ 打镜像（Dockerfile 多阶段）→ 推私有仓库（Harbor）；③ CD：更新 K8s 清单（GitOps/Argo CD 或流水线直接 apply）→ 滚动发布（新 Pod 就绪后摘旧 Pod）；④ 发布后：健康检查 + 监控（错误率、P99、GC）观察；⑤ 异常自动回滚到上一版本。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>镜像标签不可变（<code>commit-sha</code> 可追溯）；配置与代码分离（ConfigMap/环境变量，不同环境不同配置）；数据库变更要先于代码发布（兼容新旧代码）；发布窗口和大促冻结期。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>自动化程度越高越依赖 CI 稳定（流水线本身要监控）；灰度不充分直接全量发布风险大（先小流量）；回滚要验证（数据迁移类变更不可简单回滚）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>本地：Docker Compose 起依赖；测试/生产：K8s 滚动发布 + 灰度（Ingress 按权重）；发布检查清单：迁移脚本、配置、探针、监控看板、回滚预案；发布后立即看关键指标。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>滚动发布和蓝绿的区别（渐进替换 vs 双环境切换）；灰度怎么实现（权重/按用户）；发布后怎么确认成功（健康检查 + 监控指标对比基线）；数据库迁移和发布顺序（先库后码）。</div>
  </div>
</div>

# 3.5 排查问题时了解或使用过哪些开源工具？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <span style="display:inline-block;padding:2px 10px;border-radius:999px;background:rgba(58,95,191,.10);border:1px solid rgba(58,95,191,.22);color:#3A5FBF;font-size:12.5px;font-weight:600;">公司：腾讯</span>
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">概念原理：</b>排查工具按场景分四类：<b>链路追踪</b>（请求到哪了、哪段慢）、<b>指标监控</b>（资源与业务水位）、<b>日志分析</b>（错误与现场）、<b>深度诊断</b>（JVM/性能热点）。面试关键是"什么场景用什么工具 + 实际用过哪个"。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">常用工具清单（按场景）：</b>① <b>链路追踪</b>：Jaeger、Zipkin、SkyWalking——看 Trace 各 span 耗时定位慢段；② <b>指标监控</b>：Prometheus + Grafana——CPU/内存/GC/QPS/错误率大盘和告警；③ <b>日志</b>：ELK（Elasticsearch + Logstash + Kibana）、Loki——集中检索错误日志；④ <b>JVM 诊断</b>：jstat/jmap/jstack、MAT（heap dump 分析）、Arthas（线上诊断神器：看方法耗时、反编译、热更新）、JFR；⑤ <b>性能剖析</b>：async-profiler 火焰图——定位 CPU 热点；⑥ <b>网络</b>：tcpdump、Wireshark、netstat/ss、mtr（路由丢包）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">实际排查组合：</b>接口慢 → SkyWalking/Jaeger 看链路（发现某段 DB 慢）→ Prometheus 看 DB 连接池/慢查询指标 → ELK 搜相关日志确认 SQL → 用 EXPLAIN 分析；JVM 问题 → Arthas 看线程/GC → jmap dump + MAT 查泄漏 → 火焰图找热点。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">关键细节：</b>工具要<b>按场景选型</b>而不是堆砌：小团队 Prometheus + Loki + Arthas 就够；链路追踪要全量接入才有价值（采样率权衡）；Arthas 线上操作要谨慎（热更新影响运行态）。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">风险与取舍：</b>全链路可观测（追踪+指标+日志）建设成本高，按核心链路优先接入；工具本身也要监控（ES 集群挂了日志查不了）；诊断工具权限要收敛（Arthas 能改线上代码）。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">项目落地：</b>监控：Prometheus 采集应用指标（QPS、P99、GC）+ 告警规则；日志：Loki/ELK 集中检索；诊断：Arthas 日常排障、MAT 分析 OOM dump、火焰图优化热点；发布后对比指标基线。</div>
    <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>SkyWalking 和 Jaeger 的区别（APM 全家桶 vs 链路组件）；Arthas 常用命令（dashboard/thread/trace/watch）；火焰图怎么看（横轴时间占比、宽的函数是热点）；jmap 和 jstack 分别看什么（堆 vs 线程）。</div>
  </div>
</div>

# 3.7 灰度发布的风险控制关键点是什么？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3A5FBF;">核心四步：</b>「<b>分批、观测、门禁、回滚</b>」。先按用户、租户、地域或实例分批放量，确保灰度组具有代表性；每一批都要有稳定观察窗口，不能刚发布就继续扩大比例。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">指标门禁：</b>同时看技术指标和业务指标，例如错误率、P95/P99、超时率、CPU/内存、线程池队列、数据库连接，以及支付成功率、下单转化率等。阈值要和基线、流量规模、时间窗口绑定，并设置自动暂停和人工确认。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">一致性控制：</b>灰度策略、代码版本、配置版本和数据库兼容性要绑定，避免同一用户在新旧版本之间来回漂移。涉及缓存、消息和状态机时，优先保证新旧版本都能读写，切换完成后再清理旧逻辑。</div>
    <div style="margin:8px 0 0;"><b style="color:#9B5C00;">回滚边界：</b>应用版本通常可以快速回切，但数据库字段删除、数据格式变更和不可逆消息发送不能简单回滚。发布前要准备反向兼容脚本、流量开关、数据修复方案，并记录每批次的版本和时间。</div>
  </div>
  <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>灰度看板里你最看重哪 3 个核心指标？灰度流量没有覆盖到真实长尾用户怎么办？为什么发布成功但业务指标下降？</div>
</div>

# 3.8 变更三板斧怎么落地到工程体系？

<div style="--primary:#3A5FBF;--card:var(--background-primary);--border:var(--background-modifier-border);--text:var(--text-normal);--muted:var(--text-muted);max-width:780px;font:14px/1.65 Roboto,'PingFang SC','Segoe UI',Arial,sans-serif;color:var(--text);margin:12px 0;box-sizing:border-box;">
  <div style="margin:8px 0 0;background:var(--card);border:1px solid var(--border);border-left:3px solid var(--primary);border-radius:12px;padding:12px 14px;">
    <b>回答：</b>
    <div style="margin:6px 0 0;"><b style="color:#3F8C12;">三板斧：</b><b>可灰度</b>是把影响面拆小，<b>可监控</b>是用指标及时发现偏差，<b>可回滚</b>是把系统恢复到已知稳定版本。三者缺一不可：没有灰度无法降低爆炸半径，没有监控无法判断成功，没有回滚就只能现场修复。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">发布前：</b>流水线执行编译、测试、静态检查、依赖和配置校验；变更单明确负责人、影响范围、灰度策略、指标基线、停止条件和回滚步骤。数据库变更采用先扩展后切换，再延迟删除的兼容模式。</div>
    <div style="margin:8px 0 0;"><b style="color:#3A5FBF;">发布中：</b>由流水线统一推进流量比例和配置版本，自动采集错误率、延迟、资源、业务转化和日志异常；触发门禁后自动暂停或回滚，人工只处理需要判断的高风险变更。</div>
    <div style="margin:8px 0 0;"><b style="color:#3F8C12;">发布后：</b>保留观察窗口和版本标记，核对关键指标是否回到基线，清理临时开关和旧实例；异常要形成时间线、影响面、根因、处置动作和预防项，沉淀为检查项或自动化规则。</div>
    <div style="margin:8px 0 0;"><b style="color:#9B5C00;">工程取舍：</b>阈值过保守会导致频繁误报和发布阻塞，过宽又会错过真实故障；要按接口等级、流量规模和变更类型设置分层门禁，并允许紧急变更走最小审批但保留审计。</div>
  </div>
  <div style="margin:8px 0 0;"><b style="color:#B26E00;">面试追问：</b>如果监控阈值设太保守，会造成什么工程副作用？如何验证回滚真的有效？紧急变更如何兼顾速度和审计？</div>
</div>
