## 三、长期记忆

**定义**：跨会话持久化的稳定事实。落盘，会话结束不消失，下次启动仍能召回。

**存储形态**：一条记忆一个 Markdown 文件，正文即权威内容，计数走旁路。这样做的好处是每条记忆可独立读、独立改、独立删，不依赖任何数据库。

**内容分类**：用户偏好、项目事实（项目/仓库/符号作用域）、个人属性、反馈。

### 写入路径

- **自动**：任务结束时由隔离 Curator 裁决，只接受「能逐句引用明确陈述或成功工具原文」的内容。  
    这条限制解决的是「模型自己编一条记忆存下来」的问题——存进去的每句话都必须有出处。
- **结构化**：解析出 `subject / predicate / scope` 三元组，用于后续冲突判定。

### 冲突消解

新条目写入时，按 `StableKey(subject, predicate, scope)` 找同键旧条目：

- 旧条**软删**（标记已被取代 + 修订号 +1），不物理删除。
- 只有新旧**双方都是单值声明**时才自动取代；多值或未知则并存。

为什么需要这个区分：「用 Java 17」和「用 Java 21」互斥，必须只留一条；「支持 Linux」和「支持 Windows」不互斥，不能覆盖。把这两种情况混在一起处理，必然出错。

### 生命周期：硬 TTL + 软过期

这是长期记忆最需要讲清的一点——它有**两套独立的过期机制**。

**硬 TTL（到期物理删除）**​

|类型|寿命|
|---|---|
|会话记录 / 工具结果|7 天|
|摘要|30 天|
|反馈|永久|
|事实（稳定类）|永久|
|事实（普通）|180 天|

**软过期（不删除、不降权，只打标记）**​

- 触发条件：可重新验证类记忆，超过 180 天未被验证。
- 表现：注入时追加 `freshness=STALE; 待重新验证`。
- 适用：偏好、项目/仓库/符号作用域事实、反馈、流程，以及所有可变知识。
- **不适用**：教训（lesson）、决策（decision）——它们是历史事实，不需要重新验证。

软过期的设计意图：让模型知道「这条可能过时了，用之前先确认」，而不是系统擅自删掉一条可能仍然正确的信息。

**重新验证**  
记忆被再次确认时刷新验证时间，并按累计验证次数延长硬 TTL：

- 验证过 3 次 → 寿命 ×3
- 验证过 7 次 → 寿命 ×4
- 其余 → ×2

含义：反复被用到的记忆，系统判定它稳定，给它更长的寿命。这是一条「用进废退」的正反馈。


# 2.**什么条件下写入长期记忆，以及长期记忆过时后怎么处理**。

首先判断值不值得记，也就是这是临时信息？ 还是以后还能用的信息？，
对于临时状态，比如测试失败了，这些不能记录，

接下来是证据，也就是记忆应该带有出处，比如假如模型判断某一句内容需要保存，那么系统应该回头找，这句话，去证明这个真正的有用，才应该记录。


但是保存成功 ≠ 系统理解这条记忆。，



然后是，系统的兜底设计，每次把长期记忆塞给模型时，都会告诉模型：这些记忆是过去的记录。

它们可能已经过时。如果当前用户或当前工具观察和旧记忆冲突，以当前信息为准。


# 3.项目级别的记忆，


对于 coding agent 来说，长期记忆应该分成两种，第一种是全局长期记忆，这种从会话历史种自动的提取事实，用户偏好，人物关系、跟进事项。

另外一种则是项目级别的长期记忆，对于 coding agent 来说，每一个不同的项目，都应该再项目目录下面存在一个属于自己项目的长期记忆文件夹。同样这个项目级别的记忆中内容，通过

项目中其实设置有两种类似的记忆，
第一是文本记忆，比如用户说不要操控数据库或者支付模块正在从旧版本进行迁移，哪些完成了哪些没有完成，这种适合约束，经验教训，或者项目的背景，设计决策等，优点是表达能力强，什么都能写，但是缺点是不容易解决冲突

第二种是，结构化记忆，比如项目记忆中记录一些明确的可以表示成“某个属性当前是什么值”的事实。比如用 json 表示
```json
{
  "project": {
    "language": "java",
    "java_version": "21",
    "build_system": "maven",
    "test_command": "mvn test",
    "database": "postgresql"
  }
}
```

设计结构化记忆的目的是为了处理，比如项目一开始使用的 maven，后面改成了 gradle，那么这个就不需要 LLM 再去判断这两个事实是不是矛盾，程序自己就知道，那么直接修改即可。所以“结构化记忆”本质上是项目的事实状态表

需要克制的地方，结构化记忆”千万不要什么都往里塞
应该只有高价值、稳定、机器能确定解释的事实进入结构化层
