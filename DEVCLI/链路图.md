
# 1.假设用户输入“分析这个仓库并修复某个 bug”，从用户请求进入 Agent 开始，到代码修改、验证并返回结果为止，整个流程是怎么走的？请重点说明每一步的输入输出，以及你具体负责实现了哪些部分。

**第一步，接收任务并准备上下文。**

系统识别用户输入和当前项目，装配系统规则、适用的 Skill、对话上下文及相关记忆。默认进入单 Agent 执行流程；只有用户明确使用 `/plan`，才进入固定的计划与多 Agent 编排流程。

**第二步，模型判断下一步需要什么证据。**

模型通常先选择读取文件、精确搜索或代码检索，定位问题相关的实现。它生成的是工具名称和参数，**不是直接获得执行权限的命令。**

**第三步，工具调用经过程序检查。**

注册表检查工具是否存在、当前执行者是否有权限，以及参数格式和内容是否符合规则。需要审批的操作再进入相应审批流程。

例如，只读子 Agent 不能修改文件；受保护配置不能通过文件工具修改；实际走主机的命令需要单次确认，关闭审批也不能直接放行。

**第四步，执行工具，把真实结果交回模型。**

工具返回读取内容、修改结果、退出码或错误信息。模型根据这些结果决定继续定位、调整方案，还是进入验证。

这里是一个循环：**判断下一步 → 调用工具 → 获取结果 → 再判断。**失败不会直接当成成功，也不会允许无限重试，执行过程有预算、轮数、超时和取消控制。

**第五步，必要时委派子任务。**

默认模式也可以按需委派，但不会自动变成完整的 DAG 编排。子任务使用受限权限；隔离 Worker 的修改先留在独立工作区，归并前检查版本和冲突，不能直接覆盖其他任务的新修改。

**第六步，验证并形成最终答复。**

根据任务执行编译、测试或其他检查，最后汇总实际修改、验证结果及未完成事项。模型说“已经修复”本身不算证据，需要对应工具执行记录；没有运行的检查，必须明确说明没有验证。
