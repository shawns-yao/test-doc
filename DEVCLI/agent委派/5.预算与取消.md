# 28.系统如何检测重复工具调用、工具调用死循环和连续失败？

首先是停滞检测，如果发现连续几轮的「工具名 + 参数」完全相同，则是出现了重复调用工具
由系统提醒一句，给一次容错的机会，如果仍然这样，则应该停止，当然还需要参数归一化，因为模型可能会修改部分内容，但是它仍然是同一种调用

重复的工具错误，比如需要删除一个文档，被权限拒绝，那么模型可能想，我再换一个写法，

# 29.取消发生在模型请求中、工具执行中、子 Agent 执行中时，分别如何处理？


取消不是“给模型发一句别干了”，而是一个从根任务向下传播的系统级信号。
也就是模型请求停止，工具停止，子 agent 停止，子 agent 执行的工具也停止


1取消发生在模型请求中
比如 LLM 正在进行回答，正在发起 Tool Call 如果这个时候用户点击了停止，那么不能把这个**半截工具调用**拿去执行。所以取消以后应该：模型部分响应，没有形成完整的 tool call，后面的直接丢弃

2.取消发生在工具执行中
假如模型已经生成了工具调用，并且工具已经开始跑了，如果这个时候用户点击取消，那么 agent 虽然看起来停止了，但是后台可能还有任务再跑,，这种情况就比较危险，那么所以工具取消必须解决两件事：
逻辑停止 + 实际执行停止。

首先是工具停止，再工具执行接口中有一个 CancellationToken，取消令牌，工具执行过程中周期性检测，采用这种协作式取消，然后 kill 杀掉进程

如果工具以及产生了副作用。可以采用，能一次性提交的，尽量最后统一提交。比如先写入临时文件，这几个文件生成完成之后，原子提交

3.取消发生再子 agent 执行过程中，也就是主 agent 委派了子 agent，子 agent 又发起了工具调用，那么如果用户取消主 agent，子 agent 也必须一起取消
