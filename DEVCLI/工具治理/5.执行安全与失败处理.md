# 24.如何防止路径穿越、绝对路径和符号链接逃逸？

路径安全不能只做字符串匹配，而应该基于最终解析后的真实资源做判断。
相对路径需要先规范化并解析到 workspace，
绝对路径同样要验证是否仍在允许范围；
对于符号链接，还要通过 realpath 或 canonical path 判断最终真实目标，避免项目目录内的 symlink 指向项目外。

对于目标文件还不存在的场景，会向上寻找最近存在的父目录，解析其真实路径，再拼接剩余路径。最终所有写、删、读操作都必须验证解析后的目标仍位于允许的 root 内。

核心就是：**检查的不是“用户输入的路径字符串”，而是“这个路径最终会访问哪个真实资源”。**

# 26.工具失败后，什么时候应该交给模型纠正，什么时候应该直接拒绝？

模型负责纠正“调用方式错误”，程序负责终止“不可纠正的执行边界”。

对于可以纠正的，比如参数缺失，格式错误等，可以让模型进行重新规划

对于网络抖动，临时 5 xx，或者限流等，可以进行自动重试

对于不可继续的错误，应该直接拒绝，比如危险操作等
