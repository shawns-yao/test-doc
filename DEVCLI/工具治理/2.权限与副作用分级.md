# 7.为什么不能仅根据工具名称判断权限？

**工具名称只能说明“调用了哪一类能力”，不能说明“这一次具体要做什么”**。
比如 execute_command，执行命令，我们只能知道 Agent 想执行命令，但是不知道它执行的是：mvntest 还是 rm -rf
所以如果权限只按工具名称判断，那就等于：只要 Agent 有执行命令权限，它就可以执行任何命令。


再比如 read_file 一个是读正常的文件，一个是读用户的私钥，那么读用户的私钥显然不可用
如果只通过工具名称判断权限，那两个都会被放行。
所以真正判断的应该是这次具体读哪个路径，这个路径是否在允许范围内 +是不是敏感文件

# 9.为什么只允许幂等只读工具并行？

只读保证“不产生副作用”，幂等保证“重复执行也不会改变结果”，这两者叠加后最适合安全并行。

写操作不能随便并行，比如看起来修改的位置不同，但问题是它们可能都是基于同一个旧版本：
	最后谁后写入，谁可能把另一个人的修改覆盖掉。

所以写操作应该顺序执行，或者需要版本检测，事务，冲突检测

以及为什么还强调“幂等，因为只读还不完全够。幂等的意思是：同一个操作执行一次和执行多次，对系统产生的最终效果相同。
