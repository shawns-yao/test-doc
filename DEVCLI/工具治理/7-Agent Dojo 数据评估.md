# 1.Benign Utility 89.13% 

在没有攻击下，加入权限，schema 后，Agent 还能不能正常的运行

为什么不是 100%，哪些失败了
1.契约失真，比如把我未读的邮件展示给我，要求使用官方提供的工具，get_unread_emails 
这个工具会找到所有的 read= =false 的邮件，同时改成 read= = true 将未读改成已读，并且官方评价指标中会明确的检测邮件是否如期的标记成了已读

发生这个问题的原因是，项目的工具链路发生了一个误判，
	如官方的工具接入到治理系统中，项目的工具注册表根据工具名称带的 get，认为这是一个只读工具，也就是告诉系统，这个工具不会修改状态，但是
	判断哪一个邮件是未读，需要打开邮件，那么会将未读改成已读

修改方案，需要一个多维度的工具声明，比如不仅仅是判断是不是只读工具，还需要将登记的信息改成，这个工具的主要目的，附带的变化，影响程度

第二个问题，项目授权过于僵化，这个问题是，项目中对于写入，创建，一开始要求用户审批，在测试过程中没有一个真人用户手动的点击同意，所以这个是安全策略误杀了正常的行为，所以当前的项目改成了通过自动审批，防止用户审批疲劳
