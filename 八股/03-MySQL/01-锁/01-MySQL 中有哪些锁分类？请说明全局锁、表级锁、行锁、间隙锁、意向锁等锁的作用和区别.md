# 01 MySQL 中有哪些锁分类？请说明全局锁、表级锁、行锁、间隙锁、意向锁等锁的作用和区别。

## 01 核心回答


MySQL 的锁可以按**作用范围**分为全局锁、表级锁和行级锁，也可以按**兼容关系**分为共享锁（读锁）和排他锁（写锁）。

全局锁

锁定整个数据库实例，典型命令 `FLUSH TABLES WITH READ LOCK`，常用于一致性备份，期间通常不允许写入。

表级锁

锁定整张表，粒度大、开销小，但并发度低；常见有表锁、元数据锁（MDL）和意向锁。

行级锁

以索引记录和扫描区间为对象，并发度较高，但加锁开销更大；InnoDB 的记录锁、间隙锁和临键锁都属于行锁体系。

间隙锁

锁定索引记录之间的范围，防止其他事务在范围内插入，从而避免幻读，主要出现在可重复读隔离级别下的范围查询。

意向锁

表级别的标记锁，表示事务准备在表中的某些行上加共享锁或排他锁，方便表锁快速判断是否存在行锁冲突。

实际加什么锁还取决于存储引擎、索引是否命中、事务隔离级别和 SQL 的范围条件。排查锁等待时要结合执行计划、事务状态和锁等待信息，不能只看 SQL 表面。

**面试追问：**间隙锁为什么能防幻读（锁定范围阻止插入）；意向锁的作用（表锁与行锁的冲突快速判断）；记录锁/间隙锁/临键锁的区别（记录 / 区间 / 左开右闭区间）；MDL 锁是什么（表结构变更时的元数据锁）。

## 02 理解机制与追问

InnoDB 加锁对象是索引记录和区间，而不是 SQL 文本里的抽象“行”。RR 下范围锁定读常使用 next-key lock；唯一索引全列等值命中已有记录时通常只需记录锁。未命中、非唯一条件或扫描路径不同，加锁范围也不同。无合适索引可能扫描并锁住大量记录，并不是自动把行锁升级为表锁。

意向锁解决粗粒度表锁与细粒度行锁的兼容判断；不同事务的 IX 可以兼容。插入意向锁则是插入前的间隙锁请求，两者不要混淆。MDL 保护表结构，即使普通查询不加记录锁，也会涉及 MDL；长事务可能挡住 DDL。

## 03 易错点与适用边界

修正原“只锁满足条件的记录”：锁范围还由扫描路径和隔离级别决定。普通 RR 快照 SELECT 不因范围条件就自动加间隙锁。RC 的搜索和扫描通常不用间隙锁，但外键检查、重复键检查仍有例外。纯 gap lock 可以彼此共存，它主要阻止插入。

## 04 面试口述

我会先按全局、表和索引记录分类，再区分 S/X、意向锁与间隙锁。分析具体 SQL 时先看隔离级别和索引扫描范围，再看等待双方持有什么锁，而不是笼统说“有索引就是行锁”。
