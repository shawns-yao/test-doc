# 02 左连接和右连接的区别？两表内联查询 `on` 和 `where` 的区别？

## 01 核心回答


**LEFT JOIN**

以左表为基准，左表全部行保留，右表无匹配补 NULL。

**RIGHT JOIN：**对称——以右表为基准；实际写法上 LEFT JOIN 更通用（调整表顺序即可，可统一书写风格，是否限制由团队规范决定）。

**ON vs WHERE（内连接）**

**内连接（INNER JOIN）下二者结果等价**，区别在语义和执行阶段：ON 在**连接阶段**决定两表如何配对，WHERE 在**连接完成后**过滤结果行。

**外连接时差异巨大：**`LEFT JOIN t2 ON t1.id = t2.id AND t2.status = 1` 只影响匹配条件（不匹配仍保留左表行，status 为 NULL）；`ON t1.id = t2.id WHERE t2.status = 1` 会过滤掉无匹配行（等效内连接）。

**关键细节：**左连接想"只保留匹配的右表行"应把过滤条件放 WHERE（会变内连接语义，注意是否违背意图）；查"左表没有匹配的行"用 `WHERE t2.id IS NULL`（LEFT JOIN + 空判断 = 差集）。

**面试追问：**LEFT JOIN 右表过滤条件放 ON 和 WHERE 的结果差异（补 NULL vs 丢行）；多个 LEFT JOIN 的顺序（看括号、依赖与优化器允许的重排，不能只看书写顺序）；JOIN 字段类型不一致会怎样（隐式转换，可能索引失效）。

## 02 理解机制与追问

逻辑上先依据 ON 配对，外连接为无匹配行补 NULL，再应用 WHERE。以内连接为前提，普通确定性过滤谓词在 ON/WHERE 间移动通常等价；物理执行由优化器决定，不代表数据库真的先生成全部笛卡尔结果再过滤。

## 03 易错点与适用边界

修正：“多数团队禁用 RIGHT JOIN”没有可验证普适依据，统一 LEFT JOIN 是可读性选择。反连接用右表不为 NULL 的主键做 IS NULL 判断，不能选可空业务列，否则匹配到 NULL 也被误认为没匹配。多个 LEFT JOIN 还受括号和后续 ON 引用影响，不能只背固定物理执行顺序。

## 04 面试口述

LEFT/RIGHT 的关键是保留哪侧。内连接里过滤位置常可互换，外连接里则会影响补 NULL 的行能否留下；排查时先验证结果语义再谈优化。
