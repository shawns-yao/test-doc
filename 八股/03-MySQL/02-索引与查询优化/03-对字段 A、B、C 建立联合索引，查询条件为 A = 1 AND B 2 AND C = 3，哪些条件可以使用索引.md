# 03 对字段 A、B、C 建立联合索引，查询条件为 `A = 1 AND B > 2 AND C = 3`，哪些条件可以使用索引？

## 01 核心回答


**结论：**对于联合索引 `(A, B, C)`，`A = 1` 可以使用索引精确定位；接着 `B > 2` 可以继续确定扫描区间；由于 `B` 是范围条件，`C` 在 B+ 树排序中只保证在相同 `A、B` 值内部有序，因此**通常不能继续用于缩小连续的索引扫描范围**。

**C 条件并非完全没用：**如果 MySQL 使用 **Index Condition Pushdown（ICP）**，且 `C` 已包含在联合索引中，存储引擎可以在索引层先判断 `C = 3`，减少回表数量——执行计划的 `Extra` 可能显示 `Using index condition`；如果查询字段也都被索引覆盖，还可能直接使用覆盖索引。

**关键细节（面试表述）：**“用于索引定位和确定范围的是 A、B，C 通常不能继续缩小范围，但可能通过索引条件下推参与过滤。”实际情况仍需结合 MySQL 版本、优化器选择和 `EXPLAIN ANALYZE` 结果确认。

**面试追问：**如果把条件改成 `B > 2 AND C = 3` 呢（不能直接利用普通最左前缀范围访问，但可能覆盖扫描或 Skip Scan）；范围条件放最后是不是更好（通常有利于本查询的范围定位，但仍须兼顾排序和其他查询）；ICP 和覆盖索引的区别（索引层过滤 vs 免回表）。

---

## 02 理解机制与追问

A 固定为 1 后，B 大于 2 对应索引上的连续区域；区域内每一个 B 值各自有按 C 排序的小段，C=3 在整个区域不是一个连续子区间。因此 A/B 决定起止位置，C 可作为扫描时的剩余过滤条件。ICP 对 InnoDB 主要用于需要回表的二级索引访问；覆盖查询直接在索引中完成过滤，不要求出现 Using index condition。

---

## 03 易错点与适用边界

原追问“没有 A 直接无法使用”过于绝对：可能覆盖扫描，也可能在满足限制时 Skip Scan。将索引改为 (A,C,B) 对本题的等值、等值、范围访问通常更有利，但会影响其他查询和排序，必须按工作负载验证。

---

## 04 面试口述

用于构造常规范围的是 A 和 B，C 不会继续缩小这个连续范围，但可能通过索引层过滤减少回表。是否换成 A、C、B 要看整组查询，不能只优化一道题。
