# 02 `malloc` 返回的是虚拟地址吗？物理地址什么时候会被使用？

## 01 核心回答


**概念原理：**`malloc` 返回的是**虚拟地址**，不是物理地址。在常见启用虚拟内存的通用操作系统中，普通用户程序使用虚拟地址；物理内存由内核通过页表映射按需分配。这是"虚拟内存"设计的核心：进程地址空间只是映射关系，不是真实占用。

**实现流程：**① `malloc` 在堆区分配虚拟地址范围（大块走 `mmap`，小块从内存池 `brk` 扩展）；② 首次访问该地址时触发**缺页异常**；③ 内核分配物理页、建立页表映射（写时分配）；④ 后续访问直接命中页表。新匿名映射通常按需分配，但分配器元数据、已有驻留内存池和复用块仍可能占用物理内存。

**关键细节：**物理地址只在 CPU 访问内存时由 MMU 通过页表转换产生，用户程序全程不可见；`top` 的 VIRT（虚拟）vs RES（常驻物理）差别就在这里；`memset`/写入才触发物理页分配（零页 COW）。

**风险与取舍：**新映射的未触碰部分可能暂不占物理页，但整个分配过程仍可能因元数据和内存池而消耗物理内存（VIRT 高 RES 低）；反之频繁写会触发大量缺页和物理页分配；内存不足时触发 OOM killer 或 swap 抖动。

**项目落地：**排查内存问题看 RES 而不是 VIRT；JVM 堆大小设置影响虚拟内存映射；大缓存预分配 + 预热写入避免运行期抖动；`mmap` 映射大文件利用虚拟内存按需加载。

**面试追问：**malloc 不写会占用物理内存吗（不能一概而论，新映射、已有内存池和元数据情况不同）；VIRT 和 RES 的区别；物理地址什么时候被用到（MMU 转换后访存）；为什么进程虚拟地址空间能大于物理内存（按需映射 + swap）。

---

## 02 理解补充与边界校订

malloc 返回虚拟地址是结论，但「不读不写就完全不占物理内存」不成立：分配器元数据、已驻留内存池和复用页本身可能占用物理页。新匿名映射的驻留增长常由首次触碰触发；读可能映射共享零页，写可能触发写时复制。排障同时看 RSS/PSS、映射类型与内存限制，不能只看 VIRT 或 malloc 成功。
