# 04 TCP 关闭连接后，操作系统需要释放哪些资源？四元组分别是什么？

## 01 核心回答


**概念原理：**TCP 连接四元组 = **源 IP + 源端口 + 目的 IP + 目的端口**，唯一标识一条连接。连接关闭后，内核要释放与该四元组相关的所有资源，但 TIME_WAIT 状态会保留四元组一段时间（2MSL）防止旧报文串扰新连接。

**实现流程（释放的资源）：**① **文件描述符**：关闭一个 fd 只会移除当前进程 fd 表中的引用，`dup`/`fork` 共享的引用仍可能让底层 socket 存活；② **发送/接收缓冲区**：sk_buff 队列内存释放；③ **TCP 控制块（TCB）**：序列号、窗口、拥塞状态等连接状态释放；④ **端口**：本地端口按地址和端口组合参与复用，不是被 TIME_WAIT 全局独占；⑤ **定时器**：重传、保活等定时器取消；⑥ TIME_WAIT 期间保留四元组和部分状态，2MSL 后才彻底释放。

**关键细节：**TIME_WAIT 由主动关闭方进入（等待 2MSL 约 1-4 分钟）；大量短连接会导致 TIME_WAIT 堆积占用端口；四元组冲突时新连接无法建立——`net.ipv4.tcp_tw_reuse` 可复用 TIME_WAIT 连接（仅出向）；服务端大量 CLOSE_WAIT 说明对端关闭了但应用没关 fd，是典型的 fd 泄漏。

**风险与取舍：**连接释放不彻底（CLOSE_WAIT 堆积）会耗尽 fd 和内存；TIME_WAIT 过多会占端口；调小 2MSL 有旧报文串扰风险，一般不主动改，也不能把 `tcp_fin_timeout` 当作缩短 TIME_WAIT 的通用参数，它主要控制特定 FIN_WAIT_2 情况；长连接可减少建连/断连开销但要处理保活和失效检测。

**项目落地：**高并发服务用连接池复用 TCP（避免频繁 TIME_WAIT）；排查 `ss -tan` 看 TIME_WAIT/CLOSE_WAIT 分布；关闭资源要 finally 释放（try-with-resources）；HTTP 服务启用 keep-alive 减少建连；网关层面关注 `tcp_tw_reuse` 与端口范围。

**面试追问：**为什么主动关闭方要等 2MSL（确保最后一个 ACK 可达 + 旧报文消亡）；CLOSE_WAIT 大量出现说明什么（应用没调用 close，fd 泄漏）；四元组里能有两个相同连接吗（不能，唯一标识）；TIME_WAIT 多怎么办（复用/长连接/调参权衡）。
