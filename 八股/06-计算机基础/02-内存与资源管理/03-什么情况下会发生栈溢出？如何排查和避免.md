# 03 什么情况下会发生栈溢出？如何排查和避免？

## 01 核心回答


**概念原理：**每次函数调用在栈上分配栈帧（局部变量、参数、返回地址），栈空间有限（Linux 常见 8MB、Java 平台线程常见 1MB，但均依平台与配置而定）；当栈帧总量超过栈上限时发生栈溢出。常见诱因：无限递归、递归深度过大（如深树遍历）、栈上超大局部变量/数组、线程栈设置过小。

**排查流程：**① 看错误信息——C/C++ 段错误（栈溢出信号）或 Java `StackOverflowError`；② 抓线程栈（`jstack`/`pstack`/gdb）看调用链是否循环递归；③ 检查递归终止条件和深度（树/图遍历、正则、序列化递归）；④ 用 `ulimit -s` 确认栈上限，评估每帧大小（大数组、深拷贝）。

**避免手段：**① 递归改迭代（显式栈/队列，BFS）；② 限制递归深度（深度参数；尾递归优化必须由语言实现明确支持）；③ 大数组放堆（`malloc`/`new`）而不是栈上；④ 按需调大线程栈（`ulimit -s`、JVM `-Xss`），但注意内存总量 = 线程数 × 栈大小；⑤ 压缩对象图深度（嵌套对象转平铺）。

**关键细节：**栈溢出是"写越界"还是"深度超限"要区分——深度超限是 `StackOverflowError`/SIGSEGV 于栈底附近；栈上声明大数组（如 `int a[1000000]`）也会直接爆栈；Java 递归序列化循环引用也会栈溢出（JSON 循环引用）。

**风险与取舍：**线程栈越大能承载更深递归但内存翻倍（千线程 × 栈 8MB = 8GB）；调大栈是缓解不是根治——深递归应改算法；递归代码要防恶意输入构造深树（如 XML 深度攻击）。

**项目落地：**树形结构（组织架构、菜单）遍历用迭代栈；JSON/XML 解析限制最大深度；JVM 服务根据线程数设置合理 `-Xss`（默认 1MB 通常够用，深递归才调）；压测覆盖深数据场景防生产栈溢出。

**面试追问：**栈溢出和堆溢出的区别（深度 vs 容量）；递归为什么慢（函数调用开销 + 栈压力）可以怎么优化（迭代/尾递归）；线程栈大小怎么定（深度需求 × 单帧大小，权衡线程数）。

## 02 理解补充与边界校订

Linux 和 JVM 的默认线程栈大小受平台、启动参数和资源限制影响，原文的 8MB/1MB 只能当常见示例。Java 的数组对象通常在堆上，不应把 C 的栈上大数组例子直接套到 Java。Java 不承诺普遍的尾调用优化；对不可信深度输入，显式栈和深度上限更可控。
