# 02 HTTPS 使用 TLS/SSL 加密时，具体加密 HTTP 报文的哪些内容？

## 01 核心回答


**保护范围：**HTTPS 是 HTTP 运行在 TLS 之上。握手完成后，请求行、请求头、请求体，以及响应状态行、响应头、响应体都会作为 TLS 应用数据加密并校验完整性，窃听者不能直接读取 URL 路径、Cookie、Authorization 或业务内容。

**握手概要：**客户端发送支持的 TLS 版本、随机数和密码套件；服务端返回证书、随机数并证明私钥持有权；双方通过 ECDHE 等密钥交换协商会话密钥，随后用 AES-GCM 或 ChaCha20-Poly1305 等对称算法保护数据。证书主要解决“我连的是谁”，不直接用于加密全部业务报文。

**仍可见的信息：**TCP 头、IP 头和路由所需的网络元数据仍可能可见，包括通信双方 IP、端口、连接时间和流量大小；域名通常还可能通过 DNS、SNI 或证书信息暴露，具体取决于 DNS 加密和 TLS 版本。普通 ClientHello 的 SNI 可能可见，ECH 等机制还会改变暴露范围。TLS 不能隐藏所有流量特征。

**边界与误区：**HTTPS 只能保护客户端到 TLS 终止点之间的链路；在反向代理或网关处解密后，内部链路仍需重新启用 TLS 或采用可信网络控制。日志、地址栏和服务端处理仍可能泄露路径或参数，TLS 不负责这些终端风险。证书校验关闭、信任任意证书或混用 HTTP 会破坏安全性。
