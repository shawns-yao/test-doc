# 02 网络编程中的常用函数分别对应连接建立过程中的哪些步骤？

## 01 核心回答


**概念原理：**Socket 编程是传输层的用户态接口，函数调用驱动或观察 TCP 状态机，但并非一调用对应一报文。核心是**服务端四步（socket → bind → listen → accept）**和**客户端两步（socket → connect）**。

**服务端流程：**

1. `socket()` 创建套接字（协议族/类型）。

2. `bind()` 绑定本地 IP 和端口。

3. `listen()` 进入监听（内核维护半连接队列 + 全连接队列）。

4. `accept()` 从全连接队列取出已建立连接，返回新 fd（三次握手在内核完成）。

5. `recv/send` 读写数据。

6. **`close()` 关闭**（触发四次挥手）。

**客户端流程：**① `socket()` 创建；② `connect()` 发起三次握手（内核完成 SYN/SYN+ACK/ACK），成功后即可 `send/recv`；③ `close()` 关闭。其他常用：`setsockopt`（设置 SO_REUSEADDR/TCP_NODELAY）、`getsockname/getpeername`（本端/对端地址）、`select/poll/epoll`（多路复用监听多个 fd）。

**关键细节：**accept 返回的是**新 fd**（监听 fd 继续 accept 下一个）；listen 的 backlog 参数对应全连接队列长度（溢出会丢连接）；三次握手由内核完成，accept 只是取结果；Java NIO 的 `ServerSocketChannel.accept()` 对应同一语义。

**风险与取舍：**每连接一线程模型连接多时线程爆炸——用 epoll 多路复用（Netty/Redis 都是）；backlog 太小高并发丢连接；TIME_WAIT 复用靠 SO_REUSEADDR。

**项目落地：**Netty 封装了这些原语（BossGroup accept + WorkerGroup 读写）；排查连接问题用 `ss -tan` 对照 TCP 状态机；调优 backlog、SO_REUSEADDR、TCP_NODELAY。

**面试追问：**accept 在三次握手前还是后（后，队列里是已建立的连接）；backlog 满了会怎样（新连接被拒/丢）；epoll 和 select 的区别（就绪集合驱动与集合扫描、注册和通知方式不同）；close 和 shutdown 的区别（引用计数 vs 直接关闭方向）。

---

## 02 理解补充与边界校订

socket API 是对内核状态的操作，不与报文逐一对应。accept 通常只取出已完成握手的连接；非阻塞 connect 会先返回进行中，再由就绪事件与 SO_ERROR 判断结果。close 是否立刻发送 FIN 取决于剩余引用、缓冲和选项；SO_REUSEADDR 也不是无条件取消 TIME_WAIT 安全检查。
