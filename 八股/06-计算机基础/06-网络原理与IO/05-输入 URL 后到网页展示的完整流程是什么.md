# 05 输入 URL 后到网页展示的完整流程是什么？

## 01 核心回答


**概念原理：**输入 URL 到页面展示 = 一次完整的"解析 → 寻址 → 连接 → 传输 → 渲染"链路，几乎覆盖全部网络知识点，面试常从这条链路展开追问。

**完整流程（九步）：**① **URL 解析**：拆出协议、域名、端口、路径、参数；② **DNS 解析**：查浏览器缓存 → 系统缓存 →  hosts → 本地 DNS → 递归/迭代解析得到 IP（DNS over UDP/53）；③ **TCP 连接**：三次握手（HTTPS 加 TLS 握手）；④ **HTTP 请求**：组装请求行/头/体，可能先查缓存（强缓存/协商缓存）；⑤ **服务端处理**：网关/负载均衡 → 应用 → 数据库，返回响应；⑥ **响应接收**：状态码判断、解压（gzip）、按 Content-Type 处理；⑦ **解析 HTML**：构建 DOM 树（边解析边加载）；⑧ **加载子资源**：CSS/JS/图片（并发连接，HTTP/2 多路复用），CSSOM 构建，JS 执行（可能阻塞渲染）；⑨ **渲染**：DOM + CSSOM → 渲染树 → 布局 → 绘制 → 合成显示。

**关键细节：**DNS 有缓存层级（浏览器/系统/ISP/TLD）；连接复用（keep-alive/连接池）跳过第③步；强缓存命中直接本地返回（不发请求）；渲染阻塞：CSS 阻塞渲染、JS 阻塞解析（defer/async 缓解）；HTTPS 在第③步叠加 TLS 握手。

**风险与取舍：**每一环都可能失败——DNS 解析失败（缓存/换 DNS）、连接超时（重试/降级）、响应慢（超时/熔断）、渲染慢（懒加载/骨架屏）；优化按链路逐环排查（Chrome DevTools 的 Network/Performance 面板就是这条链路的可视化）。

**项目落地：**性能优化对应链路各环：CDN（就近 + 缓存）、DNS 预解析（dns-prefetch）、连接复用、静态资源缓存（强缓存 + 版本号）、JS 异步加载、图片懒加载、首屏 SSR/骨架屏；监控首屏时间、TTFB、FCP/LCP。

**面试追问：**DNS 解析是递归还是迭代（客户端到本地是递归，本地到根/权威是迭代）；强缓存和协商缓存的字段（Cache-Control/Expires vs ETag/Last-Modified）；为什么 JS 要放底部或 defer（阻塞 DOM 解析）；TTFB 慢说明什么（网络、排队或服务端耗时，需要进一步拆分）。

---

## 02 理解补充与边界校订

本题流程是讲解顺序，不是浏览器每次固定执行的全串行步骤。缓存/Service Worker 可能先满足请求，DNS 解析可能命中缓存或走 DoH/DoT，HTTP/3 不经 TCP；连接与资源获取还会并行。TTFB 包含网络往返、排队和服务端处理，不能单凭它认定数据库慢。
