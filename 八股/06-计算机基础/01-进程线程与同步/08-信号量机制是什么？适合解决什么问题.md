# 08 信号量机制是什么？适合解决什么问题？

## 01 核心回答


**概念原理：**信号量是带计数器的同步原语，两个原子操作：`P（wait）`——获取一个许可，无可用许可时等待（经典抽象可用负值表示等待者，POSIX API 不必暴露负计数）；`V（signal）`——计数器加一，唤醒等待者。二值信号量（0/1）可用于互斥，但所有者和释放规则不同于互斥锁；计数信号量控制"最多 N 个线程同时访问"。

**实现流程：**① 初始化信号量并设置初始计数 N；② 访问共享资源前执行 `P`，计数不足则挂起；③ 释放资源后执行 `V` 唤醒一个等待线程；④ 实现通过原子指令及相应同步机制保证许可更新原子性；单核关中断不能概括多核用户态实现。

**关键细节：**信号量适合控制"资源数量"而非单纯互斥——连接池限流（N=池大小）、生产者消费者（空/满两个信号量）、读者写者（读写信号量）；互斥锁与计数为 1 的信号量用途相近，但并非所有权语义等价，信号量一般没有所有者，不自动保证只有获取者才能释放，也不天然具备可重入或优先级继承语义；互斥锁有"持有者"概念，信号量没有。

**风险与取舍：**信号量不记得持有者，容易误释放（任意线程可 V）；P/V 顺序错误会导致死锁或计数漂移；并发上限 N 与每秒 QPS 限流不同：慢请求会占住许可，快速请求却可以反复获取许可；跨进程信号量（`semget`）有内核资源和权限管理成本；Java 中 `Semaphore` 可响应中断和超时更安全。

**项目落地：**连接池/线程池限流（信号量控制并发获取）；限流器（Semaphore 令牌）；生产者-消费者队列；数据库连接池可用许可与等待队列来理解，但实现还涉及连接验证、生命周期与调度；分布式场景可对应 Redis 计数或令牌桶。

**面试追问：**信号量和互斥锁的区别（计数 vs 持有者）；信号量能实现互斥吗（二值信号量可以但不推荐）；信号量如何实现限流（初始计数 = 最大并发）；P/V 为什么要原子（防止竞态条件）。
