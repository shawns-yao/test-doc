# 06 多进程和多线程有什么区别？I/O 密集型任务更适合使用进程、线程还是协程？

## 01 核心回答


**概念原理：**多进程：独立地址空间、强隔离、创建/切换/通信成本高，适合 CPU 密集并行和需要故障隔离的场景；多线程：共享地址空间、切换轻、通信方便，但需要同步且崩溃互相影响。协程/轻量线程由运行时调度；是否单线程、是否可跨核及阻塞行为取决于运行时，不能一概称为成本最低。

**I/O 密集型选型：**I/O 密集任务的特点是大部分时间在等待（网络、磁盘），CPU 占用低。常优先评估**协程/异步 I/O**——等待期不占线程，单线程可承载数万并发（Go goroutine、Java 虚拟线程、Python asyncio、Node.js）；但 asyncio 事件循环不能直接跑阻塞任务，goroutine 与虚拟线程可由运行时映射到多个系统线程，支持的阻塞 I/O 会挂起任务而非一直占用承载线程。其次是**多线程**（线程池 + 阻塞 I/O，线程数可参考核数与等待/计算时间比例，再受下游容量和实测约束）；纯多进程浪费内存且切换开销大，一般不作为首选。

**关键细节：**线程数不是越多越好——线程切换和栈内存（默认 1MB 级）有成本；I/O 密集场景线程池大小 ≈ CPU 核数 ×（1 + 等待时间/计算时间），但该公式只用于初值，还要用延迟、CPU、连接池上限和下游容量压测约束；轻量任务的阻塞行为取决于运行时：事件循环不可直接阻塞，虚拟线程支持的阻塞 I/O 可卸载承载线程。

**风险与取舍：**多进程内存占用高、IPC 复杂；多线程受线程数上限约束、共享状态需同步；协程/轻量线程需匹配运行时支持的 I/O 方式，且复杂 CPU 任务不会因协程加速。

**项目落地：**Web 服务：Netty/虚拟线程（I/O 密集）；计算任务：线程池/进程池并行分片；数据同步任务：生产者消费者 + 异步批量；Java 21+ 虚拟线程可直接用同步代码风格获得协程级并发密度。

**面试追问：**为什么 I/O 密集用协程（等待期不占线程资源）；协程和线程的切换成本差在哪（用户态 vs 内核态）；线程池大小怎么算（I/O 密集公式）；协程里能放阻塞调用吗（取决于运行时；asyncio 直接阻塞事件循环有风险，虚拟线程支持的阻塞操作可卸载承载线程）。
