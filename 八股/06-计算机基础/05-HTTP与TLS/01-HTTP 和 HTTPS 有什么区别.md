# 01 HTTP 和 HTTPS 有什么区别？

## 01 核心回答


**HTTP**

明文传输，数据可被窃听、篡改，无法验证服务器身份（可能被中间人冒充）。

**代价：**无加密开销，性能略快（少 TLS 握手）；仅适合无敏感数据的场景。

**HTTPS**

HTTP + TLS：加密（防窃听）、完整性校验（防篡改）、证书认证（防冒充）。

**代价：**多 1~2 次 RTT 握手（TLS 1.3 已优化为 1-RTT/0-RTT）；CPU 加解密开销（依算法、硬件与负载测量）；证书成本与运维。

**实现流程（HTTPS 核心）：**① 客户端验证服务器证书（证书链 → CA 信任）；② 密钥交换（ECDHE/RSA）协商对称会话密钥；③ 后续 HTTP 报文用对称加密（AES-GCM）传输；④ 每次传输带认证标签防篡改。

**关键细节：**HTTPS 加密的是 HTTP 内容（URL 路径和参数在 TLS 内），但域名（SNI）和 IP 可见；默认端口 80 vs 443；证书有效期和续期（Let's Encrypt 自动化）。

**风险与取舍：**全站 HTTPS 是标配（浏览器标记不安全）；混合内容（HTTPS 页面引 HTTP 资源）会被拦截；TLS 握手优化（会话复用、0-RTT）降低性能损失；自签证书仅限内网。

**项目落地：**Nginx/网关终结 TLS（证书集中管理）；HTTP 跳转 HTTPS（301 + HSTS）；内网服务间也可用 mTLS；证书监控告警防过期。

**面试追问：**HTTPS 握手具体几轮（TLS 1.2 2-RTT、1.3 1-RTT）；对称和非对称在 HTTPS 里各干什么（密钥交换 vs 数据加密）；中间人攻击怎么防（证书链验证）；HSTS 是什么（强制 HTTPS）。

## 02 理解补充与边界校订

TLS 成本取决于是否新建连接、算法、硬件和请求规模，原文「CPU 开销可忽略」不能用作容量规划。身份校验除了可信证书链还包括目标主机名等约束；持有受信证书不代表应用本身安全。私有 CA 可以用于组织内部信任，自签证书不是靠关闭校验来使用。
