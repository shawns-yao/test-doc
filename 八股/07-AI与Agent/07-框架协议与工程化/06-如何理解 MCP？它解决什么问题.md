# 06 如何理解 MCP？它解决什么问题？

## 01 核心回答

**理解：**MCP 是「模型与外部工具之间的**标准化协议层**」。解决的核心问题：不同模型、不同框架、不同工具之间**接入成本高、格式不统一、可移植性差**——用 MCP 后，工具对外暴露统一描述和调用方式，模型侧按同一协议发现和调用。

**现状不足：**① 工具描述质量参差不齐，schema 不规范时调用成功率下降；② 安全与权限治理在复杂场景下不够细；③ 跨语言、跨环境的调试和观测链路不统一。

**优化方向：**工具规范治理（版本化 + 契约测试）、权限与审计（最小权限 + 操作留痕）、观测体系（调用成功率、延迟、错误分类统一上报）——让 MCP 从「协议可用」升级到「生产可用」。

---

## 02 协议提供与不提供的能力

MCP 标准化客户端与服务端之间的能力协商及工具、资源、提示等交互，并非只有 tool calling。它不替模型做规划，也不替业务系统实现访问控制、事务和任务完成验收。

“统一协议”减少接入形状差异，不会自动解决工具描述差、语义不一致或供应链不可信。选型应评估客户端支持的协议版本、原语和扩展，不能假定任何两个宣称 MCP 的实现都支持完全相同功能。

口述：“它统一应用接入外部能力的接口，能力怎么使用、允许谁用、用了是否成功仍由宿主与服务端负责。”相关：[[八股/08-RAG与MCP/03-MCP协议与工具/03-为什么使用MCP而不是使用本地Tools或者Skills|MCP 与本地工具和 Skill]]。
