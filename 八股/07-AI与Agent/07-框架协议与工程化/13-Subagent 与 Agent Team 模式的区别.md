# 13 Subagent 与 Agent Team 模式的区别？

## 01 核心回答

Subagent：常用于隔离并委派明确子任务，生命周期依具体实现——主 Agent 拆任务并与各 Sub Agent 通信（方案设计、前端开发、后台开发、测试），是否回收或继续复用由具体运行时决定。

Agent Team：负责大型任务，适合上下游、多团队多角色并行协作——可按具体实现采用任务看板、共享信息和协调机制，不必都具备共享记忆或投票，像现实中多团队协作开发大项目。

---

## 02 术语依实现而异

Subagent 不天然意味着短命，也不必完成后立即销毁；它强调任务委派与上下文/权限边界。Agent Team 常强调多会话协作、共享任务或直接通信，但团队如何共享记忆、投票与调度由具体实现决定，不是所有产品的通用要求。

以 Claude Code 官方说明为例，subagent 通常向调用方汇报，agent teams 支持队友协作与任务协调；应注明所讨论产品与版本。选择时看是否需要长期协作、直接沟通与状态同步，而不单看任务规模。

口述：“两者是协作拓扑和运行方式的差别，先讲具体实现，再比较交接成本、隔离和协调收益。”

## 06 补充团队协作的可选治理

团队级路由、跨角色评审和投票可以作为多 Agent 系统的可选设计：路由决定任务由谁承担，评审引入不同检查角度，投票合并候选判断。它们会增加成本与通信，且共享模型和上下文会造成错误相关性，不能把多数票当作事实正确或权限合法的证明。
