# 07 MCP API 与普通大模型 API 的区别？

## 01 核心回答

模型 API 提供生成、推理、多模态或工具调用意图等能力；MCP 定义宿主应用连接外部工具、资源与提示服务的标准交互。协议不自行作决策或执行业务。三点区别：① 交互对象——普通 API 主要和模型交互，MCP 还要和工具生态交互；② 数据结构——普通 API 重点是 prompt 和 response，MCP 强调工具 schema、参数校验、执行结果和错误码；③ 工程目标——普通 API 追求回答质量，MCP 追求「可执行性 + 可治理性」。

关系：两者不是替代而是组合——模型负责决策，MCP 承载调用与结果消息，运行时及工具实现负责执行和回填；建议把工具调用封成统一执行器，避免业务代码里散落调用逻辑。

---

## 02 区别的准确说法

原说法“模型 API 只输入输出文本，MCP 输出可执行行为”过度简化。模型 API 可支持多模态、结构化输出和工具调用意图；MCP 规定客户端与服务端的能力发现和调用消息。真正业务执行来自工具实现与运行时，并非 MCP 协议自行执行。

一次任务可能先调模型 API 得到工具名和参数，再通过 MCP 调工具，最后把观察交回模型。也可以直接用本地函数或 REST 工具，不要求都经过 MCP。

口述：“模型 API 提供推理/生成能力，MCP 统一外部能力接入，执行器连接两者并负责鉴权与结果校验。”
