# 05 Agent 调用 MCP 的逻辑？

## 01 核心回答

**回答（四阶段）：**

① **工具发现**——通过 MCP 拿到可用工具清单和 schema，告诉模型「有哪些能力可选」；② **工具决策**——模型根据当前任务状态输出调用意图（工具名、参数、预期结果）；③ **执行与回填**——运行工具，拿到结果或错误码，标准化写回状态；④ **结果吸收**——模型读取工具结果，决定继续调用、改计划还是结束。

**工程三点：**参数校验（防模型传错字段）、防越权（白名单 + 权限上下文）、幂等（重试不产生重复副作用）——让 MCP 是「可控、可审计、可恢复」地调工具。

---

## 02 谁在真正调用 MCP

实际链路通常是 Host 中的 MCP Client 初始化并协商能力，获取 tools/list，运行时把工具描述提供给模型；模型产生调用意图后，经授权和参数校验，再由 Client 发 tools/call。模型本身不必直接连 MCP Server，也不应拿到服务端凭证。

工具返回要区分协议错误和工具业务执行错误，保留调用关联与结果证据；发现列表里的工具不等于该用户有权调用。HTTP 令牌不可作为通用令牌透传到其他下游服务。

追问“连接一建立就能调所有工具吗？”不能，初始化能力协商与每次业务鉴权是两层。详见[[八股/08-RAG与MCP/03-MCP协议与工具/02-MCP使用了哪些协议|MCP 协议与授权]]。
