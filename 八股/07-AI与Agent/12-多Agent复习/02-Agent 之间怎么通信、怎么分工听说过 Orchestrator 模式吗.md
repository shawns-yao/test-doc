# 02 Agent 之间怎么通信、怎么分工?听说过 Orchestrator 模式吗?

## 01 核心回答

一句话结论:通信方式 = 共享状态(黑板) / 消息传递(队列、事件) / 直接函数调用;一种常见编排方式是 Orchestrator-Worker(主管-工人)。

**通信:**① 共享黑板/数据库(各 Agent 读写同一任务状态,简单但需锁与一致);② 消息总线(事件驱动、解耦、可回溯,生产常用);③ 直接调用(同进程函数或 HTTP,简单直接但耦合)。

**分工模式:**集中编排(主管拆任务派发给工人并汇总) vs 对等协作(Agent 自由对话/辩论,灵活但难收敛)。

Orchestrator 模式:一个中央 Agent 负责任务分解、路由分配、结果汇总与冲突仲裁,Worker 只专注执行被分配的切片任务——可控、可观测、易加人工介入,便于集中控制，但有协调瓶颈与单点风险。

记忆要点:先答通信三选一,再答"主管-工人"集中编排便于统一控制,对比级联/对等模式容易失控。

---

## 02 通信协议要表达责任与状态

消息至少关联 task_id、parent_task_id、发送者、目标、输入版本、产物引用和成功/阻塞/失败状态。共享黑板要定义字段所有者与冲突合并；队列需要处理重复、乱序和消费确认，直接函数调用则要处理超时与取消。

Orchestrator 易集中控制，但也可能成为瓶颈或单点。协调者可以是确定性调度器，不必须是另一个 LLM；“最主流、最稳”需要具体任务证据，不能普遍下结论。

口述：“先定义任务与消息契约，再选集中或对等拓扑；通信通了不等于责任与状态一致。”
