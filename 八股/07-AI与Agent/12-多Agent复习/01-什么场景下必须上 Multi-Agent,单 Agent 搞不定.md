# 01 什么场景下必须上 Multi-Agent,单 Agent 搞不定?

## 01 核心回答

**一句话结论:**当任务需要**多种专业角色、不同上下文边界或角色间校验/协作**,单 Agent 因为"一个上下文塞不下/一个角色做不完/缺少制衡"才需要多体。

**典型场景:**① 需要多个专业视角(产品/研发/测试讨论一个方案);② 上下文隔离(各 Agent 只管自己领域,避免互相污染);③ 对抗与校验(一个生成一个审查);④ 并行任务(多个独立子任务同时推进)。

**反例(要会说不):**大多数单目标任务单 Agent + 工具就够了;Multi-Agent 会带来通信开销、状态不一致、错误传播、成本上升——"能用单体解决就不上多体"。

记忆要点:上多体的理由 = 角色分工 / 上下文隔离 / 互相校验 / 并行,不是"听起来高级"。

## 02 “必须”通常需要额外条件

多数技术任务不存在仅凭角色数就证明单 Agent 绝对做不到的结论。上下文分块、外部状态、工具和串行工作流也能处理复杂任务；多 Agent 常是并行、权限隔离或专业化的工程选择。

若法规或组织要求独立审批，增加一个同模型 Critic 不等于满足独立性。应先跑同预算单体基线，再衡量拆分的净收益；并行任务共享上下文太多时，交接成本可能抵消收益。
