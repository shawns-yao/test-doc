# 03 多个 Agent 互相"甩锅"进入死循环,怎么兜底?

## 01 核心回答

**一句话结论:**兜底三板斧 = **轮次/步数硬上限 + 仲裁者(或升级人工)+ 状态机约束消息流向**。

**硬性上限:**全局最大通信轮数、单个 Worker 最大尝试次数,超限强制终止并转人工或回退默认方案。

**引入仲裁者:**Orchestrator 或专门的 Judge Agent 在 Agent 间分歧时做裁决;裁决不了升级人工,不让争论无限持续。

**状态机约束:**定义"谁在什么状态能向谁发什么消息",限制互相推诿的发言空间,必要时只允许把问题抛回给主管而非互踢皮球。

**可观测:**所有消息带 trace_id 全链路记录,循环/重复模式可检测(如相邻消息相似度),方便定位是哪个 Agent 在甩锅。

记忆要点:上限防死循环、仲裁防甩锅、状态机防互踢、日志防黑盒。

## 02 上限止损之外，还要判断有没有进展

保存每个任务的验收条件、当前 owner 和已尝试动作；相同输入、相同失败原因反复派发且无新证据时触发无进展处理。消息相似度只是线索，不应把必要的重复核验误杀。

仲裁者按事实、规则和产物验收决策，不是让另一个模型凭语气选边。无法解决时返回阻塞状态、部分结果与待决问题；默认方案若会产生风险，不能在超时后自动执行。

口述：“预算硬上限防失控，任务所有权与验收防推诿，无法收敛时安全停机并交代恢复条件。”
