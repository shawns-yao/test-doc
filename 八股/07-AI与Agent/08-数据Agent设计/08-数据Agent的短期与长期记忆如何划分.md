# 08 数据 Agent 的短期与长期记忆如何划分

## 01 核心回答

原题来源：公司标签为字节飞书、得物、招银；由原综合题中的短期记忆 vs 长期记忆独立整理。

短期记忆服务当前会话，包括对话历史、槽位和进行中任务状态。可用内存或 Redis 做热状态，但需要断点恢复的任务仍应可靠持久化，并根据任务设保留期。长期记忆服务跨会话复用，包括经确认的用户偏好、历史结论和知识；可用结构化数据库、文件和语义索引组合，按用户与租户隔离。

划分原则是生命周期和复用价值。会话内临时状态短期化，跨会话有价值且有依据的信息沉淀为长期记忆，按相关性与权限取回；并非把全部历史写入向量库。

---

## 02 数据领域的记忆边界

一次 SQL 查询的候选表和临时结果属于任务状态；组织已确认的指标定义是知识，不应把模型上次生成的 SQL 自动当永久权威。结果缓存还受权限与数据版本限制，跨用户复用前必须验证可见范围。

追问“长期记忆怎么避免过期？”保存版本、有效时间和来源，源口径变化时更新相关摘要、索引和缓存；冲突不能只按写入时间覆盖。口述：“按用途分记忆，再按访问模式选存储。”

## 05 补充长期记忆的具体内容

长期记忆可包含经过确认的历史决策及其依据、失败案例和错误教训，而不只保存用户偏好。应附来源、适用范围、时间和失效条件；过去一次失败的经验不能升级成永久规则。检索时仍按用户、租户与权限过滤，涉及敏感内容时遵循最小保留原则。
