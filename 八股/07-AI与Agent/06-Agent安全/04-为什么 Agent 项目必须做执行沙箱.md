# 04 为什么 Agent 项目必须做执行沙箱？

## 01 核心回答

**原因：**Agent 一旦具备网页操作、代码执行和外部调用能力，风险从「答错」升级为「**误执行**」——沙箱把执行面与核心系统隔离，限制破坏范围，避免高权限误操作直达生产环境。没有沙箱，很多企业场景即使效果好也不敢上线。

适当沙箱与配套观测的价值：① 隔离——浏览器操作、代码执行、文件读写都在受控环境完成；② 可复现——任务过程可追踪、可回放，便于排障和合规审计；③ 可治理——权限边界、资源配额、网络策略和操作白名单。

**权限控制与审计：**最小权限白名单（可访问域名、可用工具、可写目录）+ CPU/内存/时长限额 + 网络出口策略；关键动作记录为结构化事件日志，绑定任务 ID 和操作者，支持按步骤回放。

**一句话：**Agent 的生产门槛不是会不会回答，而是能不能安全执行。

---

## 02 “必须”应对应执行风险

仅生成文本且没有执行能力的系统，未必需要代码运行沙箱；有不可信代码、浏览器或文件操作时，应设计适当隔离。沙箱也不自动提供可复现回放，仍需记录版本、输入和外部依赖。

重点检查进程/文件/网络/资源四个面：非特权运行、最小挂载、限制出口、短期凭证、CPU/内存/时长限额。即使代码在沙箱内，允许它调用生产 API 仍能造成真实影响，外部工具权限要另外限制。

追问“Docker 就够了吗？”取决于威胁模型；共享宿主内核的容器与虚拟机隔离能力不同，应按风险选择并维护安全补丁。
