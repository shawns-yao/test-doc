# 01 如何确保 Agent 安全、可控、可追责？

## 01 核心回答

**回答（分层安全）：**

① 模型层——对齐训练：RLHF/DPO 微调基础 LLM 遵循「有用、诚实、无害」原则，可降低部分模型风险，但不能替代系统安全边界；② 系统层——最小权限与工具白名单：只给 Agent 完成任务所必需的最少工具和权限；③ 执行层——沙箱隔离与资源限额：Agent 生成的代码/命令在受控沙箱（Docker/虚拟机）中执行，通过适当隔离限制影响范围，但仍需考虑容器逃逸、网络出口与外部 API 权限；④ 业务层——高风险动作人类确认（HITL）：执行「删除文件、发送邮件、金融交易」等敏感操作前，Agent 生成执行计划并暂停等待人类明确批准。

**再配合：**护栏规则、红队测试、注入攻击测试、全链路审计日志和告警阈值。

**核心原则：**「先可控再智能」——即使模型偶发漂移，也不能直接触达不可逆动作。

---

## 02 安全边界不能依靠模型自觉

模型对齐有帮助，但不是授权边界。即使模型完全遵循恶意文档，执行器仍应阻止访问未授权资源和传输秘密；因此服务端鉴权、资源隔离和审批应独立于模型判断。

容器也不是绝对隔离：宿主挂载、特权运行、容器逃逸和开放网络都可能扩大影响。根据风险选择隔离强度、只读挂载、出口限制和凭证范围。审批要绑定具体动作、目标和参数摘要，改变参数后不能沿用旧审批。

口述：“默认模型与外部内容可能出错，让最小权限、独立执行校验和审计把错误限制在可控范围。”

## 05 直接追问：安全与体验冲突时如何平衡

先按真实副作用、数据敏感性和可撤销性分级：已获授权的低风险读取可顺畅执行；需要审批的高风险动作先展示目标、关键参数和影响，批准后只执行对应版本。可以合并同一明确范围内的审批、提前澄清缺项，但不能用频繁打扰为理由绕过必要授权。

体验指标与安全指标分别看：记录误拦率、澄清/审批耗时和任务完成率，同时单独守住越权、泄露与不可逆误执行门槛。若误拦高，修正策略和交互设计；不要通过扩大默认权限来“优化成功率”。
