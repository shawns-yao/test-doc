# 02 什么是红队测试？

## 01 核心回答

红队测试用**攻击者视角**主动找 Agent 系统弱点，评估和提升安全性与鲁棒性——价值是发现常规测试覆盖不到的**高风险边界情况**，对具备执行能力的 Agent 尤其关键。常见手法：越权请求、提示注入、越狱诱导、工具滥用。

**闭环：**红队结果应回流到规则护栏、权限策略和训练数据，形成持续加固闭环。

---

## 02 红队测试需要明确范围

先列资产与威胁：敏感数据、执行权限、身份边界、外部内容入口。使用授权的隔离环境和合成数据，围绕可验证风险设计测试，例如知识库注入能否诱导越权工具调用；不把攻击真实第三方当作测试的一部分。

结果记录初始条件、输入、可观察动作、影响与复现步骤；修复后保留回归用例，并检查是否误伤正常任务。攻击成功率要配成功定义与严重级别，不能只统计模型是否说了违规话。

追问“和普通测试区别？”红队从对手目标主动寻找绕过路径，正常测试更多验证已定义功能，二者互补。

## 05 直接追问：红队如何发现偏见与差别对待

红队也要主动构造可能诱发刻板印象和差别对待的样本，检验相同业务条件下是否因无关身份信息改变回答、拒绝或工具选择。测试使用授权的合成情境；先固定任务事实、风险和所需权限，再对可比样本改变群体线索、姓名或表达方式，避免把事实条件本就不同的结果强行比较。

可区分两类问题：信息不足时，模型会不会用群体刻板印象补出结论；证据已经充分时，模型会不会仍让刻板印象覆盖明确事实。BBQ 就分别评估这两种情境，但其原始样本面向美国英语语境，不能直接当作所有语言和业务的公平性结论。[BBQ 原论文](https://aclanthology.org/2022.findings-acl.165/)

在当前业务中，按样本组记录正确率、错误拒答率、不当推断和实际工具行为，并保留样本量、不确定性与人工复核。发现差异后定位训练/评判规则、Prompt、检索材料或工具策略中的来源；修复后同时回归正常任务和偏见样本。差异是进一步调查的证据，不凭单例或单一均分宣布系统“没有偏见”。
