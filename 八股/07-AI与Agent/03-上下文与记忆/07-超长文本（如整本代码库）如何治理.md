# 07 超长文本（如整本代码库）如何治理？

## 01 核心回答

核心思路：不把整库塞进上下文，而是「**索引化 + 检索化 + 压缩化 + 增量化**」。除了分块，还可：

① 代码图索引：用 AST、依赖图、调用图做「代码图检索」，可补足纯文本难以表达的结构关系，准确性需按任务验证；② 混合检索——BM25（关键词）+ 向量（语义）+ 图（关系）联合召回；③ 重排与预算控制——召回后 rerank 只留最相关片段，按 token 预算动态调 TopK；④ 层级摘要——文件摘要、模块摘要、仓库摘要三级压缩，先读摘要再按需下钻；⑤ 增量更新——根据 git diff 更新变更文件，并失效受影响的依赖摘要、删除记录与索引，避免每次全量 embedding。

---

## 02 代码库索引的真实边界

AST、调用图对结构关系有帮助，但动态调用、反射、宏和生成代码可能让静态图不完整，不能宣称一定比文本检索准确。索引应记录 commit、文件路径和符号范围，回答或修改代码前回读当前版本。

增量更新不仅要重新嵌入变更文件，还需失效依赖摘要、符号引用、重命名/删除记录和缓存；“只看 git diff”不能自动保证跨文件派生数据一致。构建产物和 vendored 依赖按任务需求纳入，不能盲目全量索引。

口述：“用结构索引定位关系、用关键词定位标识符、用语义召回补表达差异，最终以当前源代码和测试核验。”
