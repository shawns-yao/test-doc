# 01 Agent 的短期记忆、长期记忆和状态怎么设计？

## 01 核心回答

**短期记忆：**承载当前任务上下文、中间结果和工具返回，保证任务连贯——生命周期短，通常跟会话/任务绑定，强调时效和低延迟，适合放缓存或状态存储（快速读写 + 过期清理）。

**长期记忆：**承载跨会话偏好、稳定事实和历史经验——生命周期长，强调可检索、可更新和一致性，更像知识资产，用向量库 + 结构化库组合（RAG 范式检索），配版本和来源管理，也可用 SQL 或知识图谱存结构化事实。

**State 设计原则：**① **最小化**——只放决策必需字段（任务目标、中间结果、证据、错误码、重试计数、下一步动作）；② **分层**——业务数据、过程数据、观测数据分开；③ 节点只读必要字段、只写自己负责字段，避免相互污染；④ **大对象外部化**——长文本/检索结果/工具返回存 DB/向量库，State 放引用 ID。

记忆写入策略（防噪声）：① 分级写入——先入候选区，依据可信来源、明确确认、可复用性与敏感程度决定是否转正，频率只是辅助信号；② 写前去重合并——语义相似度 + 关键字段去重，已有就更新；③ 生命周期——带来源/时间/版本/TTL，长期不命中自动降权或清理。

**长期记忆过期与纠错：**① TTL + 最后命中时间 + 重要度，超期归档/清理；② **冲突检测与版本化**——事实写入先检测冲突，不直接覆盖，保留旧版、标记新版、可回滚；③ **验证闭环**——关键记忆二次验证（多次出现、可信来源、用户确认），提供用户纠正入口。

**本质区别：**短期记忆服务「当前决策」，长期记忆服务「持续个性化与累积学习」。

## 02 记忆写入与遗忘的边界

“高频出现”不是所有记忆的必要条件：用户明确确认的一次偏好可能值得保存，多次出现的模型猜测仍可能是错的。按来源可信度、可复用性、敏感程度与用户授权判断，比单纯按次数转正稳妥。

短期不代表不持久化，长任务的会话状态仍需可靠落盘；长期记忆也不意味着永久保留。删除时应覆盖源记录、摘要、向量索引和缓存。冲突事实优先比较来源、有效时间和授权主体，不简单“最后写入获胜”。

## 05 直接追问：一条长期记忆怎样写入、召回并参与回答

以语义记忆为例，写入时先核验来源与保存权限，去重、处理冲突，再保存原文、所有者、版本和有效期；用选定 embedding 模型建立向量及原文 ID 的索引。明确的用户偏好也可以直接用结构化键值存储，不必全部向量化。

读取时，根据当前任务构造查询向量，在当前租户和权限范围内找候选；随后回读对应原文，核验版本、过期/删除状态及相关性。向量相似只负责找到可能有用的记忆，不证明内容正确，也不表示模型已经读到它。

使用时，把必要的原文片段或结构化事实连同来源注入本轮上下文，保留与用户当前指令的冲突检查；没有可靠命中就明确缺少历史依据。用户纠正后，源记录、索引、摘要和缓存都要同步失效旧版本。这样才形成“写入 → 召回 → 核验 → 使用 → 纠错”的闭环。
