# 06 Agent 评估与 LLM 评估的差异？

## 01 核心回答

基础 LLM 常从输入输出能力评估起步，也可评价多轮与工具能力；Agent 是多步交互系统，过程影响结果、状态持续变化，复杂度高很多。对 LLM 评估像「产品质量检测」，对 Agent 评估像「路况复杂的真实驾驶测试」——不仅要看是否到达终点，还要看过程中的效率、安全和应对突发。

**过程指标六项：**步骤数、总时延、Token/费用、工具调用成功率、重试率、异常恢复时长——很多系统「能做对但代价太高」线上不可用，过程指标直接指导优化方向。

鲁棒性与自主性：错误处理能力（工具报错能否纠正）、抗干扰能力（噪声/误导信息下成功率下降多少）；在满足授权与质量条件下衡量自主完成度，必要审批不应计为缺陷、行为可解释性、计划遵循程度。

---

## 02 评价对象的边界

基础模型也可以做多轮或工具能力评估，不能把所有 LLM 评测都限定单轮。Agent 评测的主要增量是环境状态、运行时策略和外部副作用的端到端验证。

人工介入少不一定更好：高风险任务在正确节点请求审批应计为合规，不应为了提高“自主性”鼓励越权。既检查终态，又检查是否绕过必要流程或产生多余副作用。

口述：“模型评测看能力，Agent 评测还看系统能否在预算与权限内完成任务，并正确应对失败。”

## 05 直接追问：计划偏离与行为可解释性怎么评价

先记录可观察的计划目标、关键里程碑和约束，再把实际工具动作、观察结果、状态变化与必要的简短决策理由对应起来。评审重点是每一步是否有当前证据支持、是否推进目标、是否遗漏必需步骤或违反约束，不把模型写出的长篇推理当作正确性的证明，也不要求获取隐藏思维链。

计划偏离要区分合理重规划与无依据偏离。例如原计划调用某工具，但权限不足后停止并请求审批，是遵守约束的调整；忽略权限失败仍宣称完成，才是需要计入失败的偏离。可在预先定义的计划检查点上标注“按计划完成、基于新证据调整、无依据偏离、遗漏”，分别统计无依据偏离比例、约束违反情况和重规划后的任务成功率，并保留人工复核依据。不能仅用“越少改计划”或“越少找人”判断 Agent 越好。
