# 01 如何设计 LLM/Agent 评估体系？

## 01 核心回答

**回答（离线 + 在线 + 人评三位一体）：**

**离线：**看能力覆盖——事实性、推理、安全、格式；**在线：**看业务指标——成功率、转化、时延、成本、稳定性；**人评：**校准自动评估偏差。

**Agent 还要看过程指标：**步数、工具成功率、重试率、中断率。上线后通过持续监控与坏例回流形成闭环，避免模型漂移无人感知。

**四维度评价 Agent：**① **效果**——任务完成率、答案正确率、引用准确率；② **效率**——首 token 时延、端到端时延、单任务 token 和外部 API 成本；③ **稳定性**——工具调用成功率、重试率、超时率、回环率；④ **安全性**——越权调用、敏感操作拦截率、审计完整性。评测采用「离线集 + 线上流量」双轨，最重要的是**坏例回流**——把失败 case 结构化记录并分类到 Prompt、检索、工具、编排四层。

---

## 02 先把成功率的分母说清楚

以任务为单位记录成功、部分成功、失败、阻塞与取消，明确超时和人工完成是否计入成功；只统计模型返回回答的请求会虚高。至少同时报告全自动成功率和包含人工接管的最终成功率。

固定测试版本、运行环境和预算，随机性较强的任务做多次重复并给置信区间。平均分之外按任务难度、租户和风险分桶；工具调用全成功仍可能因为目标理解错误而任务失败。

口述：“先定义真实业务验收，再分解质量、效率、稳定性、安全指标，并让失败能回到具体层定位。”
