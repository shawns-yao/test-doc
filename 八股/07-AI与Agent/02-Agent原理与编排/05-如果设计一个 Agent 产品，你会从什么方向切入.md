# 05 如果设计一个 Agent 产品，你会从什么方向切入？

## 01 核心回答

优先选「**高频、可量化、可回滚**」的业务场景（如企业知识问答 + 任务执行助手），设计思路是**先确定目标指标，再反推功能**。

**四步设计：**① 定义**北极星指标**——任务完成率、人工介入率、平均处理时长、单位任务成本；② **能力拆分**——意图识别、检索增强、工具执行、结果审校、异常兜底；③ **安全与治理**——最小权限、敏感操作二次确认、全链路审计；④ **上线策略**——小流量灰度、在线 AB、失败快速回滚。

**工程建议：**先做「**半自动**」而不是「全自动」——把高风险动作放人工审批，先把稳定性和信任建立起来，再逐步放开自治程度。

---

## 02 产品切入的可验证依据

先选一个人工流程作为基线，记录每单耗时、返工、错误后果和用户是否愿意交出执行权限。试点优先选能回读验收、权限明确、人工兜底成本可控的环节；高频本身不够，低价值任务可能抵不过模型费用。

用阶段目标约束产品：先生成建议，再准备可审阅草稿，最后在明确授权的范围内执行。把任务成功率与严重错误率分别设门槛，不能用平均满意度掩盖小概率高损失。

口述为可改编设计方案，不代表已经做过该产品。原文“经验”应理解为工程建议；面试若追问真实落地，需换成自己的可核实项目证据。
