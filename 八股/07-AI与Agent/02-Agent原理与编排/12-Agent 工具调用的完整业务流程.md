# 12 Agent 工具调用的完整业务流程？

## 01 核心回答

**回答（判定-执行-回填-收敛）：**

① **判定**——模型基于当前状态判定是否需要工具，产出结构化调用计划；② **执行**——执行层做**参数校验、权限校验和幂等校验**，通过后调用工具；③ **回填**——执行结果统一封装为成功/失败事件回填到状态；④ **收敛**——模型吸收结果决定下一步：继续调用、换工具、降级还是结束。

**关键细节：**每一步都要可观测——调用前后都打 trace，记录入参摘要、耗时、错误码和重试次数。

**线上稳定三件套：**超时与重试策略、熔断与降级策略、人工接管开关——外部依赖抖动时先止损再恢复，而不是把失败直接暴露给用户。

---

## 02 调用成功与任务成功分开验证

完整链路应有 task_id、tool_call_id 和必要的业务幂等键，工具返回与原调用关联。Schema 合法只说明形状正确，还需要检查业务范围、资源归属、参数语义和授权。HTTP 200 也不自动代表业务成功。

结果太长时保存可追溯引用，只把必要字段回填；来自外部的工具正文不能提升为系统指令。对部分成功或结果未知，要回读业务状态后再决定继续，不能偷偷降级却告诉用户全部完成。

口述：“模型提议、执行器把关、工具动作、结果核验、状态推进，这五件事分开，才能定位错在哪里。”
