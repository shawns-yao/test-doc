# 03 AI Agent 的基本实现路径是什么？

## 01 核心回答

**回答（控制面 + 数据面）：**

**控制面：**状态机/图编排——定义节点、路由条件、重试策略和结束条件；**数据面**是每个节点具体怎么跑。**大模型 API** 负责推理与决策，**RAG** 提供外部知识，**MCP** 标准化工具调用。

典型回路：模型判断当前任务是否需要知识检索或调用工具 → 按任务需要选择检索或工具调用，接入可用 MCP、本地函数或其他 API（不存在固定先后）→ 工具结果回填状态 → 再交给模型继续推理 → 直到满足结束条件。

**关键细节：**① **节点输入输出契约清晰**——每个节点只读必要状态、只写自己产物，避免上下文污染；② 线上加**步数上限、超时、幂等键和降级策略**；③ 打**全链路 trace**，区分是 Prompt 问题、检索问题还是工具问题。

---

## 02 从最小闭环落地

先选一个有验收标准的任务，定义状态字段、允许动作及终态，再实现“模型建议动作 → 执行器校验 → 工具执行 → 状态核验”。RAG 与 MCP 都是可选组件，不是所有 Agent 必经步骤；检索和业务工具也没有固定的先后顺序。

可改编例子：读取一个已授权工单并总结，可能只需直接读工具；需要历史解决方案时才查知识库。记录 task_id、call_id、结果版本和副作用状态，才能区分模型错选工具、参数错和下游失败。

追问“模型能直接执行吗？”模型通常只产生调用意图，真正的执行和授权由运行时负责。关联：[[八股/07-AI与Agent/02-Agent原理与编排/12-Agent 工具调用的完整业务流程|工具完整链路]]。
