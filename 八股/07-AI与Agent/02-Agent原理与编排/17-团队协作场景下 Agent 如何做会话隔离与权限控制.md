# 17 团队协作场景下 Agent 如何做会话隔离与权限控制？

## 01 核心回答

**会话隔离：**上下文主键设计为「**workspace/channel/thread/user**」——线程内共享任务状态，线程间严格隔离；权限采用**角色映射到动作级策略**（谁可触发外部调用、谁可审批敏感动作）。

**群聊上下文污染治理：**① 限制上下文来源——默认只读当前线程和被 @ 消息；② 消息分级——低价值闲聊不进入任务记忆；③ 关键事实落**结构化状态**而非自然语言堆叠；④ 冲突时以最近确认状态为准，保留证据引用。

**为什么审计要求更高：**协作平台涉及多人协同和组织责任，任何自动动作都可能影响业务结果与合规边界——必须回答清楚「谁发起、谁审批、执行了什么、影响了什么」，审计链完整才能可追责、可证明。

---

## 02 隔离键与授权来源

会话主键的组成取决于共享规则，不一定同时含 workspace/channel/thread/user。例如线程由多人协作时，按 user 再切开可能失去共享上下文；关键是由可信身份服务决定租户与成员资格，并在每次读写和工具执行时检查资源权限。

“最近确认状态”只适用于有权更新该事项的人，群聊中陌生人的最新消息不能覆盖任务所有者的授权。还要隔离附件、向量索引、结果缓存、日志与长期记忆，否则正文隔离仍可能侧漏。

追问“日志能否全量存？”要脱敏、分级访问和设置保留期；审计保存行动证据，不需要索取或存储隐藏思维链。
