# 15 多步骤研究型 Agent 的核心链路怎么设计？

## 01 核心回答

设计成「**规划 → 并行采集 → 证据归并 → 结论校验 → 交付输出**」五段：先把问题拆成子任务，再并行拉取多源信息，做去重和可信度排序，最后生成可追溯结论。每段都有**输入输出契约和失败恢复点**，避免长链路一步错全盘错。

**与普通 RAG 的差异：**基础固定式 RAG 常用单次检索增强（RAG 本身也可多轮）；Wide Research 是**任务型流程系统**——多轮规划、并行采集、阶段归纳、动态重规划。前者强调召回与生成质量，后者强调**任务成功率、过程可解释性、执行可靠性与恢复能力**。

**为什么复杂任务依赖编排而非单次模型能力：**复杂任务失败通常不在「某一句答错」，而在流程失控——顺序不对、依赖缺失、证据冲突没处理。编排能力决定任务能否按阶段收敛、能否回滚重试、能否追踪责任。

---

## 02 保持证据与结论之间的对应

RAG 不限于单跳，本题比较的是固定问答流水线与任务型研究流程。研究过程应记录来源、发布时间、引用范围和冲突证据；多个网页重复转述同一来源不能当多份独立佐证。关键结论需能从产物定位到支撑证据。

并行任务按子问题分工，汇总阶段先去重与处理矛盾，再形成结论；未能核验的内容标注不确定。停止依据是覆盖了任务要求并完成事实检查，或到达预算并报告缺口，而不是“写够篇幅”。
