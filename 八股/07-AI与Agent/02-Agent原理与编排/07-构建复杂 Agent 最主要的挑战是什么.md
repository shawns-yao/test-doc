# 07 构建复杂 Agent 最主要的挑战是什么？

## 01 核心回答

难点不止模型能力，而是**端到端系统可靠性**，通常集中在四类：① **规划鲁棒性不足**——卡在重复的思考-行动循环、对工具失败没有备用方案、过早认为任务完成；② **评估难复现**——开放式任务没有唯一正确答案，指标难定义、环境不可复现、人工评估成本高；③ **成本时延高**——复杂任务数十上百次 LLM 调用，API 费用和延迟难以规模化；④ **安全可控不足**——权限管理困难、提示词注入、行为不可预测。

**面试表述：**「先做可控再做聪明」——加步数上限、权限边界、故障回退和全链路日志，优先保底稳定性。

---

## 02 把挑战变成可执行检查项

复杂系统尤其要处理“结果未知”：请求超时不等于业务未执行。状态中保留调用标识和核验入口，再决定查询结果、重试或接管。防循环不能只限步数，还要检查连续相同动作是否获得新证据、目标是否真正推进。

评估难时，把开放任务拆成可检查约束与最终人工评分，保存环境快照和依赖版本。成本治理同时限制调用并发、单步最大输出、全局预算和运行时限。

追问“先优化哪项？”先按业务严重性和失败占比排序，从高损失、可复现故障改起，不预设模型能力一定是瓶颈。
