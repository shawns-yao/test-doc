# 13 节点失败或意图识别错误如何处理？

## 01 核心回答

**节点失败：**每个节点都有超时 + 最大次数，超过就走**失败分支/降级路径/人工介入节点**；做**错误分级**——可重试（超时、429、临时网络）和不可重试（参数错、权限错、业务校验失败）；用 **checkpoint + 幂等键** 配合持久化去重与结果核验，降低断点恢复时重复副作用的风险（不重复下单/发消息）。

**意图识别错误：**意图识别后先走一层**校验层/风险控制层**——高风险意图必须二次确认；执行过程中做**一致性校验**，若检索/工具返回与意图不一致，触发路由和反思。

---

## 02 错误分类还要看副作用

超时、429、网络中断只能说明调用层失败，不保证操作没有生效。读取通常可有限重试；写入先根据幂等键或业务 ID 查结果，不能机械重发。checkpoint 与幂等键也需要后端确实执行去重，单纯生成一个字符串并无保证。

意图识别置信度必须用标注数据校准。高风险的相似意图，例如“查询记录”和“删除记录”，即使模型很自信，也必须检查用户授权和真实参数；不明确就澄清。补充[[八股/07-AI与Agent/02-Agent原理与编排/19-当 Agent 遇到无法解决的场景，应该怎么处理|无法完成时的分级退路]]。
