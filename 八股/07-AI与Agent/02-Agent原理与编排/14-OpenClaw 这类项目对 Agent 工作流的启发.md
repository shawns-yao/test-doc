# 14 OpenClaw 这类项目对 Agent 工作流的启发？

## 01 核心回答

① **Gateway 统一网关入口**——跨渠道消息先标准化再路由，避免每个渠道各写一套逻辑；② **会话隔离不串台**——sessionKey、dmScope、每会话串行执行和队列并发上限，核心是防串台、防并发写冲突；③ **三层记忆系统**——「文件化 + 可检索」：MEMORY.md 做长期记忆、memory/*.md 做日记忆、配 memory_search，可追溯可审计；④ **可托管运行**——心跳机制保证主动思考工作，定时任务块机制确保周期任务统一调度。

---

## 02 从具体项目提炼可迁移设计

应把项目公开实现与自己的架构建议分开。文件记忆、索引搜索和调度机制是可借鉴的实现方式，不能概括成所有 Agent 都要遵守的“三层记忆标准”。定时唤醒仅触发检查，不保证每次都有有价值结论。

若采用文件记忆，需要明确谁能写、如何避免并发覆盖、用户纠正如何失效旧索引；会话隔离需在权限与存储层共同落实。可改编口述：“借鉴统一入口和可审计记忆，但会为当前业务重新定义身份、状态、调度与授权边界。”

具体字段和路径以所用 OpenClaw 版本文档为准，不把项目内部名称当作通用协议。
