# 16 Browser Agent 的关键失败点有哪些？如何做重试和回滚？

## 01 核心回答

**高频失败点：**DOM 变化、元素不可见、会话过期、跳转异常和限流。

**处理做法：**「**动作前置校验 + 失败分类重试**」——可重试错误做指数退避，不可重试立即降级；关键写操作加幂等键，失败后按**核验页面与业务状态（不代表外部动作可回滚）**，不从头盲跑。

**动态页面/登录态/反爬：**动态页面用**显式等待和稳定锚点**，不依赖脆弱选择器；登录态通过安全会话托管和失效检测自动刷新；遇到反爬或验证码时**切人工节点**，不强行绕过。

**为什么可观测性特别重要：**浏览器任务是长链路状态机，失败常发生在中间节点——没有步骤级日志、截图、DOM 快照和耗时指标，无法判断是页面变化、网络抖动还是策略错误。

---

## 02 回滚边界勘误

浏览器 checkpoint 或截图只能恢复可观察进度，不能撤销已经发出的邮件、付款或提交。页面未显示成功也不代表后端未执行。写操作失败后应先查订单/记录状态，确认未生效且允许重试再继续；取消或撤销是独立业务动作。

并非所有网站支持幂等键，不能假设浏览器自动化能加一个键解决重复提交。可采用动作前保存目标摘要、动作后回读结果、唯一业务编号和 unknown 状态处理。登录刷新同样不能绕过重新认证要求。

口述：“重试前先确认页面状态和业务状态；恢复运行不等于回滚业务。”参见[[八股/07-AI与Agent/02-Agent原理与编排/21-Agent的checkpoint是什么|检查点边界]]。
