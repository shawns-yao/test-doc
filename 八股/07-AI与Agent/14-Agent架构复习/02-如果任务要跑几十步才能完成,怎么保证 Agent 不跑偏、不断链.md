# 02 如果任务要跑几十步才能完成,怎么保证 Agent 不跑偏、不断链?

## 01 核心回答

**一句话结论:**用**目标锚定 + 步数上限 + 检查点 + 状态持久化**四条腿走路,让长任务"想得清、走不偏、断得了链也接得上"。

**① 目标锚定:**把总目标拆成结构化任务清单(Plan),每步开始前让模型对照目标判断"这一步是否服务于主线",偏离就拉回。

**② 硬上限:**最大步数/最大工具调用次数,超限熔断转人工,从根上杜绝无限循环。

**③ 检查点与自检:**每 N 步生成阶段性小结,校验中间结果(输出格式/数值合理性/与目标一致性);关键决策点人工确认或规则校验(风险操作审批)。

**④ 状态持久化与断点续跑:**任务状态、已执行步骤、中间产物写入存储(对应 LangGraph checkpoint 思想),进程崩溃/超时后能从最近检查点恢复,而不是从头重跑;失败步骤有重试与降级策略。

**加分讲法:**补一个"上下文瘦身"——长任务中定期对历史做摘要压缩,防止上下文塞满后模型丢失早期约束;再举个自己处理过的长任务例子(展开见"题目 3")。

记忆要点:清单防跑偏、上限防死循环、检查点防断链、持久化防白干。

---

## 02 让“不断链”具有明确语义

保存目标版本、已验证产物、待执行动作与业务副作用状态，恢复时检查外部状态是否仍有效。摘要不是 checkpoint，checkpoint 也不保证外部写入只发生一次；重放前核验业务 ID。

长任务除了最大步数，还要有时间、费用和无进展预算；计划根据新证据调整是正常纠错，不能用“严格遵循旧计划”压制合理变更。目标或授权变化后，重新检查受影响步骤。

口述：“用可验证里程碑推进任务，用持久状态接续执行，用幂等和结果回查控制恢复风险。”例子仅选自己实际做过的，详见[[八股/07-AI与Agent/02-Agent原理与编排/21-Agent的checkpoint是什么|checkpoint]]。
