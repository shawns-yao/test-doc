# 01 设计一个智能客服/代码助手/数据分析 Agent,讲讲你的整体架构

## 01 核心回答

**一句话结论:**按**接入层 → Agent 编排层 → 能力层 → 模型层 → 数据与可观测底座**分层设计,并明确每一层的职责与关键决策。

**接入层:**多渠道/协议接入,做会话管理与用户身份(客服:IM/工单;代码助手:IDE 插件)。

**Agent 编排层:**意图识别与任务规划,按场景选模式(客服=意图路由 + 多轮澄清;代码助手=代码理解 + 修改计划;数据分析=SQL/图表工具编排),并接人工升级通道。

**能力层(工具/RAG):**通过 Function Calling/MCP 暴露工具集(客服:订单/物流/知识库检索;代码:文件/执行/测试;数据:库表查询/代码执行沙箱)。

**模型层:**模型分级路由、Prompt 管理、结构化输出约束、缓存。

**底座:**向量库(知识检索)、任务状态存储、鉴权与安全(沙箱/权限/审计)、Trace 日志与评测监控、灰度与降级。

**加分讲法:**用具体例子串一遍(用户问"我的订单为什么没发货"→ 意图识别 → 查订单工具 → 检索物流知识 → 生成回答 → 解决不了转人工),并主动讲两个关键取舍:什么时候 RAG 什么时候直连业务 API、安全边界怎么做。

记忆要点:分层讲结构 + 场景串流程 + 主动谈取舍;系统设计题不怕简单,怕没有分层和闭环。

## 02 用具体任务解释架构

可改编客服例子：用户询问订单状态，先验证身份与订单归属，再查权威订单 API；只有解释规则时检索知识库。订单实时状态不应从旧向量片段推断。查不到时区分无权限、数据不存在、依赖失败与信息不足，给不同退路。

代码助手的关键额外边界是文件范围、执行沙箱与测试；数据分析 Agent 的关键是口径、只读权限、查询预算和结果计算。共用架构不代表三者拥有同一组工具和风险级别。

口述：“先串通一个带授权和验收的真实流程，再解释分层与扩展，而不只画组件盒子。”相关：[[八股/07-AI与Agent/09-Agent项目实践/22-从 0 到 1 搭 AI 后端服务怎么拆|AI 后端服务]]。
