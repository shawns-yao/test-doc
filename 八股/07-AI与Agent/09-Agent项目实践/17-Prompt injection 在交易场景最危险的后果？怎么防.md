# 17 Prompt injection 在交易场景最危险的后果？怎么防？

## 01 核心回答

**最危险后果：**让 Agent「绕过风控去执行高风险真实下单」，造成快速亏损甚至爆仓，而且是**自动连续发生**。

**五层防护：**① **执行权隔离**——LLM 只产出「建议」，最终下单必须经过确定性风控引擎；② **上下文隔离**——外部内容（新闻、社媒、RAG）一律标记 untrusted，永不当系统指令；③ **工具白名单 + 参数校验**——只允许固定动作，杠杆、数量、币对、方向硬校验；④ **高危双确认**——大额/高杠杆/新策略人工确认或双签；⑤ **运行时止损**——异常行为检测（频次突增、风险暴露异常）+ 一键熔断 read-only。

---

## 02 从攻击输入到危险动作的链路

外部新闻、网页、文档或工具结果可能夹带“改目标、导出密钥、调用工具”的指令。风险不只是模型说错，而是恶意内容影响后续动作或把账户数据传给攻击者。对不可信内容加标签有帮助，但模型仍可能受影响，因此标签不能代替执行限制。

---

## 03 防护如何验证

将读取资料的模型与资金执行隔离，执行器只接受结构化且已授权的有限操作；每次校验账户、参数、额度和有效状态。禁止外部内容修改系统规则或扩大工具权限，限制工具输出长度与可访问网络，避免“只读工具”把秘密带到外部 URL。

红队在隔离模拟环境放入恶意资料，检查系统是否尝试越权、是否被实际阻断，以及正常分析是否仍能完成。看真实动作与数据流，不把模型口头拒绝当唯一成功标准。

口述：“提示注入无法只靠 Prompt 根治，应让攻击即使影响模型也无法跨越执行和数据出口边界。”
