# 38 视频生成任务平台怎样组织素材镜头与计费

## 01 先复用可靠任务平台，再补视频领域模型

这是参考系统设计，不表示个人实现过整个平台。通用排队、取消、重试和回调沿用异步任务专题；视频业务另外建项目、素材、镜头、生成尝试、成片版本和额度账本。一个项目可有多个镜头，一个镜头可生成多个候选；发布的成片必须绑定具体版本，不能被后台重试静默替换。

## 02 素材与镜头的依赖关系

上传时验证类型、尺寸、时长、权限和内容要求；原始素材与派生产物存对象存储，数据库保存标识、版本、校验值与授权来源。镜头计划记录提示词、参考图、时长、模型版本和前后镜头约束，便于复现和局部返工。

镜头生成可并行，但合成依赖所有必需镜头及音轨就绪。修改一个镜头应使其后续合成版本失效，尽量复用未改变的产物；复用仍须核验素材权限、模型/参数版本和内容审核状态。

## 03 额度预留与结算

提交时按预估上限预留额度，实际执行产生独立用量事件，完成后按约定规则结算差额。任务 ID、尝试 ID、用量事件 ID 分开：用户一次任务可有多次内部尝试，供应商重复回调不能重复扣用户额度。

取消不代表所有成本归零：已经开始的推理、存储或供应商调用可能收费。预留、实耗、释放和异常对账都记录在可审计账本中，不能只靠 Redis 扣一个数。收费规则需要产品定义，失败任务是否收费不能由工程师临时推断。

## 04 故障与验收

模拟素材读取失败、单镜头超时、合成失败、重复回调、取消与完成竞争、结算服务短暂失联。核验任务不会双终态、成片版本可追溯、重复事件不重复计费、预留额度能最终释放或转人工处理。进度与质量评测分别用关联专题展开。
