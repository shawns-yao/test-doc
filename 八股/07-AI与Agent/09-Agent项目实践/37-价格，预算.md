# 37 价格，预算

## 01 核心回答

Agent 预算要同时管单任务、单用户/租户和周期总额，计入模型、检索、工具、计算存储与人工接管成本。价格随供应商和模型版本变化，本页不给未经核验的当前报价；实际方案应引用当时官方计费页并注明币种和日期。

---

## 02 如何估算

对第 i 次模型调用，分别统计未缓存输入、缓存输入和输出 token，以对应单价计算，再对所有调用求和；如果用量已是任务总 token，就不能再乘调用次数。还需加入 embedding、reranker、搜索/API、沙箱运行、网络与存储等费用。计费 token 的供应商口径可能包含额外类别，应以 usage 与账单为准。

先选代表任务做采样，记录调用次数分布、上下文增长、重试与长尾运行。估算每日任务量乘平均成本只是起点，还要看 p95 单任务成本、突发并发和失败任务占比。内部更有用的指标是“每个经验证成功任务的总成本”，因为最便宜模型如果大量失败或返工未必最省。

---

## 03 执行时控制

开始前预留预算，每步更新已用与剩余，接近上限时缩减非必要搜索或请求用户决定；不能为省钱悄悄降低安全标准。并发子任务共享一个总预算，避免各自都以为额度充足。设置最大调用数、单次输出、工具费用和总运行时限，处理取消后的在途费用。

缓存与模型路由要经过质量评测，语义缓存同时检查权限和版本。付费工具或新供应商涉及新的收费/数据边界时，应按照实际授权流程确认。

---

## 04 追问与口述

“为什么只算 token 不够？”检索、外部工具和人工返工可能占很大比例。“预算耗尽怎么办？”交付已确认部分、说明剩余缺口和继续所需预算，不能假完成。

口述：“先测真实用量，再按质量约束优化单位成功成本；每个任务有全局预算和可解释停止条件。”
