# 11 交易型 Agent 产品的后端架构怎么拆？

## 01 核心回答

**主链路：**`Query 理解 → 任务路由 → 检索/RAG → 工具调用 → 风控校验 → 执行 → 结果解释 → 观测与评测`。

**面试官想听的：**不是「我会用 LangChain/Dify」，而是**怎么把分析和执行分层、怎么设护栏、怎么追踪一次用户请求到真实下单的全链路**。

**Agent vs 固定 workflow：**固定流程适合路径稳定、规则明确的任务，高风险执行步骤尤其需要确定性约束；Agent/planning 适合不确定查询、多轮推理和多工具决策；交易场景里真正高风险的动作**不能完全交给自由规划**，必须加硬规则/风控闸门。

---

## 02 分离分析面与执行面

这是系统设计题，不是投资建议或真实交易授权。分析面可以读取行情、账户允许读取的信息和资料，生成可解释建议；执行面由独立网关验证用户身份、账户、审批范围、市场规则与风险限额。模型不能自行改额度、替换账户或绕过网关。

订单采用持久状态机，例如 proposed、approved、submitted、unknown、acknowledged、partially_filled、filled、cancelled、rejected。具体终态与转换以交易所契约为准；请求返回成功只代表某个阶段，不能等同成交。每次转换由回执或对账证据驱动。

---

## 03 故障与验收

网络超时先记 unknown 并按客户订单标识查状态，避免重复下单；消息重复或乱序需去重和版本处理。行情过期、仓位不同步或风控服务不可用时，停止新增风险动作，保留查询与人工处置通道。

可改编口述：“Agent 帮助理解和分析，交易网关控制动作，账务与订单状态证明结果；模拟环境验收正确性，不承诺有风控就不会亏损。”
