# 19 交易平台为什么要做 Agent Hub/MCP？

## 01 核心回答

**回答（解决「各自调 API」三大问题）：**

① 开发效率——直接调 API 每家都要重复做鉴权、重试、限流、参数校验和工具封装；Hub + MCP 用统一协议和工具描述，有望减少重复适配成本，具体交付收益需实际测量；② 风险治理——交易场景高风险，平台必须把权限分级、额度限制、风控前置校验、审计日志、熔断降级做成系统能力，避免各家用自研导致安全合规口径碎片化；③ 生态与商业化——Hub 能做插件发现、版本管理、灰度发布、计量计费和质量评分，形成网络效应。

**本质：**底层保留原生 API 给高阶团队，上层提供 Agent Hub/MCP 给规模化生态——既保灵活性又保平台可控性。

---

## 02 标准接口与平台治理的分工

Hub 可提供目录、版本、授权入口、计量和审计，MCP 统一能力发现与调用协议。但协议本身不实现额度检查、订单幂等或合规审查，这些仍需平台的执行网关与业务服务负责。“接入从周级到天级”只有真实测量才可讲，不能当通用收益。

---

## 03 设计风险与验证

中心化入口减少重复接入，同时形成集中故障域与高价值攻击面。应隔离租户、按工具和账户限流、固定版本、验证工具描述与供应链，并给原生 API 与 MCP 同等硬权限控制，避免其中一条路径绕过风控。

验证可从只读行情与账户查询开始，对比接入工时、调用失败率、运维成本及权限负例；逐步开放已授权业务能力。第三方 Agent 的能力声明或插件评分不能替代真实身份与操作权限。

口述：“平台把接入、治理和可追责做成公共能力，MCP 降低适配成本，但安全保证来自独立执行控制。”
