# 22 从 0 到 1 搭 AI 后端服务怎么拆？

## 01 核心回答

**回答（七层）：**

① **接入层**——API Gateway + 鉴权（JWT）+ 限流 + 灰度路由，长响应用 SSE/WebSocket、短请求走 HTTP；② **编排层（Agent Runtime）**——状态机/图：意图识别 → 检索/工具 → 生成 → 审核 → 返回，每节点超时/重试/最大步数/熔断/降级；③ **模型层**——模型路由（大/小模型切换）；④ **能力层**——Prompt 模板中心、Tool 调用、RAG 检索（向量 + 关键词混检）；⑤ **数据层**——MySQL（用户/订单/任务状态）、Redis（会话缓存）、对象存储（文件/产物）、向量库（知识检索），关键写操作幂等键；⑥ **安全与治理层**——内容安全、提示词注入防护、工具白名单、最小权限、审计日志；⑦ **可观测与运维层**——Metrics + Logs + Traces，重点盯成功率、时延、成本、幻觉率、工具失败率，可灰度、可监控、可回滚。

---

## 02 分层之外还要有运行契约

请求入口生成 task_id 并完成身份校验；短任务直接响应，长任务先返回受理状态，再由持久任务系统处理并提供进度查询或流式通知。断线只影响展示，不应默认取消任务；取消需要明确操作及可核查结果。

任务状态至少区分排队、运行、等待授权、成功、失败和取消。模型、工具、检索分别设置超时、重试与并发配额，写入前持久化幂等意图，结果未知走核验流程。大文件和产物放对象存储，状态只保留引用和版本。

---

## 03 失败边界与口述

JWT 只是身份凭据形式，不替代服务端资源授权；向量库也不是每个 AI 服务都必须有。先按单一业务实现可验收最小闭环，再按瓶颈扩展组件，避免为了分层堆七种中间件。

口述：“先把任务生命周期、权限和失败恢复做完整，组件可替换、关键结果可回读，架构复杂度随真实需求增长。”
