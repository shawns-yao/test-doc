# 05 Sub-agent 的收益到底是什么？

## 01 核心回答

**回答（除了并行还有五点）：**

① 上下文隔离——每个子代理只看自己需要的信息，减少主上下文污染、幻觉和 prompt 变长问题；② 职责专业化——按角色拆分（检索、执行、审校、风控），每个子代理用不同提示词/工具/模型更稳；③ 故障隔离——可通过隔离减少局部失败影响，局部重试仍需核验副作用，不能保证自动回滚；④ 权限最小化——给不同子代理不同权限（只读/可写/高危工具禁用），安全边界更清晰；⑤ 成本与性能分层——简单任务给小模型、关键步骤给强模型，「该省省、该强强」。

---

## 02 收益成立的条件

Sub-agent 的核心价值是分解任务与隔离上下文，不是“换个角色就更聪明”。独立检索多个来源可并行降低等待；不同权限的工作拆开能缩小风险；但共享同一模型或同一资料时，错误往往相关，多个答案一致不能自动提高可信度。

---

## 03 怎样设计交接

每个子任务写明目标、输入引用、权限、预算、产物格式与验收标准。大文本存外部产物，只汇报关键结论、来源和未解决项；主 Agent 核验后合并到权威状态，避免所有子代理同时写全局摘要。局部重试不代表外部副作用可回滚。

评价时比较同预算单 Agent 的端到端成功率、通信 token、结果冲突率和总时延。若任务必须串行共享大量细节，拆分可能更慢且更容易漏条件。
