# 23 AI 写论文/报告的多步工作流怎么拆？

## 01 核心回答

**回答（6 步 workflow，不是放任 Agent 自由发挥）：**

① **意图识别**——先定输出格式、篇幅、语气、引用要求；② **规划**——规划目标输出结构、拆子任务、多 Agent 分工各负责一节；③ **资料召回**——文献库/知识库/内部资料拿候选（向量 + 关键词 + rerank）；④ **证据筛选**——去重、时间过滤、来源权重、可信度评分；⑤ **内容生成**——按目标结构输出正文，每段绑定证据；⑥ **后置校验**——检查引用真实、结论不越界、格式符合，低置信度标出给用户确认——必须多步 + 反思 + Human review。

LangGraph 价值：状态机帮助明确流转与恢复；多 Agent 是否有益需对照评测；checkpointer 保存运行状态，外部副作用与完整审计仍需单独治理。

---

## 02 每一步要输出可检查的产物

规划输出提纲与证据缺口；检索输出候选来源和检索条件；筛选输出纳入理由与质量限制；分析输出断言—证据映射；生成输出草稿；校验输出具体错误、修正记录和未解决项。这样可以从最早出错的阶段重做，而非整篇不断自我改写。

按章节多 Agent 写作会出现术语、论点和引用重复，需要一个共享术语表和最终跨章一致性审阅。多 Agent 不一定优于单 Agent，只有分工可独立验收且收益覆盖协调成本时才拆。

---

## 03 追问与口述

“反思几次合适？”由缺陷是否减少与总预算决定，不能固定三次就保证质量。“checkpoint 能回滚每步吗？”能恢复运行状态，不能撤销已发布或外发的文件；发布单独走授权步骤。

口述：“工作流管理证据和产物的可追溯关系，模型负责局部生成，独立校验与人工审核控制交付质量。”
