# 01 在 Agent 项目中，如何做风险闭环？如何判断用户意图？

## 01 核心回答


**风险闭环（六步）：**“识别、评估、拦截、处置、验证、复盘”——识别阶段检测提示词注入、敏感数据、越权请求、危险 SQL 和高风险业务动作；评估阶段根据用户身份、资源范围、操作类型、影响范围和模型置信度计算风险等级。处置分级：**低风险自动执行、中风险用户二次确认、高风险人工审批或直接拒绝**。

**意图判断（不只靠一句自然语言）：**① 意图分类（查询/创建/修改/删除/分析/咨询）；② 提取对象、时间、范围、条件、输出格式和权限等**槽位**；③ 结合历史对话补全信息；④ 检查槽位是否完整、类型是否正确、实体是否存在、用户是否有权限；⑤ 多意图请求拆成任务计划逐个确认。

**审计闭环：**把意图、槽位、风险等级、规则命中和执行结果写入审计记录，异常时支持回放、人工接管、撤销或补偿。

面试追问：风险等级怎样定义（根据身份、范围、操作、影响与证据设业务策略；非通用乘法公式）；提示词注入怎么检测（敏感模式 + 工具参数校验）；撤销/补偿怎么做（状态机 + 幂等）。

---

## 02 意图不是执行授权

用户说“帮我看看这些过期记录”不等于允许删除。分类后提取动作、对象、范围和期望结果；对歧义先澄清，对涉及敏感数据或不可逆变化的动作绑定明确审批。历史对话只能提供语境，不能把过期授权无限延伸。

风险计算可使用身份、操作、影响面、可逆性和证据充分性等特征，但“身份 × 范围 × 置信度”是口述框架，不是通用数学公式。模型自报信心不能抵消权限缺失或高风险动作。规则引擎决定硬边界，模型帮助识别不确定语义。

## 03 如何验证闭环有效

审计记录关联原请求、解析结果、规则版本、审批范围、工具调用和外部业务结果。故障演练覆盖误分类、工具超时后已执行、审批内容变更与注入。整改后回归相同失败样本，并监控误拦与漏拦。

口述：“意图识别决定用户想做什么，授权决定系统能做什么，执行核验决定是否真的做成；三者不能合并为一次模型判断。”
