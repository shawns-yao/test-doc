# 34 如果做一个 Agent 创作助手，工作流怎么编排、状态怎么保存、怎么观测？

## 01 核心回答

工作流编排：用任务图或状态机——意图识别 → 任务规划 → 分段执行（过程中可检索编排）→ 任务审校核对 → 不通过则根据审校建议再修改 → 人工审核节点 → 任务发布。

状态保存（记忆）：短期记忆服务当前任务；内存/Redis 可做热状态，重要任务另需可靠持久化；长期记忆——用户特征、行为方式、专业知识，存向量库或关系型数据库；日志行为类参考龙虾存本地 MD 文件。

观测：最小三件套 Log + Metric + Trace；具体指标——系统稳定性（延迟 P95/P99、CPU）、成本（token 监控）、执行步数、业务成功率/超时率/失败错误码分布、Agent 鲁棒性（工具调用失败时表现）、主动性（人工介入情况、可观察产物是否符合约束、计划变更是否有证据与授权依据）。

---

## 02 创作状态与发布状态分开

工作流可细分为需求与受众确认、资料检索、提纲、草稿、事实/风格审校、用户审阅和发布。创作循环记录稿件版本、引用、修改意见与已确认约束，避免审校改稿后丢失用户已批准的要求。发布是外部动作，要单独绑定目标平台、内容版本与授权。

短期状态也要能跨进程恢复，重要草稿放持久文件或对象存储，数据库保存引用与版本；Redis 可做热缓存，不是可靠唯一副本。用户偏好与任务临时要求分开，不能把一次特殊语气永久记成偏好。

---

## 03 观测与验收

观察生成/审校轮数、事实错误、引用覆盖、修改采纳率、延迟和单位合格稿件成本。正常请求人工审阅不应视为失败，未经授权发布才是严重缺陷。过程可追踪以计划摘要、工具事件和产物 diff 为依据，不要求隐藏思维链。

口述：“稿件版本是创作主线，状态可恢复、证据可回查、发布有独立审批。”相关：[[八股/07-AI与Agent/02-Agent原理与编排/21-Agent的checkpoint是什么|检查点]]。
