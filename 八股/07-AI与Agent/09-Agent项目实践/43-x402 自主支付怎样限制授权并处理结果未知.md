# 43 x402 自主支付怎样限制授权并处理结果未知

## 01 协议职责与应用授权分开

x402 是基于 HTTP 的支付协议。典型流程中，资源服务给出支付要求，客户端提交支付材料，资源服务本地或经 facilitator 验证，并按所用方案结算及交付资源。验证通过、完成结算、资源成功交付并非同一状态，具体顺序和消息字段取决于协议版本与支付方案。

协议能够承载支付，不代表 Agent 获得用户无限花费权限。本页是系统设计题，不执行真实付款。

---

## 02 支付网关在签名前拦截

以下是参考治理设计：授权绑定收款方、资产、网络、金额上限、用途、有效期和累计预算；支付要求来自外部，先核对是否属于已授权服务，不能因页面返回402就自动批准。提示词注入不得改变预算或签名范围。

模型可以提出购买资源的请求，确定性网关校验策略；签名组件隔离私钥；高风险或越界请求重新交给用户决定。价格上涨、换收款方或新订阅都属于授权条件变化。

---

## 03 把支付状态与资源交付状态持久化

应用保存业务请求 ID、报价/支付要求指纹、授权证据、结算标识和资源交付标识。网络失败时可能已扣款但没收到结果，先查询或恢复原请求，不直接另付一笔。支付成功而交付失败需要可追踪的补交付或退款流程，不能指望 HTTP 重试自动保证业务恰好一次。

重放保护依具体方案的 nonce/签名语义实现，业务去重额外保证一个资源请求不会重复收费。测试重复响应、过期授权、金额不一致、预算竞争、已结算后崩溃与恢复。
