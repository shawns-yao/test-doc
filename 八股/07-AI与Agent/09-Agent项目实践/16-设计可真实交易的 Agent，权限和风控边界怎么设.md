# 16 设计可真实交易的 Agent，权限和风控边界怎么设？

## 01 核心回答

**回答（九个词对应三层防线）：**

① 权限层（先防误用）：read-only 默认——新 Agent 默认只能查行情和持仓不能下单；动作分级授权——查阅、模拟下单、真实下单、调杠杆、撤单分别授权；密钥隔离——按环境/策略/账户拆分 API Key，生产凭证由受控密钥/执行系统管理，按协议选择 KMS/HSM 等保护方式并配置轮换，避免进入模型上下文，子账户隔离。

**② 交易前风控层（先校验再执行）：** **额度限制**——单笔/单日/单策略限额、最大仓位、最大杠杆；**风控前置校验**——下单网关校验价格偏离、滑点、频率、风险敞口，不通过直接拒单；**双确认**——大额开仓/高杠杆/新币对二次确认，可人工审批或双签。

**③ 运行与追责层（可追溯可止损）：** **审计日志**——完整记录「输入-推理摘要-风控结果-最终指令-交易回执」；**回放**——按 request_id 回放决策链；**沙箱执行**——新策略先模拟盘/影子模式，稳定后再灰度真实资金。

---

## 02 权限与审批如何绑定

将读取、模拟、提交订单、撤销、调整配置等动作分开授权，审批应明确账户、对象、方向、数量、有效期与价格约束等必要参数。审批后参数或行情条件发生实质变化，重新校验；不能把一次同意扩展成无限持续交易权。

生产凭证由受控执行网关持有，不暴露给模型或通用插件。KMS/HSM 能保护密钥管理或签名，但某些外部 API 的凭证使用仍涉及执行进程，不能简单声称“用了 KMS 就绝不落入内存或绝不泄露”。禁提币权限、环境隔离和网络控制需分别设置。

---

## 03 追责不依赖隐藏思维链

保留授权、决策摘要、规则版本、入参、回执、状态转换和最终对账证据，敏感字段脱敏；回放使用模拟器，不再触发真实资金动作。模拟盘结果与真实滑点、费用和流动性不同，不能仅凭模拟成功就跳过发布审查。

口述：“权限按动作最小化，审批绑定具体指令，执行网关持有凭证，结果以业务回执与对账为准。”
