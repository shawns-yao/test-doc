# 08 大模型推理如何优化显存、时延与吞吐

## 01 先拆指标与瓶颈

显存至少区分模型权重、KV cache、激活/临时工作区与运行时预留；不要把 QLoRA 训练的显存结论直接当成推理服务结论。性能也要分首 token 时延（TTFT，含排队与 prefill）、相邻 token 间隔、完整响应时延，以及给定质量门槛下的吞吐和单位成功请求成本。

Prefill 处理已有输入，decode 逐步生成新 token；二者的计算和访存特征不同。先记录真实输入长度、输出长度与并发分布，再定位是排队、计算、内存带宽还是外部工具慢。应用只调用托管模型 API 时，通常不能自行调它的 GPU/KV 实现，应从请求预算、模型路由与供应商公开参数入手。

## 02 KV cache 为什么有效又占内存

自回归生成可保存历史 token 的 Key/Value，避免每一步重复计算对应表示；仍需用新 query 关注历史，并非后续计算全被缓存。对普通全注意力层的简化估算是：KV 字节数约为 2 × 层数 × 活跃序列数 × 每序列缓存长度 × KV 头数 × 头维度 × 每元素字节数。系数 2 对应 K 和 V；变长序列、滑窗、分片、GQA/MQA 及缓存实现会改变实际占用。

常见优化是限制总在途 token、清理结束请求、采用按块管理减少碎片；PagedAttention 解决 KV 内存管理与共享问题，不等于删除模型必须保留的历史信息。更小 KV 精度或 CPU offload 可省显存，但要验证精度、传输及时延代价。

## 03 从权重到调度的取舍

- 权重量化：降低存储和可能的带宽负担，收益依硬件内核与任务而定；量化权重不自动压缩 KV，需分别评测
- 批处理：提高设备利用率，但等待凑批或过高并发会拉长排队；连续批处理允许完成请求退出、新请求加入，仍需总 token 限额和公平调度
- 输入与输出预算：减少无关材料和不必要长输出；前缀缓存可以复用兼容前缀的计算，不等于可以复用旧答案或跨权限共享资料
- 模型与任务分级：简单任务用经过验证的较小模型，复杂任务用更强模型；应比较最终质量与返工成本，不能只看单次推理费

## 04 如何验证没有用效果换虚假提速

固定硬件、模型版本、精度、样本与长度分布，再对照 p50/p95/p99、TTFT、每 token 时延、OOM/超时率、吞吐及端到端质量。记录并发和排队政策，否则“更快”可能只是少接请求。安全、工具参数正确率和引用质量都要保留上线门槛。

直接追问“大 batch 一定更好吗？”吞吐、单请求延迟、KV 占用和公平性相互制约；“量化一定无损吗？”不能保证，要在目标任务与所选量化实现上回归。口述：“先分权重、KV 和调度瓶颈，再在固定质量门槛下优化，报告尾延迟与成功成本。”
