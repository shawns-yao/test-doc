# 03 Agent 出现幻觉、瞎调工具,线上怎么兜底?

## 01 核心回答

**一句话结论:**幻觉靠**"证据约束 + 不确定性表达"**,瞎调工具靠**"权限白名单 + 调用前校验 + 高危操作人工确认"**,线上靠**监控告警与熔断降级**。

**治幻觉:**要求回答必须引用检索来源或工具结果;提示"没有证据就承认不知道,不要编造";关键数值/事实与来源做一致性校验;RAG 检索不到时不硬答。

**治瞎调工具:**工具白名单 + 参数 Schema 强校验 + 危险操作(删除/下单/发消息)二次人工确认;按用户权限过滤可用工具。

线上兜底:必要且脱敏的审计日志(调用、参数摘要、发起者与授权可回查);异常率监控(工具调用失败率/拒绝率突增告警);高风险场景先灰度、可一键熔断降级到人工或只读模式。

记忆要点:管住嘴(证据+拒答)、管住手(白名单+校验+审批)、看得见(审计+监控+熔断)。

## 02 线上止血与根因修复分开

先关闭受影响的高风险动作或版本，保留可安全交付的查询与解释；核验已经发生的业务副作用，不能只切只读就当事故结束。参数合法仍可能选错对象，因此要验证资源归属、用户意图和实际授权。

对于幻觉，检查是否无证据、引用错、材料过期或生成外推；对于工具误用，检查描述、路由、权限和运行时策略。把已确认坏例变成回归测试，修复后灰度验证，不只是追加一句更严厉的提示词。

日志按必要性脱敏和留存，避免“全量审计”变成泄露新入口。口述：“先限制影响，再按可观察证据定位和修复，最后验证旧故障不能再发生。”
