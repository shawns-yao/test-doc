# 04 生产环境怎么做 Agent 的可观测性(日志、Trace、埋点)?

## 01 核心回答

一句话结论:Agent 可观测的核心是运行过程可追溯:从用户请求到可观察计划、状态、工具调用和结果的关联 Trace + 结构化日志 + 指标埋点。

Trace 链路:按任务组织 trace_id，并用会话/父子任务ID关联,串联每个 Agent 步骤的输入/输出/工具调用/耗时;每步关键事件打 span(模型调用、工具调用、检索、人工介入点)。

**结构化日志:**记录模型名称、温度、token 用量、工具名与参数、返回状态、错误类型,便于事后检索与统计(可接入 OpenTelemetry/LangSmith 类平台)。

**指标埋点:**成功率、平均步数、工具调用分布、token 成本、延迟、幻觉投诉率、重试率,做趋势告警。

回放与评测:线上可在隔离环境回放已保存输入、状态与模拟工具行为，不能保证复现隐藏推理或外部环境用于定位问题;抽样把线上 badcase 回流到离线评测集,驱动持续优化。

记忆要点:三个词——Trace 串全链、日志留证据、指标出告警;再加一句"能回放才能复盘,能回流才能进化"。

## 02 可观测对象是运行事实

Trace 应串联请求、子任务、模型调用、检索、工具、审批和产物；不要求获取每一步隐藏 Thought。可保存必要的计划摘要和决策依据，但这些生成文字不是模型内部过程的忠实证明。

长会话可包含多个任务 trace，用关联 ID 连接，不能强制一次会话永远等于一个 trace。日志保护敏感输入输出，指标避免高基数标签；回放用已保存输入与模拟工具，实际环境变化可能令结果不可完全重现。

口述：“Trace 看路径，日志看证据，指标看趋势；可追溯不等于完整复现内部推理，也不允许重放真实副作用。”详见[[八股/07-AI与Agent/05-评测与可观测性/09-上线后如何持续监控与评估|持续监控]]。
