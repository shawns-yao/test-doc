# 01 Agent 的成本怎么控制(Token 消耗、调用次数、模型选型分级)?

## 01 核心回答

一句话结论:模型成本按每次调用的各类 token 用量与单价求和，总成本还含工具/检索/计算等费用,分别从模型分级、上下文瘦身、调用收敛三路控制。

**模型分级:**任务分级路由——简单分类/抽取用小模型或快模型,复杂推理才用大模型;内部工具调用与面向用户回复可分层用不同模型。

**Token 瘦身:**控制上下文长度(摘要压缩、只保留必要检索结果、裁剪历史)、精简 System Prompt、结构化输出用低 token 格式、Prompt Caching 复用前缀。

**调用次数收敛:**限制最大步数/工具调用次数、合并可并行调用、失败重试设上限、命中缓存(语义缓存)直接复用历史结果。

**成本观测:**按 Agent/任务/用户维度打点 token 与成本,建立告警,用数据驱动优化(先量化再砍)。

记忆要点:分级(贵的少用)、瘦身(上下文别塞满)、收敛(别瞎调工具)、打点(先量化再优化)。

## 02 成本口径先纠正

若 token 用量指单次平均，可再乘调用次数；若已经是任务总量，再乘一次就是重复计算。输入、缓存输入、输出以及供应商额外计费项应分别求和，再加搜索工具、检索、沙箱与人工返工成本。

并行降低墙钟时延，不一定减少调用费；Prompt 缓存与答案缓存不同，后者还要处理权限和知识版本。小模型错误引起重试或人工接管时，单位成功任务成本可能反而更高。

口述：“在质量约束下优化成功成本，设置任务与租户总预算，不能只追最低 token 单价。”完整方案见[[八股/07-AI与Agent/09-Agent项目实践/37-价格，预算|价格与预算]]。
