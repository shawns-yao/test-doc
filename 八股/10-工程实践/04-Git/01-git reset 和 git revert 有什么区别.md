# 01 `git reset` 和 `git revert` 有什么区别？

## 01 核心回答


**git reset**

**行为：**移动当前分支的 HEAD 指针，**重写历史**——提交记录被移除/修改。

**模式：**`--soft`（保留暂存区）、`--mixed`（默认，保留工作区）、`--hard`（丢弃工作区改动）。

**适用：**本地未推送的提交回退、整理提交（rebase 前）；**已推送的共享分支不要用**——会与其他人的历史分叉。

**git revert**

**行为：**生成一个**反向提交**来抵消目标提交的改动，**不重写历史**，原提交保留。

**模式：**`git revert <commit>` 自动创建新提交；可 `-n` 不自动提交。

**适用：**已推送到共享分支的提交回退——历史完整、协作安全。

**关键细节：**判断标准就一条：**提交是否已推送/共享**——未推送用 reset 干净回退；已推送用 revert 安全回退。revert 可能出现冲突（后续提交改了同一处），需要手动解决。

**面试追问：**reset --hard 后还能找回提交吗（仍保留的提交可能经 reflog 找回，未提交内容不保证可恢复）；revert 和 cherry-pick 的关系（反向后应用 vs 正向应用）；rebase 和 merge 的区别。

---

## 02 理解补充与边界校订

旧文 reset 的结论特指带提交目标的分支移动形式；按路径 reset 主要更新暂存区，不移动分支。reflog 能找回仍存在的提交，不保证恢复从未提交的工作区内容，也受过期和垃圾回收影响。共享分支优先 revert，但合并提交需要理解 mainline 与后续再合并的语义。
