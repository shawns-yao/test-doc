# 05 排查问题时了解或使用过哪些开源工具？

## 01 核心回答


**概念原理：**排查工具按场景分四类：**链路追踪**（请求到哪了、哪段慢）、**指标监控**（资源与业务水位）、**日志分析**（错误与现场）、**深度诊断**（JVM/性能热点）。面试关键是"什么场景用什么工具 + 实际用过哪个"。

**常用工具清单（按场景）：**① **链路追踪**：Jaeger、Zipkin、SkyWalking——看 Trace 各 span 耗时定位慢段；② **指标监控**：Prometheus + Grafana——CPU/内存/GC/QPS/错误率大盘和告警；③ **日志**：ELK（Elasticsearch + Logstash + Kibana）、Loki——集中检索错误日志；④ **JVM 诊断**：jstat/jmap/jstack、MAT（heap dump 分析）、Arthas（线上诊断神器：看方法耗时、反编译、热更新）、JFR；⑤ **性能剖析**：async-profiler 火焰图——定位 CPU 热点；⑥ **网络**：tcpdump、Wireshark、netstat/ss、mtr（路由丢包）。

**实际排查组合：**接口慢 → SkyWalking/Jaeger 看链路（发现某段 DB 慢）→ Prometheus 看 DB 连接池/慢查询指标 → ELK 搜相关日志确认 SQL → 用 EXPLAIN 分析；JVM 问题 → Arthas 看线程/GC → jmap dump + MAT 查泄漏 → 火焰图找热点。

**关键细节：**工具要**按场景选型**而不是堆砌：小团队 Prometheus + Loki + Arthas 就够；关键链路应保证上下文贯通，采用适当采样仍有价值；Arthas 线上操作要谨慎（热更新影响运行态）。

**风险与取舍：**全链路可观测（追踪+指标+日志）建设成本高，按核心链路优先接入；工具本身也要监控（ES 集群挂了日志查不了）；诊断工具权限要收敛（Arthas 能改线上代码）。

**项目落地：**监控：Prometheus 采集应用指标（QPS、P99、GC）+ 告警规则；日志：Loki/ELK 集中检索；诊断：Arthas 日常排障、MAT 分析 OOM dump、火焰图优化热点；发布后对比指标基线。

**面试追问：**SkyWalking 和 Jaeger 的区别（APM 全家桶 vs 链路组件）；Arthas 常用命令（dashboard/thread/trace/watch）；火焰图怎么看（宽度表示采样出现频率，不是时间轴；需结合采样类型解释）；jmap 和 jstack 分别看什么（堆 vs 线程）。

---

## 02 理解补充与边界校订

火焰图横向宽度是采样栈出现的相对数量，不是从左到右的时间线；CPU、分配和锁等待火焰图的采样含义不同。Tracing 不要求永远全量采样才有价值，关键是上下文传播、采样偏差和慢请求可定位。heap dump、动态探针、热替换都可能带来停顿或状态变化，线上诊断要先评估成本和权限。
