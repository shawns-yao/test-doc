# 04 Web 应用中如何保护密码、密钥和敏感数据？

## 01 核心回答


**概念原理（密码）：**密码不能明文保存，也不能使用普通 MD5 或 SHA-1 直接哈希。应使用带随机盐和成本参数的专用密码哈希算法，如 Argon2id、bcrypt 或 scrypt；登录时用同算法校验，并设置失败次数限制、验证码、风险控制和多因素认证。密码重置 Token 要随机、短时有效、一次性使用，并避免在日志和 URL 中泄露。

**实现流程（密钥管理）：**密钥和 Token 不应硬编码在代码、镜像或仓库中，运行时从密钥管理系统或受控环境注入，按服务和环境隔离，遵循最小权限和定期轮换。密钥生命周期：生成、分发、访问、轮换、吊销、审计和应急替换都要有记录。

**实现流程（敏感数据）：**传输使用 TLS；数据库和备份中的敏感字段根据风险进行加密或脱敏，密钥与密文分离保存；日志、Trace、错误信息和监控标签要过滤身份证号、手机号、Token、密码和连接字符串。

**关键细节：**bcrypt/Argon2 自带盐和成本因子，相同密码产生不同哈希；加密 ≠ 哈希——密码用单向哈希，可逆数据（手机号）用加密 + 密钥管理；前端不要把高权限密钥放入可见代码。

**风险与取舍：**加盐哈希无法防止弱密码被离线爆破（配合强度策略）；密钥轮换要处理存量数据解密兼容；脱敏与可用性冲突（测试环境需要真实数据时用合成数据）。

**项目落地：**服务端接口做鉴权、授权、重放防护和审计；日志脱敏组件统一过滤敏感字段；配置中心/环境变量注入密钥，不落代码仓库；数据删除、导出和备份符合组织的保留与合规要求。

**面试追问：**为什么不能用 MD5 存密码（无盐可查彩虹表 + 算力可爆破）；bcrypt 和 MD5 的区别（盐 + 成本因子 + 慢哈希）；加密和哈希的区别（可逆 vs 不可逆）；密钥轮换怎么做（双密钥灰度 + 存量解密）。

## 02 理解补充与边界校订

盐不需要保密，用来阻止相同密码产生可复用的预计算结果；pepper 若使用则作为额外秘密独立保存。参数必须按服务器承载能力和当前建议调优，登录成功后可渐进升级哈希参数。环境变量只是分发手段，不天然等于安全密钥库；还需约束进程读取、诊断转储和日志泄露路径。
