# 03 如何设计一个爬虫系统？

## 01 核心回答

**本质：**爬虫系统是带**调度能力的数据采集系统**。核心链路：Seed URL 进入 Frontier 调度队列 → Downloader 拉取页面 → Parser 解析内容和新链接 → URL/内容去重过滤 → 回到 Frontier。

**URL Frontier（最关键）：**不是简单 FIFO，而是调度中心，要同时解决三件事——**优先级**（按页面重要性和更新频率安排抓取顺序）、**礼貌性**（按 host 维度拆队列，同一 host 串行抓取加间隔）、**新鲜度**（更新频繁的重要页面提高重抓频率）。

**去重：**URL 去重（防重复 URL 进 Frontier，用 Bloom Filter/HashSet/Redis Set）+ 内容去重（防不同 URL 相同内容，用哈希值/checksum）。

**其他重点：**DNS 缓存、robots.txt、失败恢复、spider trap。

**口述重点：**爬虫系统最核心的不是「抓得快」，而是「调度得稳、过滤得准、恢复得动」。

---

## 02 Frontier 是可恢复的定时调度器

队列条目保存 URL、host、优先级、最早允许抓取时间、重试次数与抓取租约。调度器选择当前可抓取的 host，限制每站点并发和速率，再由 Worker 获取任务；Worker 宕机后租约到期重新调度，URL 与内容处理需幂等。

单站串行是简单实现，不是所有站点都必须只有一个连接；并发额度应尊重站点政策、服务响应与实际容量。全局吞吐高不应以压垮某个站点为代价。用 ETag/Last-Modified 的条件请求降低重复下载成本，分别设置连接、响应、正文大小与解压限制。

---

## 03 去重与安全边界

URL 规范化要遵循语义，不能任意删除查询参数或把路径大小写统一；看起来相似的 URL 可能是不同资源。Bloom Filter 有误判，若直接丢弃“可能已见”URL，会漏抓，可配精确存储复核或接受并量化覆盖损失。内容哈希只识别相同字节，近重复需要额外特征。

遵守 robots.txt 与授权边界；robots 不是登录授权，也不是允许绕过访问限制的凭证。用户提交 URL 及重定向要防 SSRF、内网地址和 DNS 重绑定；抓取无限日历、组合参数和循环重定向需深度/预算控制。

口述：“我把爬虫设计成按站点限速、带租约的可恢复调度系统，用精确与概率去重分层控制成本，兼顾新鲜度、合法访问和失败恢复。”
