# 05 七层负载均衡和四层负载均衡有什么区别？分别适合什么场景？

## 01 核心回答


**四层负载均衡（L4）**

工作在传输层，按**四元组（IP + 端口）**转发，不解析应用内容（如 LVS、F5 部分模式、AWS NLB）。

**优点：**通常处理开销较低（具体实现可为内核、用户态或专用硬件）、延迟较低、支持海量连接（TCP/UDP）。

**局限：**不能按 URL/Header/Cookie 路由，无法做应用层判断（灰度、限流按路径）。

**七层负载均衡（L7）**

工作在应用层，解析 HTTP 内容（URL、Header、Cookie、请求体）做智能路由（如 Nginx、HAProxy、AWS ALB）。

**优点：**按路径/域名路由、灰度发布、SSL 终结、缓存压缩、应用层健康检查。

**局限：**解析与代理通常增加开销，但性能需同配置实测；连接状态与资源消耗取决于实现，连接数大时消耗资源。

**选型场景：**入口大流量（千万级连接）用 L4 抗压，其后挂 L7 做应用路由（典型：LVS → Nginx → 服务）；TCP/UDP 长连接服务（游戏、IM）用 L4；HTTP 服务需要请求级灰度/路径路由时用 L7；TLS 终止并非 L7 独有；两者常串联使用。

**面试追问：**四层转发为什么不看 URL（不拆包到应用层）；会话保持怎么做（L4 按源 IP hash、L7 按 Cookie）；LVS 的 DR/NAT/TUN 模式区别（转发方式）。

---

## 02 区分转发单位与协议能力

L4 通常以连接/流为分发单位，结合源/目的地址、端口及协议；L7 理解 HTTP 等应用协议，可以按请求内容选择后端。HTTP/2 一条连接承载多个请求，L4 固定分配连接时可能出现长连接负载倾斜；L7 代理可以在请求层使用不同策略。

“L4 必须内核态、L7 一定用户态”不是定义。NLB 也可终止 TLS，因此不能用是否有证书区分层次；未解密的普通 TCP 转发看不到 HTTP path，但 TLS 相关路由还需按产品能力说明。

---

## 03 上线时的实际取舍

选择前明确长连接数量、新建连接率、请求大小、TLS、健康检查与连接排空。摘除实例不是强行断掉全部连接，应允许存量请求完成，并限制最长排空时间。源 IP 保留、代理头和 PROXY protocol 也必须由两端一致配置，应用只能信任可信代理添加的信息。

口述：“我按是否需要理解请求内容选 L4 或 L7，再检查长连接分布、TLS、健康检查与排空。两者可组合，但多一层代理就多一份时延、配置和故障域，不能仅用千万连接这样的泛化数字决定。”
