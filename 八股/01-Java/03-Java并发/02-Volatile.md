# 02 volatile 的机制是什么？到底在解决什么问题？

多线程中，真正麻烦的不是变量有没有修改，而是线程 A 改了一个值之后，线程 B 什么时候能知道，以及线程 A 前面做的哪些操作，线程 B 能不能一起可靠的看到？

比如线程 A 做了很多事情，比如准备数据，等到所有的数据都准备好了之后，最后修改一个 volatile 的变量，相当于说，我前面的工作完成了，现在正式的发布
线程 A 在发布这个 volatile 值之前的那些完成的写操作，也要对线程 B 可见
volatile 并不是只保证这个变量本身能被看到
还可以把这个 volatile 写之前的操作一起发布出去

volatile 提供两个核心保证：
1. **可见性**
2. **有序性**（限制重排序）
但是不解决复合操作（比如 i++）的原子性

volatile 写与同一变量的后续读建立 happens-before；具体屏障和缓存访问由 JVM 与硬件实现，不意味着绕过 CPU 缓存直接读写物理主存。

---
## 01 volatile 如何保证可见性和有序性

存在一个 Happens-Before 原则，
对于一个 Volatile 变量的写，Happens-Before 后续任意线程对这个 volatile 变量的读

也就是 A Happens-Before B ，那么 JMM 保证 A 的执行结果对 B 可见，并建立所需的内存顺序约束，而不是要求所有底层指令都按这个时间顺序执行

通俗来说，一个线程中某一个变量添加 volatile 关键词后，其他线程之后读取这个 volatile 变量的时候，JMM 会通过 volatile 的同步语义，使这个写以及写之前的操作对读线程可见

---
## 02 volatile 怎么防止指令重排？
volatile 的读写会形成内存语义上的顺序约束，限制相关读写操作跨越它重新排序。面试时可以先从 JMM 的 happens-before 规则解释，再补充内存屏障是 JVM/CPU 层面的实现手段。

典型应用是双重检查锁单例：对象创建并不是一步完成，如果引用没有使用 volatile，其他线程可能看到尚未完成初始化的对象。

## 03 常见追问

### 03.1 volatile 能保证原子性吗？
需要区分单次读写和复合操作：volatile 的单次读、单次写是原子的（包括 long/double），但不能保证 `i++` 这类“读—改—写”复合操作不可被线程交错执行。需要复合操作的原子性时，可以考虑锁或原子类。

### 03.2 volatile 和 synchronized 有什么区别？

- volatile 不提供互斥，适合状态标志、发布结果等场景。
- synchronized 同时提供互斥和可见性，适合保护临界区内的一组操作。
- 两者都与 JMM 的可见性和有序性规则有关，但解决的问题范围不同。

## 04 内存屏障是什么

可以理解为 JVM/CPU 中的一种排序约束，某些内存操作不能跨越这条边界

它是 volatile 语义在底层实现中的重要手段之一。

## 06 旧面经的详细补充


**概念原理：**`volatile` 保证**可见性**（对同一 volatile 变量的后续读建立同步关系）和**有序性**（限制会破坏规定内存语义的重排序）。JMM 模型：线程有工作内存（寄存器/缓存），主存共享变量——volatile 不要求穿透物理主存。

**为什么保证不了原子性：**volatile 不管**复合操作**。以 `i++` 为例：读 i → 加 1 → 写回 i，三步都可能被其他线程穿插——volatile 只保证每步的可见性，不保证三步作为一个整体不被拆开。原子性要靠 `synchronized` 或 `AtomicInteger`（CAS）。

**典型应用：**① 状态标志位（`volatile boolean running`，一个线程写、其他线程读）；② 双重检查锁单例（`DCL` 中的 volatile 防止 `new` 三步重排暴露半初始化对象）；③ 无锁队列的写指针。

**面试追问：**懒汉单例里 volatile 有什么用（防止分配内存→初始化→赋值的重排）；JMM 主存和工作内存怎么同步（happens-before 与同步顺序，屏障是实现方式）；volatile 和 synchronized 的区别（volatile 不提供临界区互斥，锁可保护一组操作）。

## 07 为什么 volatile 引用不等于对象线程安全

volatile 修饰的是引用变量。把一个完整初始化的新对象赋给该引用，可以用于发布快照；之后多个线程继续无同步地修改对象内部普通字段，不会因为引用是 volatile 而自动获得互斥或可靠可见性。数组引用为 volatile 也不意味着每个数组元素都具备 volatile 语义。

典型适用场景是单向停止标志、只读快照替换和配合其他同步协议的状态发布。若新值依赖旧值，例如余额扣减、计数累加，或多个字段共同维护不变量，应选择 CAS 原子类或同一把锁。

## 08 面试口述版与纠错

volatile 对单次读写提供原子性和规定的可见性、顺序语义，但不锁住一整段代码。两个线程都读到 0，再分别写入 1，完全符合 volatile 规则，所以 i++ 仍会丢失更新。它最重要的用途是建立发布关系，而不是“让任意共享对象自动线程安全”。本次修正原“怎么保证原子性”的题头，以及“完全不能保证原子性”“强制穿透主存”的绝对说法。
