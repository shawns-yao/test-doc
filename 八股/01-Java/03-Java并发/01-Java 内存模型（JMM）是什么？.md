# 01 Java 内存模型（JMM）是什么？

## 01 定义

JMM 是一套并发访问共享变量的规则，是 Java 为了规定多线程环境下线程之间如何读写共享变量，以及如何保证原子性、可见性和有序性而定义的一套规范。

---

## 02 想要解决的三个问题

- 一个线程修改了变量，另外一个线程什么时候能看到？
- 代码执行的顺序能不能重排？
- 多线程并发读写怎样才算是正确的？

可以理解为每一个线程都有自己的工作内存。线程操作共享变量时，并不是每次都直接访问主内存，因此可能出现一个线程修改了变量，而另外一个线程暂时看不到的问题。

---

JVM 内存区域（堆、栈、方法区、程序计数器等）解决的是数据存在哪里的问题。

JMM 解决的是多线程情况下数据怎么读写、什么时候可见，以及能不能重排序的问题。

---

## 03 JMM 基本概念

主内存与工作内存是帮助入门的历史抽象；真正判断并发结果是否合法，要看共享读写之间是否建立规范定义的同步关系。

### 03.1 可见性问题

JMM 抽象出了两个概念：主内存存放共享变量，每一个线程还存在自己的工作内存。

线程不会保证每次操作都直接访问主内存，而可能操作自己的变量副本。如果没有建立正确的同步关系，就有可能导致其中一个线程读取到旧值。

### 03.2 历史教学模型

八种操作不是现代 JLS 的实现指令要求：

- 主内存 → 工作内存：`read`（主存读）→ `load`（载入工作内存）→ `use`（使用）
- 工作内存 → 主内存：`assign`（赋值）→ `store`（存储）→ `write`（写回主存）
- 另外还有作用于主内存变量的 `lock`（加锁）和 `unlock`（解锁）

这套历史教学术语不能替代现代 JLS 对同步动作和 `happens-before` 的定义。

---

## 04 怎么解决这三个问题

先区分观察旧值、复合操作交错和可观察重排，再选择足够的同步边；三种风险可能出现在同一个业务操作中。

### 04.1 可见性：一个线程修改共享变量后，其他线程能否及时看到

使用 `volatile` 关键字。

### 04.2 原子性：一个操作能不能被看作不可分割的整体

比如 `count++` 实际上包含读取、加一、写回三个操作，并不是原子操作。因此可以使用 `synchronized` 或 `Lock` 等机制保证原子性。

### 04.3 有序性：代码是否可能发生指令重排序

从单线程来看，只要结果不受影响，编译器或 CPU 在某些情况下可能对操作进行调整。

但是在多线程环境下，重排序可能导致另外一个线程观察到非预期的行为。

因此，JMM 规定了哪些操作允许重排序，以及哪些可观察的顺序不能被破坏。例如，`volatile` 和 `synchronized` 都会建立一定的内存顺序约束。

同步语义不等于物理缓存清空：

- `volatile`：写与同一变量的后续读建立同步关系。
- 锁（`synchronized`/`Lock`）：释放锁与后续成功获取同一把锁建立可见性关系。
- `final`：正确构造且构造期间不逸出的对象具有特殊初始化安全保证，但不代表所有普通字段都自动安全发布。

JMM 是抽象模型，实际由内存屏障和缓存一致性协议（如 MESI）在硬件层实现。

---

## 05 JMM 的核心规则：`happens-before`（先行发生）

`happens-before` 规则是 JMM 判断一个线程的修改是否应该对另外一个线程可见的核心规则。

如果操作 A `happens-before` 操作 B，则保证 B 能看到 A 做出的修改。这并不是说 A 在时间上一定先于 B 执行，而是说 A 和 B 之间建立了可靠的内存可见性关系。

## 07 面试口述版

JMM 不是 JVM 的堆、栈、方法区等内存区域，而是 Java 对多线程读写共享变量建立的一套抽象规则。它主要解决可见性、有序性和原子性问题，并通过主内存、工作内存以及 `happens-before` 规则描述线程之间什么时候能够可靠地看到彼此的修改。`volatile` 和锁都是 JMM 规则在 Java 中的具体使用方式。

## 10 用 `happens-before` 推导发布关系

不要背“过一会儿总会刷新”。假设生产者先写普通字段 `data`，再写 `volatile` 标志 `ready`；消费者先读 `ready`，确认已发布，再读 `data`。程序顺序、`volatile` 同步边与传递性组成一条链，所以发布前的 `data` 写入对消费者可见。如果消费者绕过 `ready` 直接读 `data`，这条链就不存在。

常用规则包括：同线程程序顺序；同一监视器的解锁先于后续加锁；同一 `volatile` 变量的写先于后续读；`start` 先于新线程动作；线程动作先于另一线程成功 `join` 返回；以及传递性。这里的“先于”是规范约束，不要求机器指令完全按照墙上时钟顺序执行。

---

## 11 三个容易混淆的边界

- 可见性不是实时通知。消费者必须执行相应的读取或同步操作；`sleep` 和 `yield` 不建立同步关系。
- 无数据竞争不等于业务正确。每次 `get`、`set` 都线程安全，组合起来的“检查后更新”仍可能需要共同临界区。
- 局部变量本身不共享，但它引用的对象可能共享；对象不因被局部引用而天然线程安全。
