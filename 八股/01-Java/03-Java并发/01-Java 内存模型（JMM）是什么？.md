# 定义
JMM 是一套并发访问共享变量的规则，也就是 Java 为了规定多线程环境下，线程之间如何读写共享变量，以及如何保证，原子性，可见性，有序性，而定义的一套规范


# 想要解决的问题
一个线程修改了变量，另外一个线程什么时候能看到，代码执行的顺序能不能重排，多线程并发读写怎么样才算是正确的？
可以理解成每一个线程都有自己的工作内存，线程操作共享变量的时候 ，并不是直接抽象成每次都访问主内村，所以会导致一个线程修改了变量，而另外一个线程暂时看不到的问题


---
JVM 内存区域，堆，栈，方法区，程序计数器等 --> 解决的数据存在哪里
JMM 解决的是多线程情况下，数据怎么读写，什么时候可见，能不能重排序？

# JMM 基本概念

## 可见性问题
JMM 抽象出来了两个概念，其中主内存存放共享变量，每一个线程还存在自己的工作内存
	线程不会保证每次操作都直接访问主内存，而可能操作自己的变量副本，如果没有建立正确的同步关系，这就有可能导致其中一个线程读取的是旧值


# 怎么解决这三个问题


## 1. 可见性-->一个线程修改共享变量后，其他线程能否及时的看到

使用 volatile 关键词

## 2.  原子性-->一个操作能不能被看作不可分割的整个操作

比如 count++ 其实是三个操作。并不是原子操作，所以可以使用 synchronized 或者 Lock 等保证原子性


## 3. 有序性-->为了提高 CPU 和编译器的效率，代码可能会发生指令重排序

从单线程来看的话，只要结果不受影响，编译器或者 CPU 再某些情况下可能对操作进行调整
但是再多线程环境下，重排序可能导致另外一个线程看到不是预期的行为，

因此 JMM 规定了，哪些操作允许重排序，哪些操作之间绝对不能乱序，比如 Volatile ， Synchronized 就会建立起一定的内存顺序约束

## 4.JMM 的核心规则--> Happens-Before

比如 Happends-Before 规则就是 JMM 判断一个线程的修改是否应该对另外一个线程可见

比如操作 AHappends-Before 操作 B，那么保证 A 做的修改 B 一定能看到，并且也不是说在时间上 A 比 B 先执行，而是 A 和 B 之间建立了一个可靠的内存可见性关系

## 和其他并发问题的关系

JMM 是理解并发工具的基础模型：

- [[02-Volatile|Volatile]] 主要利用 volatile 读写语义解决可见性和有序性，但不能把 `i++` 这类复合操作变成原子操作。
- [[03-Synchronized是什么|Synchronized是什么]] 通过同一把锁建立互斥和可见性关系。
- [[04-ReentrantLock是什么|ReentrantLock是什么]] 通过显式锁和 AQS 管理线程之间的同步状态。
- [[05-ThreadLocal会造成内存泄露吗|ThreadLocal会造成内存泄露吗]] 主要解决线程之间的数据隔离，但不等于共享变量同步。

## 面试口述版

JMM 不是 JVM 的堆、栈、方法区等内存区域，而是 Java 对多线程读写共享变量建立的一套抽象规则。它主要解决可见性、有序性和原子性问题，并通过主内存、工作内存以及 happens-before 规则描述线程之间什么时候能够可靠地看到彼此的修改。volatile 和锁都是 JMM 规则在 Java 中的具体使用方式。
