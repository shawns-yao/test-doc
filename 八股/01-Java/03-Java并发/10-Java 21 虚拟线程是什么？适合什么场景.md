# 10 Java 21 虚拟线程是什么？适合什么场景

## 01 核心回答

虚拟线程是 JVM 管理的轻量线程，运行时挂载到平台 carrier 线程执行，在许多阻塞 I/O 等待时可卸载，让 carrier 服务其他虚拟线程。它在 JDK 21 正式发布，主要提升大量等待型任务的可扩展性，不会让单个 CPU 计算本身更快。

## 02 为什么不建议池化虚拟线程

平台线程池通过复用昂贵线程控制线程数量；虚拟线程设计为每任务一个，生命周期短，不需要像平台线程那样复用。下游容量限制应由连接池、Semaphore、限流与背压单独控制，而不是为了限制数据库并发而把所有虚拟任务塞进固定虚拟线程池。

即使线程便宜，请求对象、响应缓冲区和下游连接仍占资源，无界接收任务仍可能 OOM。CPU 密集任务最终受可用核心限制；大量虚拟线程并不会增加硬件并行度。

## 03 JDK 21 的固定与新版差异

JDK 21 中，虚拟线程在 synchronized 内执行阻塞调用或某些 native/foreign 调用时可能固定 carrier，影响扩展性。优先定位长时间阻塞的持锁路径，而不是机械替换所有 synchronized。JDK 24 通过 JEP 491 消除了监视器同步造成的这类固定，讨论优化必须说清运行版本；native 相关边界仍需具体分析。

## 04 ThreadLocal 与观测

虚拟线程有自己的 ThreadLocal 绑定，carrier 的 ThreadLocal 不会自动变成任务上下文。把昂贵缓存放在每线程 ThreadLocal 中可能因线程数巨大而放大成本。使用支持虚拟线程的线程转储/JFR；JDK 21 的传统 ThreadMXBean 并不覆盖虚拟线程。
