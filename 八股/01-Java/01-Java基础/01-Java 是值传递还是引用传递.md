# 01 Java 是值传递还是引用传递

## 01 核心回答

Java 始终是值传递。基本类型复制数值，对象参数复制引用值，形参和实参因此可以指向同一个对象，但仍是两份独立变量。

## 02 为什么方法内修改对象会影响调用方

把一个列表交给方法后，方法通过形参向列表添加元素，修改的是双方都指向的列表对象，所以调用方能看到变化。若方法只是让形参指向一个新列表，改变的是形参自己的引用值，调用方变量仍指向原列表。这两个行为不矛盾，也不能据此说“对象采用引用传递”。

交换两个对象形参的引用，只能交换局部副本，不能交换调用方的两个变量。若业务需要返回替换结果，应明确返回新对象或修改双方共享的容器。

## 03 final 与传参的关系

final 参数只能阻止形参重新赋值，不能阻止修改它指向的可变对象。数组同样是对象，数组参数复制引用，元素仍可能通过该引用被修改。包装类和 String 的常见“改了没有影响”来自不可变性和局部重新绑定，不是特殊传参规则。
