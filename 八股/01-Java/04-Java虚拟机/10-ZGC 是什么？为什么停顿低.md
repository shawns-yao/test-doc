# 10 ZGC 是什么？为什么停顿低？

## 01 核心回答

**概念：**JDK 11 推出的低延迟收集器，原文的 ≤10ms 和 4TB 是历史阶段信息，不能当 JDK 21 通用上限。ZGC 将大量标记、重定位及根处理工作并发化，目标是让短暂停顿不随堆和存活集线性增长，但不承诺业务延迟硬上限。

**关键技术（非分代/分代版本需区分）：**① **着色指针（Colored Pointers）**：指针里带状态位，GC 快速判断对象状态；② **读屏障（Load Barrier）**：线程读对象时若对象已搬迁，屏障把引用"修正到新地址"（自愈跳转）——对象迁移和业务线程**并发**进行。对比 G1 的转移阶段完全 STW 且停顿随存活对象增长。

**适用与代价：**适合延迟敏感服务（交易链路、实时推荐、网关核心路径）；代价：吞吐略低、CPU 开销更高、调优观测更复杂——工程上"先 G1，延迟 SLA 很严再上 ZGC"。

**追问：**读屏障为什么能自愈（修正到新地址后业务线程继续）；ZGC 和 G1 停顿差异本质（并发转移 vs STW 转移）；着色指针怎么区分对象状态（指针高位存标记位）。

---

## 02 为什么搬对象时业务还能运行

对象迁移后，旧引用可能尚未全部修正。屏障在访问路径检查所需状态、解析转发表并更新引用，使业务线程与回收线程能协作完成迁移。把工作从一次长暂停摊到并发执行路径，是低暂停的重要来源；代价是屏障、并发 CPU 和备用空间。

JDK 21 支持通过 UseZGC 与 ZGenerational 选择分代 ZGC；不能只说“所有 ZGC 都不分代”。分代实现还使用写入相关屏障和代际信息，不能把早期着色指针/读屏障图当作所有版本完整实现。启用参数应以目标 JDK 发行版文档为准。

## 03 调优与参考

最关键的是给并发回收赶上分配速度的空间与 CPU。若空闲空间耗尽，业务仍可能遭遇 allocation stall；GC pause 很小不代表完全没有等待。
