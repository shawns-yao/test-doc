# 08 G1 的核心思想是什么？

## 01 核心回答

**① 堆结构变化：**把整个堆切成等大小 **Region**（大小是 2 的幂；传统自动选择通常为 1–32MB，JDK 18+ 允许显式配置到 512MB，需区分自动选择范围与硬上限），每个 Region 可在不同阶段扮演 Eden/Survivor/Old——不再是年轻代老年代的固定物理分区。

**② 回收核心（Garbage First）：**每次 GC 不一定要全堆扫，而是优先选**"垃圾占比高、回收收益大"**的 Region——用更少的停顿拿到更多可用内存。

**③ 关键流程：**`Young GC`（回收 Eden/Survivor，存活对象晋升/复制）→ `Concurrent Mark`（并发标记全堆存活对象，统计 Region 存活率）→ `Mixed GC`（年轻代回收时顺带回收高收益 Old Region）。

**④ 可预测停顿：**给 `-XX:MaxGCPauseMillis` 目标，G1 根据历史统计（Region 回收/复制成本）动态控制回收集合大小，让停顿贴近目标。

**一句话：**G1 的本质是把 GC 从"整代粗粒度回收"变成"**Region 粒度、收益驱动、带停顿预算的回收调度器**"。

---

## 02 为什么能只处理部分 Region

G1 用写屏障维护跨 Region 引用信息，通过记忆集扫描回收集合外指向集合内的引用，避免每次疏散都从头扫描整个堆。并发标记采用 SATB 保留标记开始时所需的可达性信息；并发并不意味着没有维护成本。

Young GC 要处理本次年轻代集合；Mixed GC 在年轻代基础上选择部分老年代 Region。并发标记不是每次 Young GC 后都完整执行一次，而是按占用和预测需求启动周期。MaxGCPauseMillis 是调度目标，存活率、根集、CPU 限额和疏散失败仍会让暂停超出目标。

## 03 面试口述与依据

Region 划分让回收集合可选择，记忆集让局部回收可行，成本预测让选择贴近停顿预算，疏散让选中区域重新成为整块空闲空间。不要只背“垃圾多的先收”。
