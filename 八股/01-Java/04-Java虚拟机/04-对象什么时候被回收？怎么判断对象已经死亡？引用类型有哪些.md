# 04 对象什么时候被回收？怎么判断对象已经死亡？引用类型有哪些？

## 01 核心回答


**概念原理（存活判定）：**JVM 用**可达性分析**（GC Roots 算法）判定对象是否存活：从 GC Roots（栈帧局部变量、静态变量、常量池引用、JNI 引用）出发遍历，**不可达**的对象判定为可回收。HotSpot Java 堆主要采用追踪式回收，可处理仅互相引用而无根可达路径的环。

**历史 finalize 路径（不是每个对象的固定流程）：**无强可达路径不代表立即释放，引用处理和具体收集阶段会影响时机。历史 finalizable 对象还可能等待终结并复活；**finalization 自 JDK 18 已弃用并计划移除**，不能把“两次标记+finalize”讲成所有对象的通用流程。

**四种引用类型：**① **强引用**：普通 new，只要从 GC Roots 经强引用可达，就不会作为垃圾回收；② **软引用（SoftReference）**：由 GC 按内存需求决定清理，规范保证 OOM 前清除软可达对象的软引用；不能依赖固定保留时间，也不宜替代有界缓存策略；图片或大对象缓存是常见教学例子，生产环境仍需明确容量和淘汰机制；③ **弱引用（WeakReference）**：GC 判定对象弱可达时清除相应弱引用，不保证下一次任意局部 GC 都扫描该对象——ThreadLocal key、WeakHashMap；④ **虚引用（PhantomReference）**：get 始终为 null，配合引用队列感知虚可达状态并执行清理（如堆外内存清理）。

**面试追问：**软引用和弱引用的区别（内存需求驱动的软引用清理 vs 弱可达时的弱引用清理）；引用队列是什么（引用状态变化后的入队通知，不是精确的物理内存释放时刻）；为什么不用引用计数（循环引用无法回收）。

## 02 为什么“有引用”还可能被回收

不可达环中的对象互相有强引用，但从任何有效 GC Root 都找不到它们，所以仍可回收。讨论软/弱引用时也必须先确认没有更强的可达路径；同一对象同时被普通集合强引用时，创建 WeakReference 并不会让它提前释放。

对象可回收、引用被清除、Reference 入队和内存实际复用是不同事件。清理本地资源优先使用显式 close/try-with-resources；Cleaner 可作为兜底，但同样不保证及时执行，清理动作还应避免重新强引用待清理对象。
