# 01 JVM 运行时数据区域如何划分？堆、虚拟机栈、方法区等区域分别有什么作用？

## 01 核心回答


JVM 运行时数据区域可以分为线程私有区域和线程共享区域：

程序计数器

线程私有，执行非 native 方法时记录当前 JVM 指令地址；native 方法时其值未定义。规范没有为该区域规定 OOM。

虚拟机栈

线程私有，每次方法调用创建一个栈帧，栈帧包含局部变量表、操作数栈、动态链接和方法返回地址；栈深度超限抛 `StackOverflowError`。

本地方法栈

线程私有，为 Native 方法调用服务。

堆

线程共享，存放对象实例和数组，是垃圾回收的主要区域，对象过多时抛 `OutOfMemoryError: Java heap space`。

方法区

线程共享，规范层面保存每类结构、方法代码和运行时常量池等；Java 8+ HotSpot 以本地元空间保存类元数据，静态字段值和字符串对象不能一概说放在元空间。元空间默认未指定 MaxMetaspaceSize，但仍受本地内存/容器限制，类元信息过多会抛 `OOM: Metaspace`。

直接内存不属于 JVM 规范规定的运行时数据区域，但 `NIO` 等场景会使用它，排查内存问题时也需要关注。

**栈溢出**
递归过深或栈帧过多 → `StackOverflowError`。

**堆 OOM**
对象实例过多 → `OutOfMemoryError: Java heap space`。

**元空间 / 直接内存 OOM**
类元信息过多 → `OOM: Metaspace`；NIO 缓冲区过多 → `OOM: Direct buffer memory`。

## 02 规范区域不等于物理布局

JVMS 规定可观察行为，不强制所有 JVM 按一张固定物理内存图实现。方法区与元空间不是同义词；前者是规范概念，后者是 HotSpot 的实现选择。虚拟机栈也可能因无法分配或扩展而 OOM，StackOverflowError 只是超过允许栈深度的另一种错误。

TLAB 是 Java 堆内给线程的分配缓冲区，不是线程栈，更不是堆外。对象语义上由堆管理，但 JIT 可通过逃逸分析、标量替换消掉实际分配；不要从“局部变量”直接推断其对象实体就在栈里。
