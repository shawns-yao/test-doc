# 01 线程池提交任务后的核心执行流程是什么？请说明完整处理顺序。

## 01 核心回答


以 `ThreadPoolExecutor.execute()` 为例，提交任务后的顺序是：

1. 如果当前工作线程数小于 `corePoolSize`，优先创建核心线程执行任务。

2. 如果核心线程已达到上限，并且线程池仍在运行，就尝试把任务放入阻塞队列。

3. 入队后会再次检查线程池状态：如果线程池已经停止，则移除任务并执行拒绝策略；如果线程数变成零，则补充一个工作线程。

4. 如果队列已满，且当前线程数小于 `maximumPoolSize`，创建非核心线程执行任务。

5. 如果线程数也达到最大值，则执行 `RejectedExecutionHandler`，例如直接拒绝、调用方执行或丢弃任务。

**七个核心参数：**`corePoolSize` 核心线程数、`maximumPoolSize` 最大线程数、`keepAliveTime` 空闲存活时间、`unit` 时间单位、`workQueue` 阻塞队列、`threadFactory` 线程工厂、`handler` 拒绝策略；`submit()` 底层仍是 `execute()`，只是包装了 `Future` 返回结果。

队列满且线程数达上限时，由 `RejectedExecutionHandler` 决定拒绝策略：

**AbortPolicy（默认）**
直接抛 `RejectedExecutionException`。

**CallerRunsPolicy**
由提交任务的线程自己执行，可反压提交方；已 shutdown 时会丢弃。

**DiscardPolicy**
静默丢弃新任务，不报错。

**DiscardOldestPolicy**
丢弃队列中最老的任务，再重试提交新任务。

工作线程启动后，会循环从队列获取任务，依次执行 `beforeExecute`、任务本身和 `afterExecute`；线程退出时更新完成任务数，并由线程池处理工作线程的回收或补充。

**口述重点：**线程池的优先级是“核心线程 → 任务队列 → 非核心线程 → 拒绝策略”，不是提交一个任务就立即创建新线程。

## 02 为什么先排队再扩到最大线程数

核心数量是常态并发，队列吸收短时突发，超过缓冲能力后才扩到最大值。因此使用近似无界队列时，maximumPoolSize 通常不起扩容作用。核心线程默认按需创建，不是构造线程池就立即创建完。

入队成功后重查状态是为了处理与 shutdown 的竞争：只有能把任务从队列移除，才在这条分支执行拒绝；若已被工作线程取走，需要按当时的状态继续处理。线程数为 0 时补 worker 是防止队列有任务却没有消费者。

submit 通常把异常封装在返回的 Future 中；忽略 Future 会漏掉失败。execute 的未捕获异常可能使工作线程退出，线程池再按规则补充，两者的故障观测方式不同。
