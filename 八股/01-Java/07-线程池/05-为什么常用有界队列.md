# 05 为什么常用有界队列？

## 01 核心回答

**无界队列的坑：**看似平滑，实则在高峰会**无限堆积任务**，导致内存和时延失控；任务等待时间越来越长，最终可能触发 OOM 或请求级联超时。

**有界队列的价值：**能把压力**显式暴露**出来，配合拒绝策略和降级更符合生产治理思路。当队列接近上限时，可以快速失败、调用方执行、丢弃低优先级任务或触发限流，而不是让所有请求无限等待。

**容量怎么定：**根据任务平均耗时、目标吞吐、最大可接受排队时延和线程数估算，再通过压测校准；队列越长不代表吞吐越高，还要监控队列长度、最老任务年龄、拒绝次数、线程池活跃数和任务耗时。

**取舍：**队列太小会造成频繁拒绝，队列太大又会隐藏下游瓶颈。不同优先级或不同下游依赖应使用隔离队列，不能让低价值任务占满核心任务的容量。

---

## 02 用时间预算反推容量

可先用稳定负载下“平均排队任务数约等于到达速率 × 平均排队时间”理解 Little 定律，再用峰值压测验证尾部时延。若每秒到达 1000 个任务，可接受平均排队 0.1 秒，约 100 个排队任务是一个数量级参考，不是 P99 保证或突发上限。

有界队列只界定待执行任务数量；每个任务携带的大对象、运行中任务、重试队列和下游连接仍需独立预算。队列满要有明确拒绝/降级；往另一个无界队列转移不算解决过载。
