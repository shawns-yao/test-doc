# 八股整理路线图

## 整理目标

将 `library/八股/` 建设为唯一的面试八股知识库，同时保留“一问一文档”的复习方式。

## 文档组织方式

```text
八股/
└── 技术领域/
    └── 知识专题/
        └── 一个核心面试问题.md
```

例如：

```text
八股/01-Java/03-Java并发/03-Synchronized是什么.md
八股/01-Java/03-Java并发/04-ReentrantLock是什么.md
八股/01-Java/03-Java并发/02-Volatile.md
```

## 单篇笔记整理原则

- 文件夹与问题文档都使用两位序号；每个专题内独立编号，导航使用 `00`。
- 当前 Java 并发问题依次为：01-JMM、02-Volatile、03-Synchronized、04-ReentrantLock、05-ThreadLocal。
- 后续新增问题优先追加序号，不因复习顺序调整而反复重命名；复习顺序由导航组织。

- 保留原有内容，不直接整体替换。
- 先保留作者已有的理解和表述，再补充遗漏的关键点。
- 一个文档围绕一个核心问题展开。
- 核心问题的直接追问放在同一篇笔记中。
- 可以独立复习的问题建立独立文档。
- 相关问题之间建立双向 wikilink。
- 不为了追求形式统一而删除有价值的原始思考。
- Obsidian 专属内容使用 wikilink、callout、Mermaid 等 Markdown 语法。

## 推荐的单篇笔记结构

```markdown
# 问题标题

## 一句话回答

## 核心原理

## 为什么需要它？

## 具体机制

## 常见追问

## 易错点

## 面试口述版

## 相关笔记

- [[相关问题 A]]
- [[相关问题 B]]
```

不要求每篇笔记机械地使用全部标题。已有笔记应根据内容增量整理。

## `八股 1` 的处理方式

- `八股 1` 只作为待迁移和补充的来源，不作为最终知识库。
- 大文档不原样搬迁，先按核心问题拆分。
- 如果 `八股/` 已经存在对应问题笔记，以 `八股/` 的笔记为主。
- `八股 1` 中有价值的回答、追问、场景和易错点，补充到对应问题笔记中。
- 所有内容迁移完成并检查链接后，再删除 `八股 1`。
