# 01 面试笔记的组织与写作规范

## 01 当前组织约定

本库采用「编号领域 / 编号专题 / 编号核心问题.md」，00 文件只做导航。每篇保留一个核心问题及直接追问，独立问题以双向语义链接连接。正文标题顺序编号，保留已有解释、代码和图表；不保留面试公司标签，必要的资料作者与许可信息保留；发现过时结论时就地订正并注明版本和官方依据。以下旧规范作为格式演进记录保留，其大主题单篇、标题层级倒置和仅排版要求已由本次逐题拆分与内容增强要求替代。

## 02 原排版规范记录

### 02.1 历史格式规格

以下为历史排版规范原记录，仅供追溯，不再作为本库新增、迁移或重排的当前要求。

### 02.2 目录与内容边界

- 按主题分文件夹，一个文档只代表文档名对应的主题。
- 跨主题内容必须归位到对应文档，不允许把其他主题的内容长期放在无关文档中。
- 目录结构：

| 文件夹 | 文档 | 主题范围 |
| --- | --- | --- |
| `Agent/` | agent、AI、RAG、ES | Agent 工程、AI、RAG 检索增强、Elasticsearch |
| `Java基础/` | Java | Java 语法、并发、线程池、JVM |
| `前端/` | 前端 | 前端工程、渲染、JS、HTTP 安全 |
| `四大件/` | 操作系统、网络协议 | OS、网络 |
| `基础/` | 安全、工具与工程、设计模式、系统设计 | 安全、工程工具、设计模式、系统设计 |
| `手撕算法/` | 手撕代码 | 算法与数据结构（含 LeetCode 题型题单附录） |
| `数据库/` | 消息队列、Mysql、Redis | MQ、MySQL、Redis |
| `框架/` | Spring框架 | Spring 生态 |
| 根目录 | 反问、格式规格 | 反问、规范 |

- 跨文档链接带文件夹前缀，例如 `[[数据库/Mysql]]`、`[[四大件/网络协议]]`。仅引用内容不迁移时用「详细见」链接，不复制整卡。

### 02.3 标题层级

- 文档标题：`# 主题名`（原生 Markdown，保证大纲与搜索可用）。
- 章节：`## 一、章节名`（中文序号）。
- 问题：`# x.y 问题标题`（章节号.题号）。层级倒置是全库统一约定，不调整。

### 02.5 标签规范

| 场景 | 标签文字 |
| --- | --- |
| 跨主题追问（归位后不再使用） | ~~追问（XX 主题）~~ |

### 02.6 语义色

- 概念原理 → 蓝 `#3A5FBF`
- 关键细节 / 实现 / 正向 → 绿 `#3F8C12`
- 风险 / 取舍 / 追问 → 琥珀 `#B26E00`
- 颜色只承担语义，不装饰所有元素。

### 02.7 可复用结构

- **口述重点**（源文有「口述答案」时）：绿色 callout，`border-left:3px solid #3F8C12;background:rgba(82,196,26,.08);border-radius:8px;font-size:13.5px`。
- **标签 + 说明**：grid 两列，`grid-template-columns:固定px minmax(0,1fr)`，标签列按最长标签定宽。
- **顺序流程**：时间轴——共享竖线（绝对定位一次绘制）+ 编号圆点 + 每步独立卡片，不整体套卡。
- **对比**：flex 两到三个 sibling 面板，`flex:1 1 210px;min-width:0`。
- **代码**：保留 fenced code block，不包进卡片，不改写内容。
- **图片**：`display:block;max-width:100%;height:auto;margin:0 auto`，不裁剪；Obsidian 嵌入 `![[...]]` 保持原样。

### 02.8 编号与追加规则

- 节内新增问题：沿用小数编号（如 2.4），追加到节尾。
- 新增大节：`## 章节名`，问题从 x.1 开始。
- 删除/移动问题后必须全篇重编号，正文中的编号引用（如「见 2.8」）同步更新。
- 章节名必须名实相符；主题不匹配的内容移到对应章节或对应文档。

### 02.9 迁移守则

- 默认**仅排版**：保留原句原短语，不改写、不总结、不新增事实。内容增强需用户明确授权。
- 源文档的管理性文字（使用说明、资料说明、来源标注）不迁移。
- 保留代码、链接、嵌入、表格，HTML 标签必须闭合，根 div 必须自带完整 CSS 变量。

## 03 当前增补的验收口径

一篇文章围绕一个可独立提问的核心问题展开，直接追问保留在文内，独立问题拆文并用语义链接连接。领域名、专题名和问题名依次编号；导航只负责入口与关系，不用导航替代答案。历史别名帮助旧链接与搜索继续可用；资料来源用于技术依据和许可署名，不标记面试公司。

内容增强保留已有详细解释、HTML、代码、图表和练习记录；准确结论不为统一模板强行改写。错误结论采用最小必要订正，并说明适用版本、原误区和一手资料；个人经历区分真实完成、演示假设和未来计划。已有代码可保留，无需为每题额外添加实现。

算法题按最新约定仅保留必要题意或前提、Java 核心方法及时间和空间复杂度；题单与练习记录继续保留，非算法题不为套模板强加实现代码。

提交前检查标题编号、链接目标、代码围栏、HTML 闭合与问题归属；涉及版本、标准或性能结论时检查条件是否完整。本文第 02 节是历史记录，其中“大主题单篇”“层级倒置”“仅排版”与当前规则冲突时不再适用。
