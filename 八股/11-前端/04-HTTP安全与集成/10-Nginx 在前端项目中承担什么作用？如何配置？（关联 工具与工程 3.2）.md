# 10 Nginx 在前端项目中承担什么作用？如何配置？（关联 [[八股/10-工程实践/00-工程实践导航|工具与工程]] 3.2）

## 01 核心回答


**回答（前端视角，完整 Nginx 配置见 [[八股/10-工程实践/00-工程实践导航|工具与工程]] 3.2）：**

**前端项目中的角色：**① **静态资源服务**：托管打包产物 `dist/`，配置缓存（hash 文件长缓存）；② **反向代理**：`/api` 转发到后端，解决**跨域**（同源化）；③ **SPA 路由回退**：`try_files $uri /index.html` 让前端路由（history 模式）刷新不 404；④ **Gzip 压缩**：减小传输体积；⑤ **HTTPS 终结**：证书配置在 Nginx。

**前端关键配置：**① `try_files $uri $uri/ /index.html`（适用于客户端 history 路由的 SPA 回退）；② `location /api/ { proxy_pass http://backend; }`（代理 + 跨域）；③ `location /assets/ { expires 30d; }`（带 hash 静态资源长缓存）；④ `gzip on;`。

**追问：**为什么 SPA 要 try_files 回退（history 路由刷新时服务器找不到对应路径）；hash 文件名为什么能长缓存（内容变文件名变）；前端部署回滚怎么做（保留旧版本目录切换软链）。

---

## 02 路由回退的适用范围

订正：try_files 回退到 index.html 适用于客户端 history 路由站点，不是所有前端部署都必须配置。静态资源不存在时应正常 404，API 失败也不应回退成 HTML，否则浏览器可能出现 MIME 错误或 JSON 解析失败，掩盖真实问题。

代理 location 与 proxy_pass 是否带路径、是否有尾斜杠，会影响转发后的 URI，必须按真实接口路径验证。反向代理使浏览器请求同源，并不自动增加后端鉴权或 CSRF 防护。

---

## 03 缓存与发布检查

内容哈希资源可长缓存，HTML 应及时验证更新；缺失资源、压缩响应和缓存头要分别验收。发布后检查深层路由直接刷新、API 路径、资源 MIME、HTTPS 重定向与旧版本资源可用性。回滚需覆盖前后端接口兼容性，而不仅是切换 dist 目录。
