# 05 优化页面性能有哪些手段？项目中如何应用？

## 01 核心回答


**加载优化**
CDN、gzip/压缩、图片懒加载 + WebP、路由懒加载、HTTP 缓存（强缓存 + 版本号）、预加载关键资源。

**渲染优化**
减少重排重绘（批量 DOM、transform 动画）、避免长任务阻塞主线程（分片）、骨架屏、SSR 首屏。

**资源优化**
代码分割（按路由）、Tree-shaking、依赖瘦身、长列表虚拟滚动。

**体验优化**
预取/预连接（preconnect）、关键 CSS 内联、减少 CLS（图片尺寸占位）。

**项目应用流程：**Lighthouse 基线 → 定位瓶颈（Network/Performance 面板）→ 按 加载/渲染/资源 分层优化 → 复测对比指标（LCP/FCP/CLS）→ 持续监控。

**追问：**图片优化有哪些手段（压缩/WebP/懒加载/响应式 srcset）；长列表为什么卡（DOM 太多，用虚拟滚动）；SSR 和 CSR 性能对比（首屏 vs 交互）。

---

## 02 从指标拆分瓶颈

LCP 慢先区分响应慢、资源发现晚、下载慢还是元素渲染晚，再选择缓存、预加载、压缩或减少渲染阻塞。INP 差则看长任务、事件处理和渲染工作；CLS 差检查资源占位与动态插入。骨架屏改善等待感受，但本身不降低接口耗时，也不能冒充 LCP 改善。

首屏关键图通常不宜懒加载，预加载和 preconnect 也要限于确定需要的关键资源，滥用会抢带宽。分包过碎会增加调度开销，不能只追求单个文件越小越好。

---

## 03 项目表达的证据

只讲实际做过的优化，并注明设备、网络、冷暖缓存、样本数和前后版本；没有基线就不要写提升百分比。复测同时关注加载与交互，避免为首屏减少体积却把昂贵计算推迟到用户点击时。
