# 04 页面性能指标有哪些？

## 01 核心回答


**FCP**
首次内容绘制——第一个文本/图片/SVG出现，白屏结束，非核心指标。

**LCP**
最大内容绘制——最大元素可见渲染完成，核心加载指标（≤2.5s 优）。

**FID**
首次输入延迟——旧版响应指标，2024年已废弃，被INP正式取代。

**INP**
交互到下一次绘制——现行响应性核心指标，衡量页面全生命周期交互表现（≤200ms 优）。

**CLS**
累积布局偏移——页面非预期跳动程度（≤0.1 优）。

**TTFB**
首字节时间——服务端网络响应速度。

**TTI**
可交互时间——历史实验室可交互指标，Lighthouse 10 已移除；并不表示全部 JavaScript 执行完毕。

**核心（Core Web Vitals）：**LCP（加载）+ INP（交互）+ CLS（稳定）——Google 的官方评分基准，FID已于2024年被INP替换。

**追问：**怎么测量（Lighthouse / Performance API / web-vitals库，区分实验室数据与真实用户RUM数据）；FCP 和 LCP 的区别（首个渲染内容 vs 页面最大主内容渲染完成）；CLS 怎么避免（图片设置宽高占位、动态内容预留容器空间、避免后期插入大块DOM）。

## 02 统计口径比单次分数重要

当前 Core Web Vitals 为 LCP、INP、CLS；原文 INP 已替代 FID 的方向正确。评估良好体验时，应看真实访问样本第 75 百分位，并区分移动端与桌面端，不能用一次高性能电脑上的 Lighthouse 分数替代线上分布。

INP 关注交互从输入到下一次绘制的延迟，包含等待主线程、事件处理及呈现延迟，不只是事件回调耗时；不是把所有交互延迟求平均。CLS 也不是整个生命周期位移值简单无界求和，应遵循官方会话窗口定义和排除规则。

## 03 TTI 的历史定位订正

TTI 不等于“页面 JavaScript 全部执行完”，页面可能一直有异步工作；它是依据交互准备和静默窗口等条件定义的历史实验室指标。Lighthouse 10 已移除 TTI，不应作为现行核心指标。普通导航式 Lighthouse 没有真实交互，不能直接产出有代表性的 INP；实验室可看 TBT 并结合交互测试，最终以 RUM 数据验证。
