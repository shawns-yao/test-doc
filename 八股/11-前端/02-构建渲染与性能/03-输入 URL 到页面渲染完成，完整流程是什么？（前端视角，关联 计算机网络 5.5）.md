# 03 输入 URL 到页面渲染完成，完整流程是什么？（前端视角，关联 [[八股/06-计算机基础/00-计算机基础导航|计算机网络]] 5.5）

## 01 核心回答


**回答（前端侧重渲染后半段，网络前半段见 [[八股/06-计算机基础/00-计算机基础导航|计算机网络]] 5.5）：**

1. **解析 HTML → DOM 树**：边下载边解析，遇到 `<link>`/`<script>` 发起子资源请求。

2. **解析 CSS → CSSOM**：CSS 阻塞渲染（CSSOM 未构建完不绘制）。

3. **执行 JS**：默认阻塞 DOM 解析（defer/async 缓解）——JS 可以改 DOM/CSSOM。

4. **合并 → 渲染树**（Render Tree）：DOM + CSSOM，按样式生成布局所需结构；display:none 与 visibility:hidden 的行为不同。

5. **布局（Layout）**：计算每个节点的几何位置（回流）。

6. **绘制（Paint）→ 合成（Composite）**：分层绘制，合成器输出到屏幕。

**追问：**JS 为什么阻塞解析（可能改 DOM）；重排和重绘的区别（布局 vs 绘制）；怎么减少重排（批量 DOM 操作、transform 动画）。

## 02 流程不是严格串行流水线

补足网络前半段：解析 URL，检查可用缓存和 Service Worker，按需要解析 DNS，复用或建立连接，再发送请求。HTTPS 通常涉及 TLS，HTTP/3 使用 QUIC；连接复用时并非每次都重新握手。HTML 可以边到达边解析，预加载扫描器可提前发现资源，CSS、脚本与图片下载可能并行。

普通解析器插入的经典脚本会暂停 HTML 解析；defer 通常下载并行、解析后按文档顺序执行，async 就绪后执行且不保证顺序；模块脚本默认具有延后执行特征。CSS 的影响与媒体条件、资源是否阻塞渲染及脚本依赖有关，不是所有 CSS 请求都一律阻塞所有绘制。

## 03 渲染树与完成时刻

订正：“不可见节点都剔除”不准确。display:none 不生成相应布局盒，而 visibility:hidden 通常仍占布局空间，只是不绘制内容。DOMContentLoaded、load、FCP、LCP 和业务可用是不同时间点，SPA 之后还可能继续请求和渲染，不能用一个事件代表所有意义上的“页面完成”。
