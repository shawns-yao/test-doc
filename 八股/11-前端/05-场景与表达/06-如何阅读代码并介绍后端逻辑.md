# 06 如何阅读代码并介绍后端逻辑？

## 01 核心回答


**回答框架：**

**① 读代码的路径：**先看整体（README/目录结构/入口配置）→ 再找主线（一个请求从 Controller → Service → DAO 走一遍）→ 再看关键实现（事务/缓存/并发/异常处理）→ 最后看测试和文档验证理解。

**② 介绍逻辑的顺序：**「入口 → 校验 → 业务处理 → 数据访问 → 返回」五段式；每段讲**职责 + 关键分支 + 异常路径**，而不是念代码；遇到设计亮点（幂等/缓存/状态机）主动点出。

**③ 工具辅助：**IDE 的 Find Usages/Call Hierarchy 追调用链；全局搜索关键方法；git log 看代码演进意图；断点跑一遍最直观。

**追问：**读完怎么验证理解对了（画时序图/讲给别人听/写测试）；遇到看不懂的模块怎么办（先看调用方怎么用，再往里钻）；怎么判断代码好坏（职责单一、边界处理、可测试性）。

## 02 从一条请求核对隐藏边界

沿调用链补看鉴权、输入校验、事务开始结束、缓存更新和外部调用。方法名和注释只能提供线索，实际行为要用实现与测试验证；同一事务注解是否生效、异常是否被捕获、远程调用是否可重试，都可能改变表面流程。

## 03 介绍时说明确定与未确认的部分

先用一条成功路径建立共同理解，再挑一个失败分支说明回滚、错误码和幂等策略。无法从代码确定的设计动机应说“从目前实现推测”，不要把自己的猜测当作原作者意图。真实贡献说明负责的模块和边界，不把整个项目的架构都归为个人设计。
