# 05 如何通过共享屏幕演示项目和代码？

## 01 核心回答


**回答框架：**

**① 演示前准备：**本地跑通（依赖/数据/账号齐全）、浏览器预打开、准备一条「演示脚本」（讲什么顺序）、环境变量和端口确认；避免现场装依赖。

**② 演示结构（按故事线）：**先讲「这是什么 + 解决什么问题」30 秒 → 再走核心流程（主链路演示，2-3 分钟）→ 展示亮点（性能数据/异常处理/架构图）→ 留 1-2 个可深挖点引导追问。

**③ 代码讲解：**从入口文件开始（main/controller）→ 讲清调用链（请求进来怎么流转）→ 挑 2-3 个关键实现细节（不要逐行念）→ 用 IDE 的调用关系/断点辅助。

**追问：**演示挂了怎么办（先说明预期行为再演示，挂了接「这里设计上是…」）；讲代码从哪开始（入口 → 主链路 → 亮点）；时间不够砍哪部分（砍细节保主链路）。

## 02 演示前先隔离真实数据

使用演示账号和脱敏数据，关闭通知，避免展示 .env、令牌、数据库密码、生产日志及他人个人信息。优先共享指定应用窗口，预先检查终端滚屏、浏览器自动填充和历史记录是否会暴露无关内容。

## 03 失败时如何保持可信

准备一条已验证主链路和可说明版本的备份截图或录屏。现场失败时区分“当前演示环境故障”“尚未实现”和“设计上预期行为”，不能把未实现功能说成只是网络问题。只在授权的演示环境操作，删除、支付或批量写入等动作应使用安全样例或说明流程。

代码讲解准备入口、关键决策点、失败处理和测试证据四处定位，比临时翻完整仓库更容易控制时间。
