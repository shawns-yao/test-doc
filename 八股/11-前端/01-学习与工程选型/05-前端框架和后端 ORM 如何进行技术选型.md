# 05 前端框架和后端 ORM 如何进行技术选型？

## 01 核心回答


**选型方法论（通用）：**① 业务匹配度：框架特性是否覆盖核心场景；② 生态与社区：维护活跃度、坑的解决方案、招聘市场；③ 团队能力：团队熟悉什么，学习成本多高；④ 长期演进：技术方向是否主流、是否容易招人；⑤ 性能与成本：规模下性能是否达标、资源成本。

**前端框架（Vue vs React）：**Vue 上手快、模板直观、中文生态好；React 灵活（JSX）、生态大、社区强；小程序/H5 轻量场景也可能选原生或 Taro/uni-app。

**后端 ORM（MyBatis vs JPA）：**MyBatis 灵活可控（手写 SQL、复杂查询、性能可预期）；JPA/Hibernate 开发快（CRUD 自动、对象模型）、适合简单模型；复杂查询多选 MyBatis，模型简单选 JPA，或用 MyBatis-Plus 折中。

**追问：**选型后怎么验证（POC 小项目试跑）；换框架的成本是什么（重构 + 团队学习）；有没有"不选"的判断标准（生态萎缩/性能不达标/维护停摆）。

---

## 02 选型结论必须对应约束

订正补充：JPA 是持久化规范，Hibernate 是常见实现；MyBatis 更接近 SQL 映射框架。“JPA 只适合简单模型、复杂查询就必须选 MyBatis”过于绝对，JPA/Hibernate 也能表达复杂领域关系和查询，区别在控制方式、团队经验与维护成本。

POC 应覆盖真实复杂查询、分页、事务边界、批处理、N+1 风险及数据库执行计划。手写 SQL 也不天然保证性能，可控只意味着更直接地承担 SQL 质量责任。前端框架同样要测试路由、SSR、组件生态、可访问性和团队交付流程，不能只凭上手快慢决定长期方案。
