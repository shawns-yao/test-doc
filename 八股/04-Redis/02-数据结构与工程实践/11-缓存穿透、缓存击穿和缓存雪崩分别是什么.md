# 11 缓存穿透、缓存击穿和缓存雪崩分别是什么？

## 01 核心回答


**缓存穿透**

查询缓存和数据库都不存在的 key，大量无效请求绕过缓存直接打到数据库。

**手段：**参数和权限校验、布隆过滤器预判、不存在结果缓存短 TTL 空值、网关限流和异常来源拦截。空值缓存不能永久保存。

**缓存击穿**

一个热点 key 在失效瞬间被大量请求同时回源。

**手段：**热点数据逻辑过期 + 后台异步刷新；互斥锁只允许一个线程重建，其他请求短暂等待、读旧值或降级。

**缓存雪崩**

大量 key 同时过期、缓存集群故障或流量整体切换，导致后端被瞬时冲垮。

**手段：**TTL 随机抖动、分批预热、多级缓存、限流熔断、服务降级和 Redis 高可用。

排查时要分别监控无效 key 比例、热点 key 命中率、回源 QPS、过期分布、Redis 可用性、数据库连接池和队列堆积。三类问题往往同时出现，治理方案要和数据库容量、降级策略及恢复流程一起设计。

---

## 02 理解机制与追问

按回源形态定位：穿透是不合法或不存在对象被重复查，击穿是单热点失效后的同 key 并发重建，雪崩是许多 key 或整个缓存层一起失效。互斥只合并同 key 请求，TTL 抖动只分散到期时刻，熔断/限流则直接限制下游承压，作用层次不同。

---

## 03 易错点与适用边界

负缓存需区分“确认不存在”与“数据库超时/临时失败”，把失败缓存为空可能扩大错误。逻辑过期意味着允许提供旧数据，权限、余额等不能不经业务许可照用。过滤器阴性需保证数据同步新鲜。缓存彻底不可用时，应测试无缓存的限流和降级路径，避免故障后全量回源。

---

## 04 面试口述

先看问题是不存在、单热点重建还是整体失效，再组合负缓存、请求合并、TTL 抖动和下游保护；不能指望一把锁解决全部缓存事故。
