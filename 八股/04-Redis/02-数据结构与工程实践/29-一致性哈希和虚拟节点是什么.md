# 29 一致性哈希和虚拟节点是什么？

## 01 核心回答

**一致性哈希：**映射到固定哈希空间（`2^32` 仅为示例），把哈希值空间组成虚拟圆环；节点按 IP/主机名哈希定位置；key 沿环**顺时针**找到第一个节点作为归属——新增/下线节点只影响相邻区间数据，迁移量显著降低。

**数据倾斜问题：**节点很少时分布不均，大量数据集中到某台服务器——为每台服务器计算**虚拟节点**均匀分布到环上（多一步虚拟节点 → 实体节点映射，数据定位算法不变），相对较少的数据节点也能均匀分布（数量应按分布、节点容量和迁移成本测试确定）。

**对比：**Redis Cluster 用固定 16384 槽位 + CRC16（见 2.19），一致性哈希常用于代理层分片（如客户端哈希环；Codis 主要采用槽式预分片，不是此类例子）；两者都是"key → 节点"的映射，区别在映射规则和迁移策略。

**追问：**一致性哈希迁移量为什么小（只影响相邻区间）；虚拟节点解决什么（数据倾斜）；和取模分片的区别（一致性哈希减少迁移；普通取模节点数改变时通常大量重映射）。

## 02 理解机制与追问

普通 hash(key) mod N 在 N 变化时会重映射很多键；一致性哈希通过稳定哈希空间和节点位置，只转移新增/删除节点相关区间。虚拟节点让一个物理节点对应多个区间，降低随机分布偏差，也可按节点容量加权，迁移任务更细粒度。

## 03 易错点与适用边界

修正：环大小不必是 2³²，虚拟节点数也没有通用“32 个”标准。虚拟节点改善多键分布，不解决单个超级热 key。Redis Cluster 是固定槽映射，并不是一致性哈希环；Codis 也以预分片槽方案为主，不应列成哈希环的代表。成员视图不一致仍可能使客户端路由到不同节点。

## 04 面试口述

一致性哈希的价值是降低成员变更引起的迁移，虚拟节点改善区间分配；它们不自动提供复制一致性、无热点或无需迁移。
