# 22 NoSQL 和 KV 存储有什么区别？各自适合什么场景？

## 01 核心回答


**概念：**NoSQL 是相对关系数据库的一类非关系型数据库总称，包含 KV、文档、列族和图数据库等模型。KV 把 key 映射到 value，接口简单、点查性能稳定，但通常不擅长复杂条件查询和多实体关系——KV 是 NoSQL 的子类，不能把两者当成完全并列的技术。

**KV**
会话、缓存、配置、计数、设备状态和按唯一 ID 点查。

**文档**
结构变化较多、以聚合文档读取为主的数据。

**列族**
海量写入和按主键或时间范围访问。

**图**
关系遍历场景。

选择时要评估查询模式、事务、一致性、索引、容量、扩容、故障恢复和运维成本。业务模型应先由访问模式驱动，而不是先选数据库再强行适配；需要复杂 Join、约束和多行事务时仍应优先关系数据库，NoSQL 常作为特定访问路径的存储或缓存补充。

## 02 理解机制与追问

KV 描述访问模型，不直接规定持久化介质、一致性或是否有事务：可以是本地嵌入式，也可以是分布式服务。文档模型便于一次取出聚合对象，图模型擅长关系遍历，宽列/列族面向特定主键与范围模式；这些与 OLAP 的列式存储不能简单混为一谈。

## 03 易错点与适用边界

NoSQL 不等于没有 schema、没有索引或没有事务，也不自动比关系数据库易扩容。列族不是“把关系表按列存就一样”。应先写出最重要查询、更新边界、排序与范围需要，再核对具体产品能力；分类只帮组织问题，不是性能结论。

## 04 面试口述

NoSQL 是宽泛类别，KV 是其中一种常见模型。真正选型看访问路径、事务范围和故障保证，不由“NoSQL”三个字直接决定。
