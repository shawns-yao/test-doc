# 26 Redis 的 HyperLogLog 是什么

## 01 核心回答

HyperLogLog 用很少内存估计集合基数，适合 UV、独立设备数等近似去重计数。PFADD 加入观测，PFCOUNT 估计不同元素数量，PFMERGE 合并集合估计状态。密集表示约 12 KB，另有键开销，小基数可用更小表示。

## 02 为什么可以省内存

对输入做哈希，按哈希前导模式等统计特征维护寄存器，再估计基数；不保存每个原始成员，因此空间不按全部用户明细线性增长。兼容寄存器状态可合并得到并集估计，重复加入同一元素不等于重复累加人数。

## 03 误差与能力边界

约 0.81% 是标准误差，不是每次结果都保证在 ±0.81% 内，不能用于需要精确计费或审计的计数。不能据 HLL 查询某个具体用户是否在集合，也不能精确删除单个成员。每日 HLL 合并可做时间段 UV，但活跃用户明细和严格交集统计需要其他结构。

## 04 面试追问与口述

如果要求精确人数且 ID 紧凑，可考虑 Bitmap；需要成员明细用 Set 或事实表。我的回答是：HLL 用概率统计换低空间近似去重，选择它前必须确认误差可接受、无需成员查询及单元素删除。
