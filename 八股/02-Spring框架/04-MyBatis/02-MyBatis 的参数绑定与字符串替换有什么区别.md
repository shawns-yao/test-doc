# 02 MyBatis 的参数绑定与字符串替换有什么区别

## 01 原有详细回答

**#{} vs ${}：**`#{}` 是**预编译占位符**（PreparedStatement 的 ?，参数安全绑定，防 SQL 注入）；`${}` 是**字符串拼接**（直接替换进 SQL，有注入风险）——**只有动态表名/列名/排序字段等无法参数化的场景才用 ${}，且必须白名单校验**。

---

## 02 为什么占位符能分开数据与 SQL 结构

#{} 通常生成 PreparedStatement 参数占位，由驱动绑定数据值，值中的引号不会被当成 SQL 结构重新拼接。${} 把字符串原样插入 SQL 文本，调用方输入若能控制这段文本，就可能改变谓词、排序甚至语句结构。

参数占位符表示值，不表示表名、列名或 ASC/DESC 关键字。动态标识符应由服务端白名单映射成预定义 SQL 片段，不能只做单引号替换。分页、IN 条件和可选谓词优先用受支持的动态 SQL 结构与参数绑定，而不是手工拼接用户输入。

---

## 03 参数安全的边界

#{} 不会补救其他位置的 ${} 注入，也不代替业务权限和合法范围校验。ORDER BY 后绑定一个字符串值并不会把它解释为列名；这是数据和语法分离的直接结果。字段到对象的映射另见相关问题，不能把它当作 SQL 参数安全功能。
