# 13 Query Rewrite 怎么设计？

## 01 核心回答

**目标：**问题改写目标是提升**检索召回**，不是把问题「写得更漂亮」。一般「单轮为主，多轮兜底」。

**单轮改写三件事：**补全上下文指代、规范术语、拆分复合问题。

**多轮改写：**低置信度或召回差的 case 进入——先生成若干等价 query，再并行检索，最后融合去重。加约束避免偏题：**不改变用户意图、不引入新事实、保留关键实体词**。

**效果评估：**召回命中率提升、相关性提升、端到端成功率变化；多轮改写提升有限但成本明显增加时回退单轮。核心原则是「**改写为检索服务**」。

---

## 02 改写必须保留决定答案的条件

保留实体、时间范围、数值、否定和权限范围；多轮指代只从当前获授权上下文解析。将原始 query 也保留为一路候选，防止改写丢失错误码或专有词。

改写可包括同义扩展、多查询或问题分解，但不应凭空补出用户未提供的事实。HyDE 生成的是假设文本，用于帮助检索，不能作为最后答案的证据。避免将模型幻觉先写入查询再反复召回相似幻觉。

口述：“改写是检索变换，不是擅自改需求；以召回和端到端质量对照决定是否启用。”
