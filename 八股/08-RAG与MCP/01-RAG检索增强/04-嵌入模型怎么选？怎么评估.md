# 04 嵌入模型怎么选？怎么评估？

## 01 核心回答

**选型维度：**语言覆盖、领域术语、向量维度、上下文长度、推理吞吐、许可协议、部署位置和数据合规都要考虑。不能只看公开榜单，还要确认模型对中文、代码、数字和专有名词的区分能力。

服务模型：云端模型可能降低自部署维护成本，效果需实测，但存在网络时延、调用费用和数据出域问题；开源模型可本地部署、便于量化和版本锁定，却需要承担 GPU、监控和升级成本。生产环境要固定模型版本，并记录模型、维度和归一化方式。

**离线评估：**构造 query、相关文档、难负例和权限标签组成的黄金集，计算 Recall@K、Precision@K、MRR、nDCG@K；同时按语言、业务域、查询长度、长尾术语分桶，避免平均分掩盖局部退化。

**工程指标：**记录单条向量生成耗时、批量吞吐、显存/内存、索引构建时间、向量维度带来的存储开销，以及升级模型后的向量兼容性。更换模型通常需要重嵌入，不能直接把不同空间的向量混用。

**注意：**STS 或 MTEB 高分不等于业务检索最优，必须做真实 query 的 A/B 或离线回放；还要检查提示词语言、query 长度、归一化和距离函数是否与模型训练假设一致。

**面试追问：**余弦相似度和点积何时等价（向量已 L2 归一化时）；为什么要难负例（区分表面相似但答案不相关的文档）；模型升级怎么回滚（双索引、版本路由和可重建流水线）。

## 02 兼容性比维度数字更重要

同维度的两个模型可能位于不同语义空间，不能混检；支持可变输出维度的模型也应记录实际维度与配置。模型需要的 query/document instruction、最大输入长度、池化和归一化共同构成检索契约。

语义相似不一定是可回答性：两个文档主题相同，却可能年份、产品或适用人群不同。评测要加入这种难负例，避免只测“离题很远”的简单负例。云端和自部署的质量无普遍高下，应在许可与数据边界内比较。

口述：“先保证向量空间和距离契约正确，再用业务召回和成本选择模型。”见[[八股/08-RAG与MCP/01-RAG检索增强/20-RAG 向量库|维度与容量]]。

## 04 直接追问：Embedding 榜单里的不同任务测什么

原始 MTEB 论文区分多种表征任务，不能只背一个综合分：

- 检索：用 query 与相关文档标注检查排序，报告 Recall@K、MRR、nDCG；RAG 选型重点看目标业务的检索分桶
- 语义相似度（STS）：比较模型相似度与人工相似度标注，Spearman 反映排序一致性，Pearson 反映线性相关；同主题相似不等于能回答问题
- 分类：固定 embedding 后训练简单分类器，如逻辑回归，再看测试集 Accuracy/F1，测表示是否便于区分类别
- 聚类：看相近语义是否形成合理簇，原始 MTEB 使用 V-measure；它综合同质性与完整性，不是检索召回率

这些任务提供互补证据。引用榜单须说明数据集、语言、任务、版本和计算口径，不宣称任何模型在全部任务上都最优。[MTEB 原论文](https://arxiv.org/html/2210.07316v3)
