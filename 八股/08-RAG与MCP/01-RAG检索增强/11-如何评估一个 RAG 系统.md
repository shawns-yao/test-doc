# 11 如何评估一个 RAG 系统？

## 01 核心回答

**回答（检索 + 生成两阶段）：**

**检索阶段（找得对、找得全）：**① **上下文精确率（Context Precision）**——检索到的文档有多少真正相关（信噪比）；② **上下文召回率（Context Recall）**——所有相关文档找回多少（全面性）；③ 其他排名指标——Hit Rate（及格线）、MRR（第一个正确结果速度）、nDCG@k（相关性等级 + 排名）。

**生成阶段（忠实、准确、有用）：**① **Faithfulness/Groundedness（可溯源性）**——答案是否完全基于上下文、有无幻觉；② **Answer Relevancy**——是否直接回答用户问题；③ **Answer Correctness**——事实是否准确（更严格，原文也可能错）。

**自动化框架：****RAGAS、ARES、TruLens** 用 LLM-as-a-Judge 把 Faithfulness/Relevancy 等指标自动化计算，提高评估效率。

---

## 02 指标必须给出计算单位

经典 Precision@K 是 TopK 中相关条目比例，Recall@K 是相关条目召回比例；证据按文档、段落还是断言标注，结果会不同。RAGAS 等工具的同名 context 指标可能按排序或断言实现，不能不看版本就当同一个公式。

Faithfulness 表示答案能否由给定材料支持，不证明材料本身真实；Answer Correctness 要另有可靠标准。评测集需包含无答案、冲突版本、权限不可见、数字表格和多跳问题。

口述：“分层评价检索与生成，并把自动裁判当需校准的测量器，不能直接用其分数当事实。”

## 05 直接追问：排名指标怎样计算，检索回归怎样执行

排名指标要固定相关性标注、截断 K 和无答案口径：

- Hit Rate@K：每个 query 的前 K 项只要有一项相关就记 1，再对 query 求平均；它不区分相关结果排第一还是排第 K
- MRR@K：取首个相关结果名次的倒数，前 K 项无相关结果记 0，再求平均。例如三条 query 分别在第 1、第 2 位命中和未命中，MRR@K = (1 + 1/2 + 0) / 3 = 0.5，Hit Rate@K = 2/3
- nDCG@K：先按相关等级给收益，再按排名位置折扣，最后除以同一批标注下理想排序的 DCG。常用约定为 `DCG@K = Σ(2^rel_i - 1)/log2(i+1)`；必须说明收益与折扣约定，以及理想 DCG 为 0 的 query 是单列还是计 0

MRR 只关心第一个相关结果，不能代替多跳任务的全部证据覆盖率。上述名次指标也不是查询耗时；时延另测 p95 等运行指标。计算口径可对照 [Elasticsearch 排名评估说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval)。

检索回归可按以下步骤执行：

1. 固定 query、相关文档/片段标注、权限身份和数据快照，包含原失败样本、同义改写、长尾实体、无答案和多跳样本；开发调参集与最终测试集分开
2. 记录解析/切块、embedding、索引、过滤、召回和 reranker 的版本与参数。比较算法改动时固定语料；比较知识更新时先确认新增或删除事实是否改变正确标注
3. 在相同 K 和资源预算下运行新旧方案，分别保存初召回、过滤后、重排后与最终上下文的文档 ID、版本、分数和证据覆盖，定位首次丢失证据的阶段
4. 报告逐 query 差值与语言、租户、任务类型分桶，列出退化样本；同时检查权限泄漏、p95、成本和最终答案引用。按预先定义的门槛决定是否发布，不能用平均分上涨掩盖高风险桶退化

这套回归检查的是证据可用性与结果质量，不要求更新后所有排名保持原样。评测集的文档、查询、相关性判断和独立测试原则可参考 [《信息检索导论》评估章节](https://nlp.stanford.edu/IR-book/pdf/08eval.pdf)。
