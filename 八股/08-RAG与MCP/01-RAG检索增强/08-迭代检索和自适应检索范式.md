# 08 迭代检索和自适应检索范式？

## 01 核心回答

① 自反思与纠正：Self-RAG 使用学习到的检索/反思 token 控制生成，CRAG 评估检索质量后选择纠正策略；两者并非完全相同的通用自问循环。

② 按需检索：FLARE 用即将生成的句子和低置信度信号触发检索与重生成；Self-Ask 则显式提出并求解子问题，可结合搜索，不是同一个概率阈值机制。

**③ 多源 Agentic RAG：**Agent 判断需要哪些信息，同时调用向量库、知识图谱、SQL 数据库或搜索 API，综合生成答案。

**共同点：**提升复杂问题准确率，但增加流程复杂度和时延。

---

## 02 不同方法不能混成同一个反思循环

- Self-RAG：通过检索与反思相关 token 学习是否检索、如何评价候选内容，是具体训练/推理方法，不只是普通 LLM 自问一句“够不够”。
- CRAG：评估检索结果质量，并据此选择补救，例如扩展检索与整理知识；重点是检索失败后的纠正。
- FLARE：利用即将生成内容构造查询，对低置信度生成片段触发检索和重生成。
- Self-Ask：显式拆出后续子问题并求解，可结合搜索；不能概括成统一的 token 概率阈值触发法。

选型先看能否取得所需置信度或训练能力，闭源 API 未必提供论文需要的信号。通用工程启发是按信息缺口分配检索预算，但不能把启发当原算法复现。

口述：“都在改变何时检索，但控制信号、是否需要训练、失败处理并不相同。”
