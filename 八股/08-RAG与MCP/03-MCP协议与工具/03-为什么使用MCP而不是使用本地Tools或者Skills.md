# 03 为什么使用MCP而不是使用本地Tools或者Skills

## 01 核心回答

本地 tool 是运行时直接调用的函数或能力；MCP 是让客户端以统一协议发现和访问外部能力的接口；Skill 是组织任务方法、说明和可选脚本/资源的封装。三者处在不同层，可以同时使用。

---

## 02 为什么选择 MCP

当同一能力要接多个客户端、跨语言进程、独立发布或统一做远程权限治理时，MCP 有复用价值。它减少为每个模型应用单独写接入适配的重复劳动，但仍需模型侧工具描述转换、连接管理、业务鉴权和结果处理，不是零成本。

本地 tool 的优势是简单、低延迟、调试直接，适合单应用内部函数。Skill 告诉 Agent 怎么完成任务，可指导它何时调用本地工具或 MCP，也可能附带脚本；仅加载说明不会自动获得外部服务权限。

---

## 03 示例与权衡

可改编例子：一个“排查告警”的 Skill 规定先看指标、再查日志、最后验证假设；日志查询由 MCP Server 暴露，多种客户端均可复用；解析日志行的纯函数保留本地。不要为了“统一”让每次字符串处理都绕一趟远程 MCP。

MCP 增加网络、服务部署、版本兼容和供应链风险。Skill 也可能包含恶意指令或脚本，因此来源审查、权限和执行限制不能省略。授权链由真实用户与服务端策略建立，不由工具描述或技能文案建立。

---

## 04 追问与口述

“用了 MCP 就不用 Function Calling 吗？”不是，模型可能通过 Function Calling 选择工具，运行时再映射为 MCP 调用。“Skill 是另一个 MCP Server 吗？”不是，Skill 主要是任务知识/流程包装，MCP 主要是通信与能力接口。

口述：“我按复用和隔离需求选接入方式。本地工具做简单内部计算，MCP 统一外部能力，Skill 固化使用方法，三者可组合而不必相互替代。”
