# 02 检索结果不准导致 Agent 决策跑偏,你怎么解决?

## 01 核心回答

**一句话结论:**先定位是**召回不全会导致没检索到,还是排序噪声导致检索到错的**,再分层治理,最后用评测闭环验证。

**召回侧(查不到):**混合检索(BM25 关键词 + 向量语义 + 重排)、Query 改写与扩展、HyDE(先让模型生成假设答案再检索)、多路召回、索引切分策略调整。

**排序侧(查不准):**引入 Reranker(cross-encoder)精排,把最相关片段顶到前面;设置相似度阈值与 top-k 控制,过滤低分噪声。

**Agent 侧兜底:**把检索结果做成"证据"给模型并提示**"证据不足就明说/继续检索/换问法",不要硬答**;关键决策前加一步证据充分性校验。

**评测闭环:**建评测集(标准问法 + 期望证据),指标看检索命中率与端到端正确率,badcase 回流迭代切分/embedding/重排。

记忆要点:四板斧 = 混合检索保召回、Reranker 保精度、提示词"没证据不许答"、评测集驱动迭代。

---

## 02 决策跑偏要先限制影响

先暂停高风险后续动作，回看支撑决策的具体证据与版本，区分无数据、错检索、错排序、误读和注入。相似度阈值需按模型与任务校准，不能把任意 0.8 当成可信概率。

检索到的文档可能含恶意指令或过期条件，要在权限和信任边界内处理。修正后用原失败样本及近邻反例回归，并检查是否只是召回更广却把噪声引入模型。

口述：“先止住错误行动，再沿证据链定位首次偏离；只改 Prompt 说‘不许幻觉’不能替代数据、召回和执行校验。”
