# 01 Agent 里用的 RAG 和普通问答 RAG 有什么不一样(比如要不要多轮检索、什么时机触发检索)?

## 01 核心回答

一句话结论:固定两阶段 RAG 基线通常一次检索后生成，RAG 本身也可条件触发或多轮;Agent 内 RAG 是由 Agent 按需触发、可多轮、结果参与决策与反思的检索。

触发时机:固定流水线常按预设规则决定是否检索;Agent 由模型自己判断"执行当前子任务是否需要外部知识",需要才检索,减少无效检索与噪声。

**多轮与改写:**Agent 任务跨多步,检索常伴随 **Query 改写/分解**(把复杂问题拆成多个子检索),甚至边推理边补检(ReAct 循环中的检索),而不是一次检索定终身。

**结果用途:**普通 RAG 检索结果只喂给最终生成;Agent 的检索结果还会**影响后续规划决策**(如证据不足触发再检索或换策略)。

记忆要点:固定两阶段 RAG 基线 = 查一次答一次;Agent RAG = 需要才查、边想边查、查完还能改主意。

## 02 对比的适用边界

原题比较的是固定两阶段 RAG 与由 Agent 控制的检索。RAG 本身可以多轮、条件触发、重写或多跳，因此“普通 RAG 一定每问必检且只检一次”只能作为简单基线示意。

触发检索时应说明当前缺哪项事实、目标来源和停止条件；模型自报“不确定”不一定可靠，关键业务可用规则强制查证。记录补检是否带来新的有效证据，连续重复无收益时停止并报告缺口。

口述：“区别在控制权与任务状态驱动，动态检索可能更灵活，但也更需要预算、验收和安全边界。”详见[[八股/08-RAG与MCP/01-RAG检索增强/17-Agentic RAG|Agentic RAG]]。
