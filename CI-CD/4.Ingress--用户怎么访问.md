
# Ingress：外部用户到底怎么访问到集群里的服务

## 一、Service 想对外，NodePort 和 LoadBalancer 都不理想

Service 默认只能在集群内部访问。想暴露到集群外，早期有两个办法，但都有明显问题：

- **NodePort**：在每台机器上开一个高端口，用户得访问 `机器IP:30080`。机器一换 IP 就变，也没法直接用域名。
- **LoadBalancer**：让云厂商分配一个公网地址。但**每个对外服务都要一个**——服务一多就是十几个公网入口，每个都要花钱，域名和证书还得各自配一遍。

## 二、Ingress：只留一个入口，按请求内容分发

更合理的做法是**只暴露一个统一入口，让它按请求的域名和路径决定送给谁**——这就是 **Ingress**，集群的「总前台」：

- 路径 `/api/*` → 订单服务
- 路径 `/static/*` → 静态资源服务
- 域名 `admin.example.com` → 后台服务

## 三、最关键的一点：Ingress 是规则，Controller 才是执行者

这是初学者最容易踩空的地方：**Ingress 本身只是一份路由规则（一个 API 对象、一段 YAML），你把它提交上去，什么都不会发生。** 真正让规则生效，需要集群里运行着一个 **Ingress Controller（入口控制器）**，比如 ingress-nginx、Traefik：

- 它持续盯着所有 Ingress 规则，把规则翻译成自己（一个反向代理）的配置；
- 再由它通过一个公网地址（云上通常是 LoadBalancer）接住外部流量并转发。

类比：**Ingress 是贴在前台的「分流表」，Ingress Controller 才是真正站在门口、照着分流表接待的人。** 只有表、没有人，客人是进不来的。

## 四、Ingress 顺带帮你做的事

- **TLS 终止（TLS Termination）**：HTTPS 在入口统一解密，证书只需在入口配一份（放在 Secret 里挂载），后端服务可以只跑 HTTP。
- **统一路由**：基于域名、路径分流；还能配置默认后端（defaultBackend，兜住所有未匹配请求）、路径重写等。
